## Why v1 failed (28 Sep: `btn_result=0x00 elect_result=0x00` -> "3-pole" for a real 4-pole headset)
* v1 read `MBHC_RESULT_1` (0xf158) as a live level ("0x1f = above every button threshold = mic"). It is not: it is the
  latched code of the last debounced **button event** (0=BTN0, 1, 3, 7, 0xf; see mainline press handler and downstream
  `wcd_mbhc_get_button_mask`). With no button event it stays 0, so 0x00 carries no information.
* Downstream msm-4.4 `wcd-mbhc-v2.c` (used by msm8x16-wcd / msm-analog-cdc on stock SDM660) decides after enabling MIC
  BIAS2 + FSM: **no button-press interrupt && `HS_COMP_RESULT` (ZDET_ELECT_RESULT 0xf159 bit0) == 0 -> HEADSET**;
  a press interrupt (mic line pulled under the BTN0 threshold = grounded ring) -> HEADPHONE; hs_comp=1 (line above
  HS_VREF, open) -> high-impedance / keep checking. The 28 Sep reading (no press irq, elect bit0 = 0) is therefore
  exactly the downstream *headset* case.
* v1 also released the bias with `snd_soc_dapm_disable_pin("MIC BIAS External2")`, which leaves that pin
  **disconnected** afterwards (headset-mic captures could lose the bias). v2 uses `snd_soc_dapm_enable_pin` (force off,
  pin connected).
* Stock DT cross-check: `qcom,msm-hs-micbias-type = "external"`, `msm-micbias2-ext-cap`, Headset Mic = MIC BIAS External2
  -> AMIC2, micbias 1.8 V, `msm-mbhc-hphl-swh=1`, `gnd-swh=0`; irq bits on 0xf0: 4 but_rel, 5 but_press, 6 ins_rem,
  7 mbhc(switch) — same as mainline, so `CDC_D_INT_RT_STS` 0xf010 bit5 is the live button/"mic low" comparator.

## v2 logic (work 300 ms after insertion when no BTN0 sequence was seen)
1. DIAG `pre` dump; force MIC BIAS External2, 100 ms; DIAG `micb2` dump.
2. 5 samples (20 ms apart) of 0xf010 RT_STS (bit5 = press level), RESULT_1, ZDET_ELECT_RESULT (bit0 = hs_comp).
   Button-press / release irqs during the window are **counted, not reported** (no false key / removal).
3. Debug only: ELECT_SCHMT_ISRC (DET_CTL_2 bits 2:1) = 2 for 20 ms (downstream cross-connection check) -> `elect_schmt`,
   DIAG `schmt` dump, restore DET_CTL_2; release bias (enable_pin); 60 ms; DIAG `post` dump.
4. Decision:
   * **3-pole** only with positive evidence on both: RT press bit set on 5/5 samples AND >=1 press irq since the last
     removal (or in the window); re-measured 3x (500 ms) first -> `A6L_MBHC_HEADPHONE (mic line grounded: 3-pole)`
     (+ a BTN release report in case the press handler reported BTN_0).
   * hs_comp high 5/5 -> re-measure (3x), then `A6L_MBHC_HEADSET (fallback: hs_comp high, undecided)`.
   * otherwise `A6L_MBHC_HEADSET (mic detected: no btn0 press with MIC BIAS2 on, hs_comp=0)` (or `(fallback: rt_press=…)`).
   => a 4-pole headset is never silently reported as headphones; undecided = HEADSET (mic path stays usable).
* Params (runtime 0644, /sys/module/snd_soc_msm8916_analog/parameters/): `a6l_mbhc_detect` (default 1),
  `a6l_mbhc_diag` (default 1 in this build; the presence of this file proves the v2 module is loaded).
* Log per try: `A6L_MBHC try N: micb2_en=.. rt_press=a/5 hs_comp=b/5 btn_result=.. elect_result=.. elect_schmt=..
  win_press=.. win_rel=.. press_res=.. ins_presses=.. rt=..` and 4 lines `A6L_MBHC_DIAG pre|micb2|schmt|post: 010=.. … 140=.. … 15f=..`.

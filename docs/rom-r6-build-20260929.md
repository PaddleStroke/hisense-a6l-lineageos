## 3. Fixes (recorded in the ledger)
1. **Build break, first attempt:** `error: lineage.updater.uri cannot exceed 91 bytes` (build/make/tools/post_process_props.py:
   non-`ro.` values have a 91-byte limit). The non-release placeholder in `device/hisense/a6l/rom/android/android.mk`
   (`https://raw.githubusercontent.com/PaddleStroke/hisense-a6l-lineageos/main/updater/unpublished/{device}.json`, 107 bytes)
   is now `https://updater.invalid/a6l/updater/unpublished/{device}.json` (61 bytes). The `.invalid` TLD (RFC 2606) never
   resolves, so the URI is never published, which was the intent. check-android-overlays 46/0 and test-selinux-prep PASS
   (U1/U2) were run after the change. Failed log: `build-try1-errors.txt`.
   **Latent, NOT fixed (Pierre):** the release URI in `rom/release/release.mk`
   (`https://raw.githubusercontent.com/PaddleStroke/hisense-a6l-lineageos/main/updater/{device}.json`, 95 bytes) also exceeds
   91 bytes. **Any `A6L_RELEASE=1` build will fail the same way.** It needs a shorter host or path, e.g. a GitHub Pages URL
   or a redirect, and a matching update to the two tests that pin it.
2. `tools/check-rom-v2-image.sh`: pins and expected defaults moved to r6. Each pin accepts the v67 or the r5 build of the
   merged module. The camera is now expected to be advertised. A block of r6 item checks was added (§5).

The preflight and the kernel/stage checks needed no other fixes.

## 7. Known issues / open
- **r6 has never booted on the phone, and neither has the thermal r5 kernel.**
- **`ro.debuggable=0`:** `vendor/lineage/config/common.mk` sets `PRODUCT_NOT_DEBUGGABLE_IN_USERDEBUG := true`. This is
  standard Lineage behaviour and the same in r5. Plain `adb root` is therefore expected to be refused. Enable "Rooted
  debugging" in Developer options first and check this at the first boot. Commands in older docs that assume `adb root`
  (e.g. setprop persist.*) depend on it.
- AVC denials in QEMU: 1042, of which 784 are `vendor_modprobe` (r5: 453 / 195). There are more modules (camera group now
  on) and the rc seclabels are unchanged because `A6L_SELINUX_PREP` is unset. The boot is permissive, so this has no
  functional effect. Handle it in the enforcing work.
- The release updater URI is too long (§3). Any `A6L_RELEASE=1` build fails until it is shortened.
- QEMU-only messages (expected): "LCD connector missing", "vibrator led MISSING".
- Still open, unchanged from r5:
  - test keys: a release-key switch needs one wipe install;
  - no FBE;
  - dm-default-key not staged;
  - rc-enforcing not applied;
  - EDL entry from LineageOS unproven;
  - VoLTE off;
  - camera AF not merged;
  - btcall needs `A6L_AUDIO_SET=series`.
- WSL leftovers: `/home/a6l/rom-v2/{boot-r6,boot-r6-qemu,dt-r6,flashtest-r6,qemu-r6,kit-r6}`. The keep-data scratch copies
  (24 GB, `/home/a6l/scratch/r6upd`) were deleted after the logs were copied.

1. **RAM boot of the thermal r5 kernel** (docs/kernel-android-config-20260930.md step 1): `boot-r5t/boot.img`
   (`458201f9`) or r6's `boot-r6/boot.img` (`971e4554`, same kernel + r6 DT) from the V75 recovery flow. Check:
   - module loads and `dmesg | grep -E "disagrees|Unknown symbol|usercopy"` empty;
   - display, touch, audio, radio, Wi-Fi;
   - the watchdog node probes (qcom-wdt, `/dev/watchdog`) but watchdogd stays off;
   - optionally, emul_temp 111000 on a CPU zone -> power-off.
2. Laptop: `cd ~/A6L-usb-20260915/rom-r6 && python3 Verify-RomV1Stage.py` -> `"passed": true` (already done once, §9).
3. **Rollback rehearsal before the first write.** No tool writes anything in this step.
   - Quick path: fastboot menu -> Recovery should boot the V74/V75 diagnostic recovery with adb (`HLTE730T-PROBE`),
     `toybox`, `/sdhci-msm.ko`, and `mmcblk1` enumerated. This is the same entry as update-keepdata §4 step 1.
   - Full path: the stock restore (`Launch-RomV1Restore.py`) needs the install capture, so it can only be rehearsed after
     step 4. Offline it is covered by Test-RomV1Flash `restore_full_byte_identical`.
   - EDL entry: confirm `adb reboot edl` from stock, and whether a hardware-key or test-point EDL entry exists. EDL entry
     from LineageOS is unproven.
4. **First install on Pierre's go:**
   - Phone in stock Android, battery >= 60 %, laptop port 3-2.
   - Run `python3 Launch-RomV1Install.py && tail -f rom-v1-install-launch.log`.
   - Keep `capture-rom-v1-install/`, the only way back to stock: copy it to the desktop `captures/` at once.
   - First boot: tap "Allow" for adb, enable Rooted debugging.
   - Check: `getprop ro.vendor.a6l.rom.build` = r6, `A6L_ROM ... fails=0` per group, `uname -r`, thermal HAL,
     charger 9 V, radio registered.
   - Collect AVCs (`Collect-AvcV1.py`).
5. Keep-data rehearsal on r6 (update-keepdata §4): `adb reboot recovery` -> `backup-only --transport adb-recovery` ->
   `update --reflash` with data -> boot with data -> `rollback`.

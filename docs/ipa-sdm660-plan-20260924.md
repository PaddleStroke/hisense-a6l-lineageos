# IPA v2.6L on the A6L (SDM660) mainline kernel: plan for a kernel agent (agent `ril`, 24 Sep 2026)

**Why:** mobile data on SDM660 goes through the IPA (Internet Packet Accelerator). The modem has no other
packet path. The stock kernel has no SMD/glink rmnet; its symbols are `rmnet_ipa_*`, `ipa2_*` and
`ipa_init_mem_partition_v2`. The radio HAL (`device/hisense/a6l/radio`) already does everything above the
netdev: WDA data format, WDS bind-mux/start-network/current-settings (with DNS), and rmnet link creation. It
needs a `rmnet_ipa0` netdev from the mainline `drivers/net/ipa` driver. Until that netdev exists,
`setupDataCall` fails cleanly with `OEM_DCFAILCAUSE_1` and a 10-minute retry hint.

## 1. What the hardware is (proven from stock files)

Stock DT `firmware/extracted/device-trees/stock-00.dts`, node `qcom,ipa@14780000`:

| property | value | meaning |
|---|---|---|
| `qcom,ipa-hw-ver` | `<0x06>` | `IPA_HW_v2_6L` (msm-4.4 `enum ipa_hw_type`: v2_5=5, **v2_6L=6**, v3_0=10, v3_1=11) |
| `reg` / `reg-names` | `0x14780000 0x4effc` "ipa-base", `0x14784000 0x26934` "bam-base" | BAM-DMA transport (no GSI). The BAM size is the same as msm8953 |
| `interrupts` | SPI 333 (0x14d) "ipa-irq", SPI 432 (0x1b0) "bam-irq" | |
| `clocks` | `<&rpmcc 0x22>`, `<&rpmcc 0x59>` "core_clk", "smmu_clk" | downstream RPM ids; mainline `RPM_SMD_IPA_CLK` (68) exists for sdm660 |
| `iommus` (ipa_smmu_ap) | `<&anoc2_smmu 0x19c0>`, `qcom,smmu-s1-bypass` | mainline `anoc2_smmu: iommu@16c0000` exists in sdm630.dtsi |
| `ipa_smmu_uc` | `<&anoc2_smmu 0x19c2>` | microcontroller context |
| `qcom,ee` | 0 | |
| `qcom,rmnet-ipa` | `qcom,rmnet-ipa-ssr`, `qcom,ipa-loaduC` | the rmnet_ipa (WWAN) netdev on top of IPA |

The stock kernel ships both `ipa_v2` and `ipa_v3` code and picks v2 because hw-ver 6 < 10. There is no IPA
smp2p in the stock DT: v2 does not use the "ipa-clock-enabled" smp2p handshake that mainline v3+ needs.

**Mainline 7.2 (`/home/a6l/kernel/a6l-baseline-7.2/drivers/net/ipa`) supports IPA v3.1 and later only.** All
of those use GSI; the data tables go from v3.1 to v5.5. The phone config already has `CONFIG_QCOM_IPA=m`,
`CONFIG_RMNET=m`, `CONFIG_QCOM_BAM_DMA=y` and `CONFIG_QCOM_QMI_HELPERS=m`. `bam_dma.c` knows `qcom,bam-v1.7.0`
but lacks the "immediate commands" support that the IPA v2 port needs.

## 2. Existing work to port (none of it is upstream)

1. Sireesh Kodali, **"[RFC PATCH 00/17] net: ipa: Add support for IPA v2.x"** (Sep 2021, on 5.13/net-next).
   It covers v2.0, v2.5 and v2.6L. It adds an `ipa_dma` abstraction over GSI/BAM, BAM transport, v2 registers,
   endpoints, memory map, QMI, the uC, the 2.6L init sequence and DT bindings for msm8953/msm8996.
   The author's results: v2.5 (msm8996) got an IP address through ModemManager (traffic not verified); **v2.6L
   (msm8953) got an IP but could not send or receive packets.**
   https://lkml.iu.edu/hypermail/linux/kernel/2109.2/04397.html
2. **msm8953-mainline `linux` branch `msm8953-6.1.0/ipa`** (last commit ad55d896, 7 Jan 2023). It is the RFC
   rebased on 6.1, about 27 commits, plus later WIP fixes: "Skip entire unprocessed packets rather than just
   their status part", "Remove pad_align from IPA v2.* AP_LAN_RX endpoint configuration", "Add IPA v2.*
   opcodes", `dmaengine: qcom: bam_dma: Add support for immediate commands`, and a working-looking msm8953
   DT (below). `data/ipa_data-v2.6l.c` has endpoints 2..9, the local memory map and `smem_id 497`, size 0x2000.
   Note that **the modem endpoints set `qmap` but not `checksum`**, so rmnet must run with flags `0x01`
   (deaggregation only). The HAL uses that as its default (`ro.vendor.a6l.ril.rmnet_flags=1`).
   `git clone --single-branch -b msm8953-6.1.0/ipa https://github.com/msm8953-mainline/linux`

msm8953 is **also IPA v2.6L**, with the same register layout: ipa-base+0x40000 holds the registers and BAM is
at ipa-base+0x4000. The downstream ipa_v2 memory map and endpoint mapping depend only on the hw type, so the
v2.6L data should apply to SDM660 unchanged. That still has to be checked against the stock
`ipa_init_mem_partition_v2` (disassemble `stock-symbolized.elf`).

## 3. Proposed DT for the A6L (V75+ overlay or sdm630.dtsi patch, untested)

```dts
ipa: ipa@147c0000 {
    compatible = "qcom,sdm660-ipa", "qcom,msm8953-ipa";   /* reuse ipa_data-v2.6l */
    reg = <0x147c0000 0x5000>, <0x147c5000 0x2000>;       /* ipa-base+0x40000 / +0x45000 */
    reg-names = "ipa-reg", "ipa-shared";
    interrupts = <GIC_SPI 333 IRQ_TYPE_EDGE_RISING>;
    interrupt-names = "ipa";
    clocks = <&rpmcc RPM_SMD_IPA_CLK>;
    clock-names = "core";
    interconnects = <&a2noc MASTER_IPA &bimc SLAVE_EBI>,
                    <&a2noc MASTER_IPA &cnoc SLAVE_IMEM?>,     /* check the sdm660 icc tables */
                    <&gnoc MASTER_APSS_PROC &cnoc SLAVE_IPA>;
    interconnect-names = "memory", "imem", "config";
    iommus = <&anoc2_smmu 0x19c0>;                          /* stock: S1 bypass; try without first */
    dmas = <&ipa_bam 2>, <&ipa_bam 3>, <&ipa_bam 4>, <&ipa_bam 5>,
           <&ipa_bam 6>, <&ipa_bam 7>, <&ipa_bam 8>, <&ipa_bam 9>;
    dma-names = "ap_lan_rx", "cmd_tx", "ap_modem_tx", "ap_modem_rx",
                "modem_lan_tx", "modem_cmd_tx", "modem_lan_rx", "modem_ap_rx";
    modem-remoteproc = <&remoteproc_mss>;
};
ipa_bam: dma-controller@14784000 {
    compatible = "qcom,bam-v1.7.0";
    reg = <0x14784000 0x26934>;
    interrupts = <GIC_SPI 432 IRQ_TYPE_LEVEL_HIGH>;
    clocks = <&rpmcc RPM_SMD_IPA_CLK>;
    clock-names = "bam_clk";
    #dma-cells = <1>;
    qcom,ee = <0>;
};
```

**Honest estimate:** 2–4 weeks for one experienced kernel developer to reach packets on SDM660, and it may not
get there (the v2.6L data path never worked upstream). Plan B for data: none on the modem side. Wi-Fi stays the
data path. SMS and calls do **not** depend on IPA.

## 5. Contract with the radio HAL
- Netdev name: `ro.vendor.a6l.ril.data_parent` (default `rmnet_ipa0`, the mainline name).
- The HAL sends WDA Set Data Format: endpoint type 4 (embedded), interface 1, raw-IP, QMAP UL/DL (the property
  `ro.vendor.a6l.ril.ep_type/ep_iface` can override the endpoint).
- The HAL binds each call to mux id 1..4 and creates `rmnet_dataN` with `ro.vendor.a6l.ril.rmnet_flags`
  (1 = deaggregation; 13 = + MAPv4 checksum, only if the v2 port enables checksum offload).
- Android (netd) configures the addresses, routes and DNS from SetupDataCallResult. The HAL only brings the
  links up and sets the MTU.

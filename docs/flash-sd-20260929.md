## Key technical point: re-parenting after the overlay

`of_platform_notify()` creates the platform device of a node an overlay enables with
`parent = of_find_device_by_node(parent node)`. For a PMIC child (`pmic@3` is an **SPMI** device) or an smd-rpm child
(`rpm-requests` is an **rpmsg** device) that lookup returns NULL, so the device lands under `/sys/devices/platform` and:
- `leds-qcom-flash` fails with *"Failed to get parent regmap"* (`dev_get_regmap(dev->parent)`),
- `qcom_smd-regulator` fails with *"Unable to retrieve handle to rpm"* (`dev_get_drvdata(dev->parent)`).

Both loader modules therefore re-create the device under the parent of an already-bound sibling
(`a6l_ovl_reparent.h`: flash → parent of `leds@d800` WLED = the PM660L SPMI device; SD regulators → parent of
`regulators-0` = the smd-rpm device). One *"Unable to retrieve handle to rpm"* line right after the SD overlay apply is
**expected** (the notifier's first, wrongly parented instance); it is followed by `A6L_SD_OVL ... -> ... parent ...`.

Also for the SD: the smd-rpm regulator driver registers only the children present at probe, and `regulators-0`
(L1/L3/L4/L7, in use) must not be unbound, so the runtime overlay adds L2/L5 in a **new** node
`rpm-requests/regulators-a6lsd` (`qcom,rpm-pm660l-regulators`). The ROM overlay `a6l-microsd-v75.dtso` (merged at build
time) keeps them in `regulators-0`; both merge cleanly on the V74 base (`kvoice-build/dt/v74.dtb`).

## Flash bundle (`run-flash.sh`)

DT checked against stock (`stock-dtbo-20260914/stock-0x-merged.dts`): `qcom,leds@d300` (qpnp-flash-led-v2),
`qcom,camera-flash@0` uses flash_0 / torch_0 / switch_0 (**HW channel 0** → mainline `led-sources = <1>`),
stock max 1500 mA flash / 500 mA torch. V74 base: `pm660l_flash` = `pmic@3/led-controller@d300`, `status = "disabled"`.
Runtime dtbo (`a6l-flash-rt-v75.dtso`): `led-max-microamp` 500 mA (stock torch max), `flash-max-microamp` 500 mA,
`flash-max-timeout-us` 100 ms. LED appears as `/sys/class/leds/white:flash`.

| MODE | Does | Limits |
|---|---|---|
| check | read-only: kernel, `sha256sum -c`, DT status, modules, LED list | — |
| load | insmod a6l_flash_ovl → led-class-flash → leds-qcom-flash, list LEDs, brightness 0 | FAIL if `max_flash_brightness` > 500000 µA |
| torch | torch on `TORCH_S` (2, max 10) s then off | default `TORCH_MA=25` → brightness 12/255 ≈ 23 mA (driver: mA = b·500/255, 5 mA steps); `TORCH_MA` 5..100; `LEVEL=max` = 255 = 500 mA (stock torch max) |
| flash | ONE sw strobe via `flash_brightness`/`flash_timeout`/`flash_strobe`, readback checked before strobing | `FLASH_MA` default 200 (13..500), `FLASH_MS` default 50 (10..100) |
| off | force off | — |

Every mode ends with a trap (EXIT/INT/TERM/HUP) writing `flash_strobe=0`, `brightness=0` (`A6L_FLASH_OFF brightness=0`).

```sh
adb -s HLTE730T-PROBE push ~/A6L-usb-20260915/v75/flash /tmp/flash
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/flash MODE=check sh /tmp/flash/run-flash.sh'
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/flash MODE=load sh /tmp/flash/run-flash.sh'
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/flash MODE=torch sh /tmp/flash/run-flash.sh'            # 25 mA, 2 s
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/flash MODE=torch TORCH_MA=100 sh /tmp/flash/run-flash.sh'  # optional
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/flash MODE=flash sh /tmp/flash/run-flash.sh'            # 200 mA / 50 ms, only if Pierre agrees
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/flash MODE=off sh /tmp/flash/run-flash.sh'
```
Expected: kernel log `A6L_FLASH_OVL applied (ovcs N)`, `A6L_FLASH_OVL recreating ... under <spmi dev>`,
`A6L_FLASH_OVL ready`; `A6L_FLASH_LEDS white:flash`; `A6L_FLASH_LED ... max_brightness=255 max_flash_brightness_uA=500000 max_flash_timeout_us=100000`;

## microSD bundle (`run-sd.sh`)

Stock `sdhci@c084000`: vdd = `pm660l_l5` 2.95 V (15..800 mA), vdd-io = `pm660l_l2` 1.8..2.95 V, `cd-gpios = <&tlmm 54 0>`
(active-high), cd pin gpio54 function gpio 2 mA pull-up (`cd_on`). V74 base: `sdhc_2` = `/soc@0/mmc@c084000` disabled,
`sdc2_state_on/off` present, **aliases mmc1 = eMMC c0c4000, mmc2 = SD c084000** → the eMMC is **mmcblk1** on this kernel
(not mmcblk0) and the card should be `mmc2`/`mmcblk2`.
Module parameter `CD=` (script) → `cd=`: 0 = active-high (stock), 1 = active-low, 2 = `broken-cd` (polling). To switch
variant the recovery must be rebooted (the overlay is not meant to be removed; do not `rmmod`).

| MODE | Does |
|---|---|
| check | read-only: DT status, mmc hosts with paths, mmcblk types, sdhci_msm, pm660l_l2/l5 regulators, gpio54 debugfs line |
| load | insmod `a6l_sd_ovl.ko cd=$CD`, wait ≤10 s for the c084000 host → `A6L_SD_LOAD_PASS` + card PRESENT/absent + gpio54 line; FAIL prints `devices_deferred` |
| detect | `DETECT_S` (30) s loop: `A6L_SD_EVENT t=Ns INSERT/REMOVE`, gpio54 changes, heartbeat every 5 s |
| read | CID/CSD/name/manfid/date/serial, size, partitions, `blockdev --setro`, `dd` 16 MiB → /dev/null (MB/s), `mount -o ro` vfat/exfat of p1, `ls`, umount (`MOUNT=0` to skip) |

Guard: `read` only uses a whole `mmcblkN` whose sysfs device path contains `c084000` **and** whose card `type` is `SD`;
otherwise `A6L_SD_REFUSE` and exit (tested on a mock: eMMC mmcblk1, a partition name, an MMC-type card are refused).
Nothing in the script writes to a block device.

```sh
adb -s HLTE730T-PROBE push ~/A6L-usb-20260915/v75/microsd /tmp/microsd
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/microsd MODE=check sh /tmp/microsd/run-sd.sh'
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/microsd MODE=load sh /tmp/microsd/run-sd.sh'      # CD=0
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/microsd MODE=detect sh /tmp/microsd/run-sd.sh'
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH TMPDIR=/tmp; D=/tmp/microsd MODE=read sh /tmp/microsd/run-sd.sh'      # card inserted
```
Expected: kernel log `A6L_SD_OVL applied (ovcs N, cd mode 0)`, one `Unable to retrieve handle to rpm` (expected),
`A6L_SD_OVL ... regulators-a6lsd -> ... parent ...`, `A6L_SD_OVL ready`, then `mmc2: SDHCI controller on c084000.mmc`;
`A6L_SD_REG pm660l_l5 ... uV=2950000`; `A6L_SD_LOAD host=mmc2 (...c084000.mmc...) card=PRESENT mmc2:xxxx type=SD`;
`A6L_SD_LOAD_PASS`. detect: INSERT/REMOVE events matching Pierre's actions. read: `A6L_SD_READ disk=mmcblk2 size=...`,
`A6L_SD_READ dd rc=0 16 MiB in N ms = X MB/s` (toybox `dd` also prints its own rate), `A6L_SD_READ_PASS`.

## Open risks / uncertainties

- **Is there a microSD slot at all?** stock `ro.build.characteristics=nosdcard`; the stock DT enabling sdhc_2 is not proof.
  Pierre: look at the SIM tray first. `load` PASS only proves the controller probed; no card = `card=absent`.
- **CD polarity**: stock flag 0 → active-high with pull-up (as Sony Nile). If the card is never seen, or seen with no card,
  reboot the recovery and retry with `CD=1`, then `CD=2` (polling).
- Re-parent path is new (not yet exercised on hardware). If LOAD_FAIL with "Failed to get parent regmap" / "Unable to
  retrieve handle to rpm" without a following `A6L_*_OVL ... parent` line, stop and send the kernel log.
- Flash channel: channel 1 (= stock flash_0/HW 0) per stock DT; if torch shows nothing and no fault, the LED may be on
  another channel (needs a rebuilt dtbo, `led-sources = <2>`).
- The PM660L flash block may need the (unmodelled) stock headroom/thermal-derate settings; mainline driver defaults are used.
- UHS SDR104 switching uses vqmmc L2 1.8 V as stock; if the card fails at high speed, a `no-1-8-v` variant would be next.

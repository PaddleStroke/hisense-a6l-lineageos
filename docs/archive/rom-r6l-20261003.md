## E-ink and wake investigation

r6k composition now takes about 52–63 ms and input preparation about 50–80 ms,
confirming that the earlier CPU optimization helps on the physical phone.
Most appearance requests nevertheless receive an invalid transaction present
fence and fail open at three seconds. Empty no-buffer redraw transactions can
produce invalid fences; this is not evidence that all HWC fences are unsupported
because two rear requests have valid fences. Successful requests still spend
about 2–2.5 seconds waiting for first rear frame completion. Cold bridge bring-up,
waveform generation/drive and temperature reads need separate measured timings.

Candidate work suppresses E-ink-only animations, preserves exact LCD scale
settings, and handles launcher and notification/Quick Settings gestures that
bypass duration scales. Per-sequence WM, native key/wake, capture and command
stage logs distinguish empty redraw, configuration, display resume and panel
latency. No GPU power/clock/voltage policy or waveform/rail timing reduction is
claimed. The reported ten-second wake is outside the saved stream; the ordinary
LCD wake does not invoke appearance preparation, so it cannot be attributed to
the three-second switch timeout from these logs alone.

The fresh-render trial forces ViewRoot's actual HWUI root display list to be
invalidated once for each exact current theme request, gated to the A6L default
display and a buffer-synchronized reported draw. A Java dirty rectangle alone
does not prevent an empty HWUI redraw. Valid presented-fence checks remain
mandatory, with the existing group/fence deadlines. The actual helper/callsite
fixture passes 41 cases; physical valid-fence frequency remains to be measured.

Temporary animation scales save/restore exact prior raw values (including unset,
zero and custom values), durably across controller recreation. Global restoration
passes 78 cases; theme/gate checks pass 31/24. Launcher pages use their existing
immediate snap path; launcher springs emit final geometry and normal completion.
QS interpolation uses endpoints. The mirror continues delivering touch but
suppresses new captures during moving rear gestures, discarding captures that
span drag transitions. Actual mirror FIFO/gesture tests and 24 gate cases pass.
EPD/dualux service suites pass 20/11; ARM64 native compilation has zero warnings.
The final three native daemons also stamp every Android log with boot_ms and
mono_ms, so wake events can be correlated with Java across suspend. Fifteen
actual-wrapper ASan/UBSan checks pass. Scheduling/deadlines still use monotonic
time; electrical timings and host stdout are unchanged.
The redundant 200 ms controller settle delay is removed while exact readiness
checks remain; mirror property polling changes from 500 to 50 ms.

The actual boot DT confirms no TPS65185 PMIC interrupt. Its original temperature
read therefore waits the 200 ms IRQ timeout even when conversion is complete.
The isolated candidate polls READ_THERM clear plus CONV_END set, at 2 ms intervals
within the same 200 ms bound, only for the IRQ-less case. IRQ behavior, fresh
temperature/error reporting and all rail/voltage/waveform timings are retained.
The actual driver routine passes 12 ASan/UBSan cases; module vermagic and all 36
import CRCs match the retained kernel. Physical saving is not measured yet.

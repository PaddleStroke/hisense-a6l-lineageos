## 1. Decoding `A6L_VFE0_STOP irqs 373 bits s0b5:3 s0b8:2 s0b31:1 s1b4:1 s1b29:370`
| bit | VFE 4.8 meaning (upstream camss-vfe-4-8.c + downstream msm_isp47/48) | count | reading |
|---|---|---|---|
| s1b29 | **RDI0 SOF** (`IRQ_STATUS_1_RDIn_SOF(0)`), not an error | 370 in ~9.2 s | every frame reaches VFE0 RDI0 (≈40 IRQ/s) |
| s0b8 | WM0 ping-pong done (`IMAGE_MASTER_n_PING_PONG(0)`) = a frame written to DDR | **2** | only 2 frames ever reached memory |
| s0b5 | RDI0 reg-update ack | 3 | enable + one per WM-done (upstream calls reg_update from each done) |
| s0b31 | reset ack | 1 | normal |
| s1b4 | **bus error** summary on VFE 4.8 (`msm_vfe48_get_bus_err_mask`, per-WM bits in 0xC94). On 4.7 the same bit = "realign buf y overflow". Stock ignores it for RDI WMs (`set_bus_err_ign_mask` in `msm_isp_axi_reserve_wm`) | 1 | one occurrence at irq#3, right after frame 1; not in the IRQ mask, so upstream never sees it |
No overflow (s1b9..15), no violation (s1b7), no camif error. ISPIF: no RDI0 overflow (bit 25); status 0x2000/0xa000 = RDI0 SOF (+bit 15) each frame.

## 2. Register dump vs. what the driver programmed
- 0x05c/0x060 IRQ masks 0x80000120 / 0x20000380: reset-ack, WM0 done, RDI0 reg-update / RDI0 SOF, WM0 overflow, halt-ack, violation. OK.
- 0x084 BUS_CFG 0x101, 0x090 XBAR 0x00000c00 (WM0 <- RDI0), 0x46c RDI0_CFG 0x7 (MIPI_EN + RDI_EN, stream 0, CID 0). Matches stock `msm_vfe47_cfg_rdi_reg`.
- WM0: ping 0xfe800000, pong 0xfe000000: valid, distinct IOVAs 8 MiB apart. The frame 2880x2156 RAW10 = 3600 B/line = 7 761 600 B fits.
  UB_CFG 0x2aa (offset 0, depth 682 of the 2047-word UB, upstream value). IMAGE_SIZE and BUFFER_CFG are 0: frame-based.
- **WR_ADDR_CFG 0x7e = frame-based + framedrop period field 31, FRAMEDROP_PATTERN 3.** This is upstream's scheme: toggle the
  period 30/31 and set pattern 1 or 3 on every reg update, assuming the HW restarts its framedrop counter on each reg update.
- 0x338 ping-pong status 0x00100000 (WM0 bit = 0), 0x4a4 CAMIF status 0x80000000 (halted, PIX unused), 0x4ac = 2 (RDI0 update).
**Cause.** Pattern 3 was active from the first frame, but frames 1..11 produced no WM-done (irq#2..#12 in the log). Then
exactly 2 dones occurred, then none for about 360 frames. The framedrop counter therefore does not restart on this VFE 4.8.
The two dones fit the counter reaching bits 0/1 of the 32-frame window once. After that, the period toggle leaves no matching window.

Stock never uses this scheme. It uses `framedrop_period` 1 (reg 0) with pattern 0x1, so **every frame is written** (see
`msm_isp_cfg_framedrop_reg`). When no user buffer is queued, it points the free ping/pong slot at a **scratch buffer**
(`msm_isp_cfg_stream_scratch`). For frame-based WMs, stock also writes the ADDR_CFG value into WR_BUFFER_CFG
(`msm_vfe47_axi_cfg_wm_reg`), which gives burst length 2. Upstream writes 0. Ping/pong semantics were checked against stock and agree
with upstream: status bit = the slot being written, the other slot has just completed. Stripe/size/UB/XBAR/RDI config all match
stock, so no stride or crop mismatch is involved.

## 3. The phone reset at stream-off
Stream-off order is VFE → ISPIF → CSID → CSIPHY. The VFE dump completed and the VFE was stopped (reg-update ack seen).
The ISPIF dump printed rows up to 0x480, and the log ends there. Rows 0x4a0+ are the **VFE1 interface bank**. Its interface
status registers need `csi_vfe1`/`vfe1` clocks, which are only in VFE1's clock list and are off because VFE1 is unused. The
VFE0 bank's status row 0x2c0 read fine. An unclocked read hangs the bus and causes a watchdog/NoC reset.

## 4. Changes: `device/hisense/a6l/kernel/camera/patches/camfix3_patch.py` (after camfix + camfix2)
Cumulative diff vs. 7.2.3: `patches/camss-sdm660-camfix3-cumulative.patch` (677 lines).
1. **`a6l_wm` module param (default 3, runtime-writable, read at STREAMON):**
   - bit0 = stock-like RDI write master:
     - period reg 0 / pattern 1, so every frame is written; no per-frame reg-update.
     - A per-line scratch buffer (sizeimage, `dma_alloc_attrs(..., DMA_ATTR_NO_KERNEL_MAPPING)` on the camss/IOMMU device, allocated
       outside the spinlock at STREAMON and kept for reuse) fills any slot that has no user buffer.
     - Buffers are handed to the HW only from the WM-done IRQ (race-free); `queue_buffer` just adds to the pending list.
   - bit1 = stock frame-based BUFFER_CFG (= ADDR_CFG value).
   - `a6l_wm=0` = upstream (camfix2) behaviour. Only RDI lines are affected; the PIX path is unchanged.
2. **Safe dumps:**
   - ISPIF: reads only 0x000-0x07f and the bank of the VFE in use (0x200-0x2ff for VFE0), and only while `power_count > 0`.
   - VFE dump: runs only while `power_count > 0`; adds 0xc80-0xc9f (bus-error regs).
   - CSID: the register dump at stream-off is **dropped**. Only `A6L_CSID<n>_STOP irqs N` remains; the START dump is kept, since it worked in t25b.
3. **Diagnostics:**

## 7. Risks / unknowns
- **Not verified on HW.** The framedrop-counter explanation is inferred: it fits the counts and irq#2..12, but the exact time of the 2
  dones was not logged. The new done# lines give the timing.
- The scratch buffer takes one sizeimage (7.4 MiB for IMX576) of IOVA/RAM per RDI line and is kept until module unload. It is freed only
  when a larger format needs a new allocation, and leaks at rmmod (debug-grade).
- Every frame is now written (≈230 MB/s for IMX576 full-res at 30 fps). This is within the ICC vote added in camfix2 (1 GB/s avg).
- s1b4 bus error: meaning taken from stock (RDI WM bus errors are normal and ignored). If it repeats every frame with no dones, see the table.
- VBIF QoS settings from stock DT (0x124=3, 0xac=0x40, 0xd0=0x1010 at 0xca40000) are still not applied, because the mainline DT does not
  map VBIF. Not expected to matter for one RDI stream.
- No CSID register dump at stream-off any more. The CSID START dump and IRQ lines remain.

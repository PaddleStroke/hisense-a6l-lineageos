## 1. Charger: qcom_smbx never bound (task 1)

**Root cause (from today's t27-16 log + the V74 base DT):** the V74 base already contains `/battery` (label `a6l_battery`,
phandle 0xe5, from a6l-battery-telemetry) and `pm660_fg` okay. `a6l-charger-v75.dtso` / `a6l-charger-test.dtso` re-declared
`a6l_battery: battery { ... }`. `fdtoverlay` (build time) silently merges that, but the kernel's runtime overlay
(`of_overlay_fdt_apply`, used by `a6l_chg_ovl.ko`) refuses it: an overlay node with a phandle onto a live node that has a
phandle -> `-EINVAL` (drivers/of/overlay.c add_changeset_node) and the `a6l_battery` `__symbols__` entry is a duplicate
(-EINVAL). So **nothing was applied**: rradc stayed `disabled` (-> "rradc:" empty), FG had no `power-supplies`
("Failed to get charger supply: -2"), charger@1000 stayed disabled -> `qcom_smbx` loaded but never probed. The "EEXIST"
in run-power.sh was only the script's guess. (Charger node itself was fine: compatible `qcom,pm660-charger`, 4 interrupts,
`io-channels = <&pm660_rradc 3>, <&pm660_rradc 4>` usbin_i/usbin_v; rradc node `qcom,pm660-rradc` reg 0x4500 is complete.)

**Fixes**

## 2. Headset-mic detection (MBHC "Mic Jack: Off") (task 2)
**Cause:** mainline `msm8916-wcd-analog` reports SND_JACK_HEADSET only if a BTN0 press+release interrupt happened *before*
the mechanical insertion interrupt. On the A6L (PM660L analog codec) that never happens, so every 4-pole headset is reported
as headphones (Headphone Jack On, Mic Jack Off) although the headset mic records fine (A6L_AU6_CAP_headset_PASS today).
The DT MBHC props are present and correct (`qcom,mbhc-vthreshold-low/high` 75/150/237/437/437 mV, hphl normally-open =
stock `msm-mbhc-hphl-swh=1`); the ALSA jack mapping (qcom common: "Mic Jack" = SND_JACK_MICROPHONE) is fine.
(Stock has `msm-mbhc-gnd-swh=0` while the base DT has `qcom,gnd-jack-type-normally-open`; the mainline driver never enables
GND detection, so it is left as is.)

**Fix** `device/hisense/a6l/kernel/audfix/a6l-wcd-analog-mbhc-mic-v75.patch` -> `snd-soc-msm8916-analog.ko` (387273ad…):
after an insertion without the BTN0 sequence, a delayed work (300 ms) force-enables DAPM "MIC BIAS External2", waits 100 ms,
reads MBHC_RESULT_1 (and ZDET_ELECT_RESULT 0xf159 for the log), releases the bias: result 0x1f (mic line above every button
threshold = electret mic present) -> report SND_JACK_HEADSET; 0x00 (mic ring grounded) -> 3-pole, stays headphone; anything
else -> re-measure (500 ms, max 4 tries). Button interrupts are ignored while measuring. Module param `a6l_mbhc_detect`
(default 1, runtime 0644) turns it off. Logs `A6L_MBHC inserted/removed`, `A6L_MBHC try N: btn_result=0x.. elect_result=0x..`,
`A6L_MBHC_HEADSET` / `A6L_MBHC_HEADPHONE`. Staged: `fixes-20260927/mbhc/`, and ready-to-overlay copies for the bundles
(`fixes-20260927/audio6/{modules/…,SHA256SUMS}`, `fixes-20260927/speaker/{modules/…,SHA256SUMS}`); ROM: `setko` in
`tools/stage-rom-v2-prebuilts.sh`.

## 4. Radio HAL: provisioning + PIN guard + radio power (task 4)
`device/hisense/a6l/radio/hal/ModemCore.{h,cpp}`, `hal/RadioSimModemConfig.cpp` (same logic as today's CLI fix):
- `provisionIfNeeded()` now covers **slot 1** (primary GW session) as well as slot 2: whenever the card has a detected USIM/SIM
  app but the modem left the session inactive (gw_primary=0xffff), the core sends UIM Change Provisioning Session (session,
  activate, uim slot, AID). Called at init, on **every card status indication**, and after radio power changes. Rate limit:
  5 s apart, 3 tries per SIM power cycle (re-armed when the session appears or the radio power changes). Log `A6L_RIL_PROVISION`.
  `persist.vendor.a6l.ril.auto_provision=false` still disables it.
- **Radio power**: LOW_POWER -> ONLINE powers the SIM down; `setRadioPower()` now re-arms provisioning and re-reads the card
  2 s and 6 s later (card status + provision + `onSimChanged` -> Android `simStatusChanged`), so Android sees "PIN required"
  again even without a modem indication. **The HAL never stores or re-sends a PIN.**
- **PIN guard** `ModemCore::checkPin()` (pure) + `pinPreflight()` (fresh card status, provisions first and waits up to 5 s)
  used by `supplyIccPinForApp`: PIN sent only for app state PIN with >= 1 attempt (UPIN counters when UPIN replaces PIN1) and
  4-8 digits. Otherwise not sent: no card -> `SIM_ABSENT`; not provisioned / app not asking for a PIN -> `INVALID_SIM_STATE`;
  blocked/PUK/0 attempts -> `PASSWORD_INCORRECT` with remainingRetries 0 (Android then asks for the PUK); bad format ->
  `INVALID_ARGUMENTS`; the **same PIN the card already rejected (per ICCID) -> `PASSWORD_INCORRECT` without sending**
  (protects against automatic re-entry loops); app already READY -> NONE (nothing sent). Log `A6L_RIL_PIN … preflight verdict=`.
- Host tests: new `radio/tests/simprov_tests.cc` (added to `tests/run-host-tests.sh`): pure guard table (no card, not provisioned, PIN 3/1/0 left, PUK, blocked, ready, detected, bad formats, UPIN), slot-1
  auto-provisioning with the exact TLVs (session 0 activate 1, slot 1, AID), PIN state after provisioning, repeated-wrong-PIN
  guard, blocked, LOW_POWER -> ONLINE re-provisioning + SIM re-report with **0 VERIFY PIN sent by the core**, provisioning
  rate limit when the modem ignores it. **Full suite (g++ ASan/UBSan): qmi 271, modemcore 87, volte2 291, volte2-modemcore 11,
  volte3 147, `A6L_SIMPROV_TESTS PASS (45 passed, 0 failed)`, exit 0.** RadioSimModemConfig.cpp / ModemCore.cpp also pass an NDK
  clang `-fsyntax-only -Wall -Wextra -Werror` against the Lineage AIDL V4 headers (with the existing CDMA deprecation warnings
  silenced as the real build does). Not built with `m` (rule).
- Other PIN paths (changeIccPin, facility lock "SC", PUK) are unchanged (they still go to the card; PUK entry is always user-driven).
- **volte-probe label** (`tools/volte/volte-probe.c`): libqmi `qmi-service-nas.json` Get System Info: TLV 0x29 "IMS Voice
  Support" (boolean), TLV 0x2A "LTE Voice Domain" (`QmiNasLteVoiceDomain`: 0 none, 1 IMS, 2 1X, 3 3GPP). New wording:
  `ims_voice_support=%u (TLV 0x29 IMS Voice Support, boolean: 1 = the LTE network indicates IMS voice over PS, 0 = not
  indicated/not supported)` and `lte_voice_domain=%u (TLV 0x2A LTE Voice Domain: 0 none, 1 IMS, 2 1X, 3 3GPP CS; …)`.
  So today's `ims_voice_support=0` means the network/modem did **not** indicate IMS voice on LTE; `lte_voice_domain=3` = 3GPP
  (CS fallback) — the reading in attended-20260927 stays valid. Unit test PASS; static NDK build `fixes-20260927/volte/volte-probe`
  (f9ab3b40…; the pinned volte-20260925 binary was not overwritten). The a6l-qmi CLI labels (`lte_ims_voice`, domain map) already matched libqmi.
- ROM test (r4, with a PIN SIM): logcat `A6L_RIL_PROVISION slot1` when the modem left the session inactive; Android PIN
  prompt; correct PIN -> `Sim.supplyIccPin … left=3`; airplane on/off -> PIN prompt again, no `Sim.supplyIccPin` unless typed;
  the same wrong PIN twice -> 2nd time `NOT sent: the card already rejected this PIN` (retries unchanged).

## 5. Bluetooth "Malformed MSFT vendor event" (task 5)

events do not parse. Patch `device/hisense/a6l/kernel/bluetooth/a6l-btqca-no-msft.patch` -> `btqca.ko` (ea345ab1…,
`fixes-20260927/bluetooth/`): new param `enable_msft` (default 0) skips `hci_set_msft_opcode` and logs
`A6L: MSFT extension disabled`. Nothing on the phone uses MSFT (LE monitor offload). ROM: `setko` in stage-rom-v2-prebuilts.sh.

## 7. Risks / not verified
- Nothing ran on the phone. The runtime overlay path is now kernel-rule clean (checked offline), but the reparenting of the
  new rradc/charger devices is still the a6l_fl_ovl design (first real run in C2).
- JEITA_EN_CFG HARDLIMIT relies on the FG JEITA thresholds programmed by the bootloader (0/10/45/55 read today); FCC/float are

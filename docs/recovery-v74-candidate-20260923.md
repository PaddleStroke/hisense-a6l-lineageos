Repo copy: `firmware/extracted/v74-bundle-20260923/` (`run.sh` sha `56542b29…95ad3`, `assemble-on-laptop.sh`, `SHA256SUMS`).
Contents = the **proven 23 Sep evening payloads**, re-hashed: bundle-r16 modules (display ∪ gpu: tps65185 `c7b9ffaf…`,

(libtcon_eink, lib64, linker64, waveform `epd-nor.bin` `bcc829d1…`, test PGMs, scripts), `script-phone-clear.txt`, tools
(a6l_mmio, modetest, a6l_tps65185_step, a6l_gpio_hold, a6l_epd_play). `run.sh` does, in order: toybox links in /tmp/bin →
image check (controls = v71; prints image v71/v74) → `sha256sum -c` → `insmod /sdhci-msm.ko; sleep 6` (skip with
`A6L_NO_EMMC=1`) → tps65185 (BOUND check) → GPU modules with `separate_gpu_kms=1` (renderD128 check) → ft8719 + V73 panel →
/dev nodes (dri, i2c-*, gpiochip*, snd) → copies the e-ink payload to `/tmp/epd` (same layout as r149/r155) → prints the
e-ink command and `A6L_BUNDLE_V74_READY`. Works on V71 **and** V74. Syntax-checked (`sh -n`, `bash -n`); not run on a phone.

```
cd ~/A6L-usb-20260915
adb -s HLTE730T-PROBE push v74/bundle-v74 /tmp/bundle-v74
adb -s HLTE730T-PROBE shell 'D=/tmp/bundle-v74 /system/bin/sh /tmp/bundle-v74/run.sh'      # ~30 s

adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; E=/tmp/epd; LD_LIBRARY_PATH=$E/lib64 $E/a6l_epdd_v2 --xon-line -1 --waveform $E/epd-nor.bin --lib $E/lib64/libtcon_eink.so --script $E/script-phone-clear.txt'
```

Expected: `A6L_EPD_PMIC_BOUND_PASS`, `A6L_GPU_RENDER_NODE_PASS`, `card*-DSI-1 status=connected`, `A6L_EPD_STATUS prepared=…`,

## 5. Attended install procedure (Pierre present; same flow as V71)

Preconditions: phone in **stock Android** (adb serial `1e529013`, original fingerprint, boot_completed), USB on the established
laptop port 3-2, battery ≥ 40 %, phone recovery = V71 (the tool refuses anything else), no earlier host pause.
1. Laptop: `cd ~/A6L-usb-20260915 && python3 Verify-ControlsV74CStage.py` → `"passed": true`.
2. `python3 Launch-ControlsV74CInstall.py` **once** (desktop session; it takes the idle/suspend inhibitor, pauses host services,
   `adb reboot edl`, writes only the recovery partition with V74, reads everything back, powers the phone off, restores
   services). Watch `controls-v74c-install-launch.log`; result in `capture-diagnostic-install-user-v74c/session.json`.
   If it stops: keep USB connected, do not retry; inspect the capture first.
3. Copy the capture to the desktop `captures/` and run `python3 tools/Verify-ControlsV74CReadbacks.py install`.
4. Pierre boots the recovery the usual way (fastboot menu → Recovery). First checks (read-only):
   `cat /proc/device-tree/chosen/hisense,a6l-image` → `v74`; `ls /proc/device-tree/aliases/` has `serial1`;
   `dmesg | grep c1af000` → the port registers as ttyMSM1 without -22.
5. `bundle-v74` as in §4 → e-ink v2 clear (Pierre watches the rear panel), then
   `cat /sys/kernel/debug/regulator/regulator_summary | grep epd-vcom` (expect 2400 mV).
6. BT (RF: only with Pierre's explicit go, Pierre types it): the radio `run-bt.sh` should now work with **no rebind**; if it
   still rebinds, that is harmless.

## 7. Risks / unknowns

- XON is now held by the panel driver: high from `.prepare` (after reset) to `.unprepare`, instead of from epdd start. The
  rails still only switch on in `epd_power` after `.enable`, so "XON high before the rails" holds. Untested on the panel.
- VCOM apply at registration is one extra I2C write (VCOM1/VCOM2 bit 0) during `tps65185` probe. If that write failed,
  the regulator (and the panel's rails) would fail to register → e-ink down in that boot → roll back or remove E3.
- serial1 makes msm_serial register the BT UART at boot (built-in driver). The radio agent expects better console hygiene;
  still an untested boot-time change.
- Files: `tools/{Prepare-RecoveryV74,Test-RecoveryV74,Prepare-V74CTrial,Stage-V74C,Verify-ControlsV74CStage}.py`, generated
  `tools/*V74C*`, `*V74R*`, `*-v74c*`, `*-v74r*`, `diagnostic-user-v74{c,r}-tools.json`, `v74c-pins.json`,
  `device/hisense/a6l/kernel/a6l-eink-v74.dtso`.

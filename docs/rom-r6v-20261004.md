## Confirmed cause

All three sensors' timestamps advance approximately 33.3 ms per sensor sequence (~30 Hz). The software ISP cannot process that stream fast enough. It processes each native pixel on the CPU using two workers: RAW Bayer interpolation, gamma/AWB lookup and BGR-to-NV12 conversion, followed by a separately overlapping preview scaler. There is no active RAW field-of-view resampling in these tests.

In normal Aperture on r6u, processing completion medians were 150.83 ms main (6.63 Hz), 101.91 ms selfie (9.81 Hz) and 58.07 ms wide (17.22 Hz). These are processing completions, **not measured screen FPS**. Main processes 2872×2156 pixels, selfie 2296×1728 and wide 1624×1224; the per-pixel CPU work explains the main camera's much larger cost. Preview scaling additionally takes about 34–37 ms, overlapping rather than adding strictly to ISP time.

## Accepted changes

- Exact ARM NEON Bayer interpolation, retaining all gamma/AWB table entries and the original scalar tail and CCM/alpha paths.
- Exact ARM NEON BGR-to-NV12 conversion: same coefficients, rounding, saturation and four-pixel chroma averaging.
- Six processing workers instead of two. Six were more consistent than eight and leave two of the eight CPU slots for preview/framework/UI work; this does not reserve cores or alter affinity or clock speeds.
- Exact preview-column interpolation with a thread-local geometry cache and bounded table gathers. Original Y and UV interpolation arithmetic and unsupported-geometry fallbacks are retained.

Native field of view, output sizes, sensor registers, tuning, IPA/signature/key/base/proxy and controls are retained. This does not correct remaining stock-versus-port optical quality differences. Both extra vector gamma-table experiments were slower and are excluded.

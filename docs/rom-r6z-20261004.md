## Playback

The new r6y WAV contains microphone signal (RMS -30.95 dBFS) and lacks the earlier
repeated ~85-ms capture gaps. Active speaker playback proves the complete DAPM
path is powered, TFA firmware is OK and DSP initialization complete. However,
the PCM repeatedly recovers from XRUN. Actual hardware negotiation selects
1440 frames x 4 periods = 5760 frames, while software avail/start/stop values
remain 1024/2048/4096 from the original request. At hardware pointer 2879 and
application pointer 4096, availability 4543 exceeds stop 4096 while 1217 frames
are still queued.

The deployed library is `libtinyalsav2` from `external/tinyalsa_new`, rather than
the older tinyalsa source initially inspected. Its configuration code reads
negotiated periods but computes ring size and default thresholds from the
original caller structure. The correction derives ring size, avail_min,
xfer_align and default thresholds from negotiated dimensions; explicit nonzero
thresholds and NULL-config full-buffer startup are preserved. All later
transfer, prepare, DROP, pointer and close functions remain byte-identical.

The original full source reproduces the premature stop. The corrected full
source passes 152 host and sanitizer assertions; the independent sanitizer
supplement runs 254 total assertions including the original cases. ARM64 object
compilation and patch checks pass. Only this library inside the audio APEX may
change; the retained capture-fixed HAL executable and APEX keys/certificate are
checked separately. The r6z trial confirms HWperiod1440/ring5760 and software
avail1440/start2880/stop5760. Eleven samples RUNNING in one trigger epoch,
continuous pointers through about73 rings, no sampled XRUN/premature stop;
speaker DAPM path powered and TFA DSP initialized. Early quiet AudioFlinger PCM
matches the WAV's quiet introduction. Acoustic listening, repeated opens, new
spoken-recording quality and calls remain physical acceptance items.

PCM status queries invoke the kernel's normal hardware-pointer refresh; they
are not passive cached reads and may expose an already invalid stop threshold.
Trial 2 captured idle state because its VIEW intent did not restart a completed

## E-ink labels and tracing

The retained launcher selected a dark-text wallpaper theme but workspace icon
style still inherited hardcoded white glyphs. With shadows removed on white
e-ink, the names became invisible. One style item now resolves text color through
`workspaceTextColor`. AllApps overrides and intentional hidden hotseat/taskbar
labels are retained. Launcher compilation, actual compiled resource inspection
and unchanged platform signer checks pass; rear/LCD optical acceptance is pending.

The inherited AVF `vsock://-1:2010` Perfetto relay fails on this physical kernel
and restarts traced about every five seconds. A guarded system_ext init action
clears only this exact inherited relay on the A6L, retaining local Unix tracing.
The temporary live correction keeps PID11221 stable across at least 20 seconds
and `perfetto --query` succeeds. It is a debug startup fix, not a proven sleep fix.

## Still open

Washed camera colors require proper sensor calibration and matched RAW/neutral
and stock comparisons. CCM/LSC are absent; AWB/tone processing is generic, and
the current pixel path loses RAW low bits. Those are verified capability gaps,
not a quantified explanation for this specific portrait. A private ten-bit,
per-Bayer-phase measurement helper is prepared for future controlled calibration
and is excluded from r6z. No stock coefficients, black level or gamma are guessed.

Intermittent lock/suspend failure remains unresolved. The previous retained log
ends at s2idle entry with no persistent panic; that does not establish successful
resume. The current awake r6y diagnostic boot has stayed alive throughout these
measurements. Further sleep evidence must distinguish OS wake from USB loss.

## 1. Summary
- **What Pierre asked, and what now happens**
  | Situation | Key | Result |
  |---|---|---|
  | LCD active, awake | e-ink key | switch to the e-ink: LCD backlight off, UI mirrored on the e-ink, rear touch drives Android, front touch ignored |
  | LCD active, asleep | e-ink key | wake up **on the e-ink** |
  | LCD active | power | normal Android (sleep / wake / hold = power menu) |
  | e-ink active, awake | power (short) | **back to the LCD, no sleep** |
  | e-ink active, awake | power (held ≥ 0.45 s) | handed to Android → power menu |
  | e-ink active, awake | e-ink key (single) | **sleep** (stock behaviour; setting: "clear" instead) |
  | e-ink active, awake | e-ink key (double) | full clear (anti-ghosting flash) |
  | any | e-ink key held ≥ 0.8 s | full clear |
  | e-ink active, asleep | e-ink key / power | wake on the e-ink / wake on the LCD (stock) |
  | e-ink active | brightness slider, auto-dim, keys | drive the **e-ink frontlight**, LCD stays dark |
  | LCD active | brightness slider | LCD backlight, frontlight off |
- **Framework-free design** — no framework patch is needed. A vendor daemon `a6l_dualux` (C, 16 KB of logic) owns the
  switch: it reads the e-ink key from evdev, *grabs* the power key and the front touchscreen only while the e-ink is
  the screen, injects KEY_WAKEUP / KEY_SLEEP / a re-timed KEY_POWER through its own uinput keyboard, blanks the LCD with
  `bl_power`, and turns what the composer writes into the LCD `brightness` node into the frontlight level. A
  platform-signed app `A6LDisplaySwitcher` provides 4 Quick Settings tiles and the e-ink settings screen (Settings >
  Display) and remembers brightness + screen timeout per screen (stock does the same). Only system properties cross the
  system/vendor boundary.
- **Stock behaviour decompiled** (services.vdex, §2): e-ink key = `EPD_POWER` (Generic.kl `key 616 EPD_POWER`), the
  table above is the stock table; stock frontlight = LED-class `epd-backlight` on **PM660L LPG channel 4 (pwm@b400,
  54 µs) → DTEST2 → PM660L GPIO6**, one channel only (no warm/cold), driven by the stock lights HAL when
  `sys.sysctl.display_type` says e-ink; separate `screen_brightness_epd` / `screen_off_timeout_epd` settings.
- **Found a real bug in the 22 Sep frontlight candidate**: as a `pwm-backlight` named `a6l-eink-frontlight` it would sort
  before the LCD's `backlight` and drm_hwcomposer attaches the *first* backlight to display 0 → the slider would have
  driven the frontlight and never the LCD. New overlay `a6l-eink-frontlight-v75.dtso` uses `leds-pwm` with the stock
  name `epd-backlight` (not a backlight-class device). `CONFIG_LEDS_PWM` is off in v67 → `leds-pwm.ko` built externally.
- **Verified offline**: state machine unit tests **158/158**; daemon end-to-end on a fake sysfs + property files +
  evdev FIFOs **25/25** (switching, re-blank after the composer unblanks, frontlight tracking incl. HLG decode, sleep/
  wake, double press, power long-press re-injection, requests, restart after a crash in e-ink mode, SIGTERM restores the LCD); refresh-mode mapping tests
  pass; eink3 logic regression 50/50; NDK static build 0 warnings; composer patch 0002 `git apply --check` + clang
  syntax check clean; frontlight overlay compiles and merges onto V74 `base.dtb` (`aceadcb7…`); app aapt2 + javac (0 warnings) + d8 clean; SELinux (vendor + system_ext) passes a monolithic checkpolicy with all neverallows; bundle staged on the laptop `v75/dualux` (8/8 sha OK).
- **Not tested at all**: anything on the phone; the frontlight hardware path (needs Pierre, §7F); the app (no device);
  SELinux (written from reading; ROM runs permissive).

## 2. What stock does (evidence)
Decompiled with vdexExtractor (`--dis`, built in the Cowork VM) from `system/framework/oat/arm64/services.vdex`;
excerpts in `firmware/extracted/dualux-20260925/stock-epd-key-policy-disassembly.txt`.
- **Keys** — `system/usr/keylayout/Generic.kl`: `key 616 EPD_POWER`, `key 555 EPD_READING_WAKE`, `key 539 SWITCH`.
  `HmctPhoneWindowManager` handles EPD_POWER with a double-tap timeout (`getDoubleTapTimeout()`):
  - single press (`HmctPhoneWindowManager$30.run`): e-ink on → `PowerManager.goToSleep`; LCD on →
    `EpdManager.setDisplayType(4)` (e-ink); all off → `setWakeupSourceType(1, 4)` + `wakeUp…` (wake on the e-ink).
  - double press (`EpdKeyDoubleClickFunction`, log "EpdPower key long press"): LCD → AI assistant; e-ink (keyguard not
    showing) → `HmctPolicyHandler` msg 118; neither → "epd_show_screenshot_note" intent. The handler has an
    `epdForceClear()` path (`EpdManager.forceClear` → `SurfaceControl.forceClearGhosting`); that 118 is that path is
    likely but the packed-switch table was not decoded — we map double press on the e-ink to "clear".
  - `PhoneWindowManager.powerPress` (SHORT_PRESS_POWER_GO_TO_SLEEP/REALLY): if the e-ink is on and the Hall cover is
    not closed → `setDisplayType(0)` "powerPress switch to primary screen" — **no sleep**; otherwise normal sleep.
- **Brightness** — `DisplayPowerController.getScreenBrightnessSetting()` returns `Settings.System.screen_brightness_epd`
  while the e-ink is active (also `screen_brightness_mode_epd`, `screen_off_timeout_epd`, `brightness_for_slide_epd`),
  so each screen has its own level. The stock lights HAL (`vendor/lib64/hw/lights.sdm660.so`) reads property
  `sys.sysctl.display_type` and writes `/sys/class/leds/epd-backlight/brightness` (scaled to its `max_brightness`,
  log "cur screen epd, max brightness: %d") instead of `/sys/class/leds/lcd-backlight`.
- **Frontlight hardware** — stock DT panel node `qcom,mdss_dsi_epd_eink_qhd_video` ("eink epd qhd", display_2):
  `qcom,mdss-dsi-bl-pmic-control-type = "bl_ctrl_pwm"`, `pwms = <&pm660l pwm@b400 0 0>`, `qcom,mdss-dsi-bl-pwm-pmi`,
  `qcom,mdss-dsi-bl-pmic-pwm-frequency = <54>` (µs), `qcom,mdss-dsi-pwm-gpio = <&pm660l_gpios 6 0>`, no
  `bl-max-level` (→ mdss default 255). `pwm@b400`: `qcom,channel-id = 4`, `qcom,dtest-line = 2`, `qcom,dtest-output = 2`,
  `qcom,period = 54`. PM660L `gpio@c500` (GPIO6): mode 1 (out), vin-sel 1, src-sel 7 (DTEST2), out-strength 2, master-en.
  Stock kernel strings: `epd-backlight`, "set epd backlight from %d to %d". Duty = level/255 × 54 µs (linear).
- **Settings UI** — stock `Eink_Settings.apk`: per-app "clear mode" (quality, slow) vs "smooth mode" (fast) lists,
  "E-ink screen default mode", "High contrast text" (`persist.sys.epd.contrast/black/white` → fb1 `epd_contrast`,
  `epd_black_threshold`, `epd_white_threshold`), lock-screen style. No frontlight page (the normal slider does it).
- **Touch** — stock `EpdManagerService.setExternalTpEnabled` writes `/sys/ctp1/ctp_func/tpenable` (rear touch on/off).

## 3. Design
```
 e-ink key (gpio-keys "A6L side keys", KEY 616, read-only) ─┐
 power key ("pm8941_pwrkey", grabbed in e-ink+awake)        ├─► a6l_dualux (vendor, user system) ──► persist.vendor.eink.mode = mirror|off ──► vendor.a6l_eink (mirror)
 front touch (MT, x max ≥ 1000; grabbed in e-ink)           │     dualux_logic.c (state machine)     vendor.eink.clear_req = n ─────────────►   clear + redraw
 /sys/class/drm/card*-<1080x2340>/dpms (awake)  ────────────┤                                        LCD /sys/class/backlight/backlight/bl_power = 4 (e-ink)
 /sys/class/backlight/backlight/brightness (slider) ────────┤                                        /sys/class/leds/epd-backlight/brightness (frontlight)
 sys.a6l.dualux.req "<seq> eink|lcd|toggle|clear" ◄── app ───┘                                        uinput "a6l-dualux-keys": WAKEUP / SLEEP / POWER
 persist.sys.a6l.dualux.* / persist.sys.a6l.eink.{refresh,clear_every,contrast} ◄── app (tiles + settings)      vendor.dualux.state = lcd|eink|eink-asleep, vendor.dualux.lcd_blank
```
- **"E-ink mode" = Android's display stays ON, the LCD is only dark.** The mirror captures the LCD CRTC's planes, so the
  CRTC must keep scanning; turning the LCD *off* through Android would stop the picture. `bl_power = 4` makes the
  backlight core report brightness 0 to qcom-wled (the panel keeps scanning at ~panel logic power only). The composer
  keeps writing `brightness`; the core stores it without applying it — the daemon reads it back as "the slider".
- **Brightness → frontlight.** drm_hwcomposer (this tree) drives `/sys/class/backlight/backlight` itself
  (`SysfsBacklightController`, WLED max 4095, `scale` ≠ linear → it writes `max × HLG_OETF(b)`). The daemon inverts the
  HLG curve (exactly the composer's constants) to get Android's linear brightness `b`, then frontlight =
  `round(255 × b^gamma × max_pct/100)`, at least `fl_min` (1) when `b > 0`; 0 when the LCD is active, Android sleeps,
  or the frontlight is disabled. Auto-brightness and screen dimming are therefore followed too.
- **Why the composer can turn the LCD on at wake-up.** When Android sleeps the composer writes `bl_power = 4` and
  forgets; at wake-up it writes `bl_power = 0`. In e-ink mode the daemon re-blanks within ≤ 100 ms (poll), i.e. the LCD
  may flash briefly. **Optional composer patch 0002** (`switcher/patches/external/drm_hwcomposer/`, 25 lines): while
  `vendor.dualux.lcd_blank=1` the composer holds `bl_power = 4` itself and still stores the requested brightness → no
  flash. Applies cleanly next to 0001; clang syntax check of the patched file: 0 errors/warnings.
- **Power key.** Only the `pm8941_pwrkey` device carries KEY_POWER (volume-down is `pm8941_resin`), so grabbing it
  never takes other keys away. Grabbed only while e-ink + awake; the grab state is latched at key-down. A held press
  (≥ `power_long_ms` 450) is re-injected as KEY_POWER down (…up at release) from `a6l-dualux-keys`, so Android's
  power menu appears ~0.45 s later than usual. Double-press-power (camera gesture) is not available while on the e-ink.
- **Front touch** is grabbed (EVIOCGRAB, events dropped) in e-ink mode; the rear touch is the mirror's job (always
  grabbed, forwarded through its uinput touchscreen only while mirroring — unchanged).
- **Awake detection**: `dpms` of the DRM connector with the 1080x2340 mode (atomic commits keep `connector->dpms` in
  step with CRTC ACTIVE); fallback `vendor.eink.state != mirror-paused`.
- **Refresh modes** (`persist.sys.a6l.eink.refresh`, applied live by the mirror via `pol_apply_refresh_mode()`):
  | UI | property | policy (eink_logic) | a6l_epdd waveforms used |
  |---|---|---|---|
  | Auto (default) | auto | GC16 when still, A2 bursts while moving, one clean update on settle | 2 quality, 8 fastest |
  | Quality | quality | GC16 only, once still (reading path with full_frac 0) | 2 |
  | Reading | partial | REGAL partial, GC16 on page turns (> 60 % tiles) + every 8 partials | 3 (+2) |
  | Fast | fast | like auto, bursts in DU-like "fast" | 1 (+2) |
  | Fastest | fastest | like auto, A2, quiet 150 ms / settle 600 ms | 8 (+2) |
  "auto" in a6l_epdd's own mode list (0) is not used: the mirror picks per update. **Anti-ghosting**: on-demand clear
  (tile, settings, e-ink key hold/double), periodic full clear every N clean updates (`persist.sys.a6l.eink.clear_every`,
  live; default 10 from the rc, 0 = never; reading mode clears every 2N GC16s) — stock-like.
- **Contrast** (`persist.sys.a6l.eink.contrast` 0..100, settings slider "Text contrast boost"): the mirror stretches
  grey levels between a black point and a white point (100: 0..60 → black, 195..255 → white) before the e-ink
  quantisation — the software equivalent of stock's "high contrast text" (fb1 `epd_contrast`/thresholds, which our
  kernel does not have). A change forces one redraw. Dithering: not done (the TCON library already maps to 16 greys).

## 6. Changes to eink3's mirror (why and what)
- `persist.sys.a6l.eink.refresh` (auto|quality|partial|fast|fastest) read every 0.5 s and applied to the live policy

- Host regression: eink_logic 50/50; NO_DRM host build OK. The DRM build of the mirror and eink3's full

## 9. Risks and open questions
- **LCD not really off**: in e-ink mode the LCD panel keeps scanning (backlight off only), costing panel + DSI0 power
  (tens of mW). Turning the panel off needs a DCS "display off" hook in the FT8719 panel driver (sysfs), or a
  capture source that does not depend on the LCD CRTC (virtual display — crosses Treble, see eink3 §2).
- **LCD flash at wake-up** without composer patch 0002 (≤ 100 ms).
- **Power key**: long press re-injected 0.45 s late; camera double-press gesture not available on the e-ink; a
  press in the ≤ 100 ms after Android fell asleep may be swallowed (next press works).
- **Frontlight path unproven** on mainline (DTEST routing through `qcom,dtest`, spmi-gpio `dtest2` function mapping on
  PM660L LV/MV GPIOs). The LED driver behind GPIO6 is unknown (no enable GPIO/regulator in the stock DT → probably
  powered from VPH and switched only by the PWM).
- **uinput KEY_POWER/SLEEP/WAKEUP** from a virtual device: assumed accepted by PhoneWindowManager (idc marks the
  device internal). D6/D7 check it.
- **SELinux**: written from reading; monolithic checkpolicy passes, but the split build (`m selinux_policy`, treble
  tests) was not run; genfs paths unverified.
- **Stock double-press → clear** mapping is an inference (§2).
- **Dither, per-app refresh modes (stock "clear/smooth" app lists), Hall cover handling, `EPD_READING_WAKE`
  key 555** — not done.

## 1. SMS ACK "qmi-error ERR_84" — meaning and fix
- **84 = 0x54 = `QMI_ERR_ACK_NOT_SENT`** (Gobi API 2013 `QMIEnum.h` eQMI_ERR_ACK_NOT_SENT = 84; libqmi
  `QMI_PROTOCOL_ERROR_ACK_NOT_SENT`). It is the WMS Send Ack (0x0037) answer when the modem could not deliver the RP-ACK
  to the network. The response then carries **TLV 0x10 "Failure Cause"**: 0 no network response, 1 network released the
  link, 2 not sent. Our CLI never printed that TLV, so the exact cause of today's ERR_84 is unknown (no log file was kept;
  the laptop `v75/logs` has only ril-r1..r4 from 24 Sep, where the acks succeeded).
- Our request layout was already identical to ModemManager's (`mm-broadband-modem-qmi.c`: TLV 0x01 {txn u32, protocol
  1 = WCDMA for GW formats, success 1}); MM logs this error at debug level and moves on. Likely causes, in order: (a) the
  link was already released / the network had given up (ack arrived too late or the SMSC retransmitted), (b) the message
  came with ack indicator DO_NOT_SEND or had already been acked (a second process listening, or a stored message),
  (c) SMS over IMS without the "SMS on IMS" TLV. The stock modem IDL (vendor `libqmiservices.so`, decoded below) confirms
  Send Ack TLVs 0x01 (struct), 0x10, 0x11 (3GPP failure struct), 0x12 (u8 SMS on IMS).
- **Fix (lib + HAL + CLI):** `EventReport::needsAck()` (transfer route AND ack indicator 0) is the only condition to ack;
  stored messages/indicator 1 are never acked; the protocol comes from the format (`messageProtocolFor`, CDMA → 0);
  TLV 0x16 of the event report (SMS on IMS) is echoed in the ack TLV 0x12; the failure cause is returned and logged
  (`ackFailureCauseName`). The HAL keeps a FIFO of `{txn, needed, options}` and treats ACK_NOT_SENT as non-fatal (the SMSC
  retransmits; Android already stored the message). `errorName(84)` now prints `ACK_NOT_SENT`.
- CLI for the A/B test: `A6L_QMI_SMS_MT txn= ack_ind= fmt= ims=` before the ack, `A6L_QMI_SMS_ACK <result> txn proto
  cause=<name> after_ms=`; `A6L_SMS_ROUTE=ack` sets routes TRANSFER_AND_ACK (the modem acks itself — if ERR_84 disappears
  and the sender sees one delivery, keep transfer-only + our ack but look at timing); `A6L_SMS_NO_ACK=1`,
  `A6L_SMS_ACK_DELAY_MS`.
- **Delivery reports:** routes already transfer status reports (TLV 0x10 = 1); `isStatusReport()` → `newSmsStatusReport`.
  The parser now returns TP-MR and TP-ST (`srMessageRef`, `srStatus`), the CLI prints `A6L_QMI_SMS_STATUS_REPORT mr= st=`.
- **CLI sms-send:** UTF-8 → GSM 7-bit default alphabet incl. accents é è à ù and the extension table (€ [ ] { } ^ ~ | \)
  when every character maps, else UCS2 (UTF-16BE, surrogate pairs kept together); >160 septets / >70 units →
  concatenated parts (UDH 05 00 03 ref total seq, 153 septets / 67 units per part, an escape pair is never split),
  `A6L_SMS_SRR=1` = delivery report requested (waits for the reports), `A6L_SMS_UCS2=1`. Decoder: UDH concat info,
  GSM7 extension table, UCS2 surrogates. (Android builds its own PDUs; this only matters for the CLI tests.)

## 2. Dual SIM (DSDS)
Stock: `persist.radio.multisim.config=dsds`. The modem reports card 1 = present-error (empty slot).
**QMI facts (read from the stock IDL tables, not guessed):** I decoded `firmware/extracted/vendor/lib64/libqmiservices.so`
(APS2 packed relocations applied; service object → message table → encoded TLV stream: `81 04 00` = last TLV 0x01,
1-byte enum, offset 0; `44 10 04 04` = optional TLV 0x10 …). Message ids match the Gobi API 2013 list:

| message | TLVs (stock IDL) | value used |
|---|---|---|
| NAS 0x0045 Bind Subscription | 0x01 enum8 | 1 (secondary) |
| WMS 0x004C Bind Subscription | 0x01 enum8 | 1 |
| VOICE 0x0044 Bind Subscription | 0x01 enum8 | 1 |
| DMS 0x0054 Bind Subscription | 0x01 u32 | 2 (1-based) |
| WDS 0x00AF Bind Subscription | 0x01 u32 (libqmi QmiSubscriptionType) | 2 |
| UIM 0x0038 Change Provisioning Session | 0x01 {session u8, activate u8}, 0x10 {slot u8, aid len-prefixed} | session 2 = secondary GW, slot 2 |
| NAS 0x004B Set Dual Standby Pref | 0x10–0x13 enum8, 0x14 u64, 0x15 enum8 | **0x12 = default data subs (position-based, unconfirmed)** |
| NAS 0x005C Get Dual Standby Pref (resp) | 0x10–0x14 enum8, 0x15 u64 | read back after every DDS change |

**HAL design** (`device/hisense/a6l/radio`): `ModemCore::get(slot)` — one core per logical slot, each with its own QRTR
socket (= its own QMI clients). **Slot 1 is the v1 core unchanged** (default primary binding, nothing new sent: the host
test checks that only one NAS bind appears and it comes from slot 2). Slot 2 binds NAS/WMS/DMS/VOICE to subscription 1
before registering indications, uses the secondary GW session / card-slot-2 session for SIM I/O, its own
`DataCallManager` (WDS bound to sub 2, mux 5–8, `rmnet_data4..7`; the IPA port's DPM/WDA setup stays with slot 1 and is
triggered through `prepareFormat()`), and provisions a detected USIM in card 2 (UIM change provisioning) unless
`persist.vendor.a6l.ril.auto_provision=false`. If binding fails (single-standby firmware) slot 2 is **unusable, not
aliased**: no service, no card I/O beyond card status, dial/SMS/data refused with RADIO_NOT_AVAILABLE. Card→slot mapping
(`multisim::viewFor`): the card a subscription is provisioned from, else card N, else the card the other one does not
use (SIM only in physical slot 2 → logical slot 1 uses card 1). IRadioConfig: `getSimSlotsStatus` = one entry per card
with the logical mapping, `getNumOfLiveModems`/`getPhoneCapability` = 2 logical modems, 1 active data;
`setPreferredDataModem` → NAS 0x004B TLV 0x12 + readback; IMEI type SECONDARY on slot 2 (DMS bound → second IMEI).
Slot count = `ro.vendor.a6l.ril.slots` (1|2), else `persist.radio.multisim.config` (dsds/dsda → 2); `radio.mk` now sets
`ro.vendor.a6l.ril.slots=2`, `persist.radio.multisim.config=dsds`, `ro.telephony.default_network=9,9`; rc and VINTF
declare slot2. Voice-path property is aggregated over both slots.
**Single SIM stays the v1 behaviour** with one SIM inserted (slot 2 shows "no SIM"); to force a one-phone framework set
`ro.vendor.a6l.ril.slots=1` + `persist.radio.multisim.config=ssss`.

## 3. Radio power, airplane mode, SSR
- One DMS operating mode for both subscriptions (`multisim::PowerVote`): ONLINE while any slot voted on, LOW_POWER when
  all voted off (airplane). A slot turned off alone reports OFF while the modem stays online for the other slot. Votes
  reset on modem loss. Single SIM: identical to v1 (slot 1's vote alone decides).
- SSR: unchanged v1 mechanism per core (DMS/UIM/NAS DEL_SERVER → RADIO_UNAVAILABLE, caches/acks cleared, data calls
  dropped, re-init on NEW_SERVER incl. binding and indication registration). **Host fault injection** (`tests/
  modemcore_tests.cc`): two full SSR cycles (all 7 services removed and re-announced on new ports) → both slots lost then
  ready again, NAS indications re-registered; after the 1st SSR the binds fail (slot 2 unusable, no SIM-1 traffic), after
  the 2nd they work and the card-2 USIM is provisioned; plus `testSsrClient` (3 rounds, NoService in <500 ms, recovery).
- No-SIM boot (both cards absent) and PIN-locked boot (app state PIN, PIN1 enabled-not-verified) through UIM card-status
  indications: tested; airplane on/off both orders: tested. Not testable offline: the framework's behaviour.

## 6. Risks / unknowns
- NAS 0x004B TLV 0x12 = default data subscription is inferred from the field order (TLV ids and sizes are exact from the
  IDL); a wrong guess makes `setPreferredDataModem` change another preference. Step 1 reads 0x005C first; the HAL reads it
  back after each change. With one SIM Android never calls it with modemId 1.
- Subscription enum values (0/1 for NAS/WMS/VOICE, 1/2 for DMS/WDS) follow Qualcomm/libqmi conventions, not the IDL
  (enums are not in the tables). Step 1 (`SUB2_BIND`, second IMEI) verifies them read-only.
- Whether this MPSS.AT.3.1 build auto-provisions slot 2 (then our change-provisioning is never sent), SIM hot-swap on
  slot 2, DSDS paging/tune-away, and the framework's handling of 2 phones are untested. VINTF declares slot2: with
  `ro.vendor.a6l.ril.slots=1` the slot2 instances are declared but not registered (acceptable, not VTS-clean).
- `persist.radio.multisim.config` may be unreadable for `hal_radio_default` under enforcing SELinux; the HAL relies on
  `ro.vendor.a6l.ril.slots` (vendor_a6l_ril_prop) for that reason.
- ERR_84's real cause needs step 2's `cause=` value.

## 2. Key facts from the sources
- **qcom_smbx (7.2)**: probe writes the SMB2 init sequence (charging enabled, HVDCP off, watchdog off, AICL on,
  pre-charge 0.5 A), float from `voltage-max-design` (4.4 V) and **FCC 1.95 A hard-coded**. The USB **input** limit is set
  per charger type after plug-in: SDP 500 mA, CDP 1.5 A, **DCP = `constant-charge-current-max-microamp`** of the battery
  node. Writable: `current_max` (input limit) and `status` (0 = USB input suspend, 1 = resume). No temperature logic.
  Battery current ≈ ICL × Vbus/Vbat × η → ICL 0.8 A gives ≤ ~1.0 A into the battery; the laptop port (SDP) gives 0.5 A.
- **pmi8998_fg**: `qcom-battery` psy: status (from the charger when present, else sign of current: **current_now < 0 =
  charging**), capacity, current_now, voltage_now, temp (0.1 °C), and `temp_min/temp_alert_min/temp_alert_max/temp_max` =
  the FG hardware JEITA thresholds actually programmed (BATT_INFO_JEITA_* registers, 0.5 °C steps, -30 °C base).
- **Stock policy** (stock-00.dts `qcom,qpnp-smb2` + `qcom,fg-gen3` + battery profile): FCC max 2.4 A, FV 4.40 V, ICL 2.0 A,
  JEITA **0 / 10 / 44 / 55 °C**, hysteresis 2 °C, warm FCC 0.9 A + FV −0.3 V, cool FCC 0.85 A, thermal-mitigation ICL steps
  2.4/0.8/0.5/0.3/1.0 A, step charging on, 3800 mAh profile `4101451_hisense_hlte730t_3800mah…`.
- **Mainline CPR (CPR kernel `/home/a6l/kernel/a6l-7.2-cpr`)**: CPR3 built in (`CONFIG_QCOM_CPR3=y`), fuses through
  `nvmem_cell_read_variable_le_u32` (only the 40 cells), debugfs `qcom_cpr3/threadN`: `corner i - uV=[min uV max] … freq=`.
  **Its kernel.release is `7.2.3-a6l-probe` (no `+`) while every V74/V75 module says `7.2.3-a6l-probe+`** → modules in the
  recovery ramdisk (sdhci-msm) would be refused. The F2 package must rebuild the CPR Image with `LOCALVERSION=+` (or rebuild
  its modules against `out-a6l-cpr`).

## 3. Attended procedure — CPR (Pierre only for F2+; S1 and F1b are read-only)
**S1 (read-only, rooted stock, recommended first):** reboot stock, then within 2 minutes of boot, from the laptop in `~/A6L-usb-20260915/v75/power`:
```
adb -s 1e529013 push stock/a6l-stock-cpr-read.sh /data/local/tmp/ && \

```
Expect `A6L_STOCK DONE`, `[stock] speed_bin=N` (0/1/3/4), 10 `init fuses` values, every corner `ok` against the stock table
and **A6L_CPR_OPENLOOP_SANE**. `WARN no 'fused … open-loop' lines` = the log rotated → reboot stock and run again sooner.
Any `DIFF` = the mainline tables (REF/OADJ/fmax) disagree with the stock kernel → stop, send stock-cpr.txt to the offline agents.
(CORNERS=1 writes only the downstream debugfs display selector `corner/index`; drop it for a strictly read-only run.)

**F1b (optional, V74 recovery, read-only but touches qfprom):** laptop first `adb -s HLTE730T-PROBE shell dmesg -w > klog-f1b.txt &`, then
```

```

python3 a6l_cpr_openloop.py --stock-log stock-cpr.txt --mainline cpr-check.txt

Expect `thread 0/1 initialized with N OPPs`, cpufreq policy0/policy4, every mainline corner `ok` and
**A6L_CPR_MAINLINE_MATCH**; any `DIFF` → reboot to the V74 slot, stop.
**F3a:** `MODE=cpr-step HOLD=5 TMAX=70000` (userspace governor, each OPP with a busy loop, abort ≥ 70 °C). Only after

## 4. Attended procedure — charger C2 (V74 recovery; chg-on is CURRENT-AFFECTING, Pierre present, phone on the desk)
```
cd ~/A6L-usb-20260915/v75/power && sha256sum -c SHA256SUMS && cd .. && adb -s HLTE730T-PROBE push power /tmp/power
P='export PATH=/tmp/bin:$PATH; export D=/tmp/power'
adb -s HLTE730T-PROBE shell "$P MODE=chg-ro; sh /tmp/power/run-power.sh" 2>&1 | grep -v linker          # read-only
adb -s HLTE730T-PROBE shell "$P MODE=chg-on ICL=500000; sh /tmp/power/run-power.sh" 2>&1 | grep -v linker # starts charging + 5 min monitor
adb -s HLTE730T-PROBE shell "$P MODE=chg-status N=12; sh /tmp/power/run-power.sh"                          # every ~1 min
adb -s HLTE730T-PROBE shell "$P MODE=chg-off; sh /tmp/power/run-power.sh"                                  # stop any time
```
- chg-ro: expect `A6L_CHG_OVL applied`, 3 × `… parent=…spmi…` (or `already under`), `qcom-battery` uevent, FG JEITA line
  (expect ≈ 0/100/440/550 if the bootloader programmed stock values — record it), rradc usbin/die-temp values, 3 RO snapshots.
  Nothing is written to the charger (qcom_smbx not loaded).
- chg-on (refuses at battery ≥ 35 °C, ICL > 0.8 A without FORCE=1, ever > 1.0 A): expect `ICL set: 500000`, then the monitor
  every 10 s for 300 s: `bat[status=Charging … uA=<negative> temp=…]`, `chg[online=1 status=Charging health=Good icl=500000]`.
  Laptop port = SDP → ~0.5 A in. With a wall charger (DCP) run `ICL=800000`: charge current ≤ ~1.0 A.
  **Auto-abort (USB input suspend)**: battery ≥ 40.0 °C, charge current beyond 1.05 A twice, health ≠ Good, Vbat > 4.42 V.
  At the end: `MON_DONE`, ICL back to 500 mA, charging continues (END=suspend to stop instead).
- Pierre: during the monitor unplug/replug once → `online=0` then back to Charging (clean stop/start). Watch the phone
  temperature by hand; battery temperature rise < 5 °C expected.
- Pass → a6l-charger-v75 (fixed) can be enabled in the ROM with the guard (`persist.vendor.a6l.charger=1`).

## 7. Risks / unknowns (honest)
- Nothing here has run on the phone. The stock script was checked for syntax only (strings verified in the stock ELF; the
  exact debugfs file set of the stock kernel is assumed from msm-4.4).
- The fused open-loop recovery assumes the stock prints are before the fuse adjustments (msm-4.4 order); the per-corner
  CORNERS=1 table is the ground truth and is cross-checked.
- The FG may report temp/current before its SRAM is ready (first reads 0/NA); the monitor treats NA as "no data" (no abort).
- a6l_chg_ovl re-parenting has the same design as the proven a6l_fl_ovl fix but for 3 devices on pmic@0; if a device still
  says "failed to locate the regmap", rmmod the drivers + ovl and report.
- qcom_smbx keeps FCC 1.95 A: the ≤ 1 A bound relies on the input limit + the monitor's abort; a DCP at ICL 0.8 A was not measured.
- CPR: the F2a package (CPR Image with matching vermagic) is not built; OSM sequencer writes under TZ on SDM660 remain untested.

# VoLTE on the A6L: research and staged plan (25 Sep 2026, `volte` agent)

Status: **research and plan, plus one read-only probe tool (built, never run on the phone).** VoLTE is not needed for
the first image. Orange France plans to shut down 3G in 2028. In Pierre's area 2G is being shut down between
22 Sep and 20 Oct 2026, which does not matter here because CSFB already goes to UMTS (seen today: LTE → CSFB → UMTS).
After 2028, the phone has **no voice at all** without VoLTE, and **no emergency calls** without IMS emergency.

## TL;DR
1. **On stock SDM660, the IMS stack runs on the modem.** SIP, RTP and the vocoder for VoLTE voice are all inside
   MPSS. The AP side is small. `imsdatadaemon` is the **server** of the QMI service **IMSDCM (770 = 0x302)**: the modem
   asks it to bring up the IMS PDN, and it answers with the IP address. `imsqmidaemon` is a client of IMSS (18) and reads
   settings. `ims_rtp_daemon` is the server of IMSRTP (40) and handles video RTP only. qcrild talks IMSA (33) and IMSS (18).
   ims.apk uses the `vendor.qti.hardware.radio.ims` HIDL.
2. **The modem already carries a full Orange France IMS configuration.** The MCFG_SW
   `EU/ORANGE/COMMERCI/FRANCE` has IMS_enable=1, voice_domain_pref=3 (IMS PS voice preferred), SMS over IMS preferred,
   user agent "Orange VOLTE Qualcomm", the `ims` APN, SRVCC, LTE emergency redial and a PLMN list of 208-01/208-02.
3. **The modem does not publish IMSA/IMSS/IMSP today.** They were missing from the 25 Sep lookup. Our guesses are:
   the active SW MBN is not Orange (ROW, where IMS is disabled), or the capture was taken before online, or the modem
   waits for the AP-side IMSDCM (770). **Step 0 settles this with a read-only probe (built today).**
4. **The recommended path (B) is modem-centric IMS, transparent to Android.**
   - What we build: a small IMSDCM server (IMS PDN on request, over our existing WDS code), an IMSA reader, dialling
     through the existing QMI VOICE path (the modem chooses the IMS domain), and a VoLTE CVD session in q6voice.
   - Android side: no ImsService. The HAL reports voice as in service on LTE.
   - Effort: about **2–3 weeks**.
   - It does not depend on IPA data. It reuses the call audio already proven (CVD=0).
5. **The fallback (A) is an AP-side ImsService**, based on ShapeShifter499's `joan-volte-lineage`: LG V30 msm8998,
   LineageOS 22, working VoLTE on T-Mobile US, Apache-2.0, and it already has an **Orange France (ORG.FR)** profile.
   It needs IPA data, xfrm/IPsec, USIM/ISIM AKA through the HAL, and AP audio capture. Effort is about 3–5 weeks
   **after IPA works**.
6. **The biggest non-technical risk: Orange may refuse IMS for a device model it does not know** (eligibility
   depends on the device's "fiche technique"). **Free check first (step −1):** does the *stock* A6L get VoLTE on
   Pierre's Orange SIM?

## 1. How VoLTE works on stock SDM660 (from the stock vendor partition)
| Component (stock) | Role | Evidence |
|---|---|---|
| Modem MPSS (QIMF/QIPCALL in MPSS.AT.3.1) | SIP UA, IMS registration, IPsec, RTP, AMR/AMR-WB/EVS vocoder (the audio goes to the ADSP through the CVD voice session), SRVCC, IMS emergency, SMS over IMS, Ut/XCAP | the MCFG files `qp_ims_*`, `IMSVoiceDynamicConfig`, `ims_sip_config`, `qp_ims_ut_config_item`, `IMSEmerDynamicConfig` |
| `imsdatadaemon` (AP) | **QCSI server of IMSDCM (770)**: handles `QMI_IMS_DCM_PDP_ACTIVATE` from the modem, brings up the IMS/emergency PDN with `dsi_netctrl`/CNE, and sends back `PDP_ACTIVATE_IND` with the addresses; also Wi-Fi quality/handover measurement | links libqmi_csi + libdsi_netctrl; strings `DATAD#>>#QCSI … QMI_IMS_DCM_PDP_ACTIVATE_IND_V01`; `imsdcm_qmi_idl_service_object_v01` (id 0x302) |
| `imsqmidaemon` (AP) | QMI client of IMSS (18) (Get* config), NAS, DSD, WDS and DMS; starts imsdatadaemon via `vendor.ims.QMI_DAEMON_STATUS=1` | strings `QMI_IMS_SETTINGS_GET_*`; init.target.rc |
| `ims_rtp_daemon` (AP) | QCSI server of IMSRTP (40): **video** RTP (H.264/ION, AV sync). Voice RTP stays on the modem | strings `QC_IMS_QMI_VIDEO_*` |
| qcrild (`libril-qc-hal-qmi.so`) | IMSA (33) client: registration and service status, PDP status, VoWiFi; IMSS; the MBN module (`/data/vendor/modem_config/mcfg_sw`, PDC load/select/activate, auto-select by IIN); props `persist.vendor.radio.sw_mbn_volte`, `vdp_on_ims_cap` | strings |
| ims.apk + `vendor.qti.hardware.radio.ims@1.0-1.4` | Android ImsService ↔ qcrild IImsRadio | vendor/lib64 |

**The AP must do these things for the modem's IMS to register:** (a) have the right SW MBN active; (b) answer the
IMSDCM PDP activation for the `ims` APN, which means a WDS call on the IMS profile. SIP and voice RTP then run on the
modem's IP stack, so IPA is not needed for them. This is inferred from the stock design and **not proven**.
(c) Nothing else is strictly needed for registration. Dialling uses QMI VOICE, and the audio uses the CVD voice
session (the VoLTE session in msm-4.4 is `"default volte voice"`, a different session from the CS `"default modem
voice"`). **Whether the modem brings up the IMS PDN by itself (the IoT-module style, as on the EG25-G in the PinePhone)
is unknown.** Step 0/1 will show it.

## 2. The stock modem configuration (MCFG)
The source is `firmware/extracted/peripheral-firmware-20260917-r3/modem/IMAGE/MODEM_PR/MCFG/CONFIGS/MCFG_SW/`, with 120
SW MBNs. `OEM_SW.TXT` names `common/row/commerci` as the OEM default. The Orange FR MBN is
`GENERIC/EU/ORANGE/COMMERCI/FRANCE/MCFG_SW.MBN`: 50 348 bytes, sha256 `336ac0f8…3c4c`, MCFG format 4,
108 items, carrier index 11. Its trailer says "France-Commercial-Orange" and lists PLMNs 208-01 and 208-02.
Items decoded with `tools/volte/mcfg.py` (a heuristic parser; the value starts after the 0x07 attribute byte):

| EFS item | Orange FR | ROW (OEM default) |
|---|---|---|
| `/nv/item_files/ims/IMS_enable` | **1** | 1, then **0** again later in the file (IMS probably off) |
| `ims_operation_mode` | 2 | 2 |
| `modem/mmode/voice_domain_pref` | **3** (IMS PS voice preferred, CS secondary) | 3 |
| `ue_usage_setting` | 0 (voice centric) | — |
| `sms_domain_pref` | 1 (SMS over IMS preferred) | 1 |
| `ims_user_agent` | "Orange VOLTE Qualcomm" | empty |
| also present | `qp_ims_reg_config_db`, `RegistrationConfiguration`, `SMSConfiguration`, `IMSVoice/Emer/RTP/Codec DynamicConfig`, `nas_srvcc_support=1`, `lte_nas_ignore_mt_csfb_during_volte_call=1`, `lte_emerg_redial`, `qp_ims_xcap_common_config` ("orange", Ut/XCAP), 4 `Data_Profiles` (orange / ims / …), ANDSF (APN `ims`, `vowifiorange`) | |

Bouygues and SFR also have VoLTE MBNs (IMS_enable=1, vdp=3), which helps if Pierre changes carrier.

**Can our QMI stack select it?** Yes. PDC (36) is published. The flow is `List Configs` → `Set Selected Config` (SW,
id) → `Activate Config` (this resets the modem), or `Load Config` first if the MBN is not in the modem EFS
(qcrild's MbnModule does this from `/data/vendor/modem_config/mcfg_sw`). libqmi documents all of them (the PDC service).
The modem EFS (modemst1/2) is encrypted, so the backups cannot tell which MBN is loaded or active: **the probe asks PDC.**
Selecting writes to the EFS. With rmtfs on RAM copies the change is lost on reboot, which is fine for a test. In the ROM,
with the real EFS, it persists: **Pierre's go is needed.**

**AOSP/Android 17:** an ImsService is an app bound through `config_ims_mmtel_package`, with `MmTelFeature`,
`ImsRegistrationImplBase` and `ImsConfigImplBase`. The tree has `frameworks/opt/net/ims` and `packages/modules/ImsMedia`
(AP RTP/codec). `android.hardware.radio.ims` (IRadioIms) is optional in the matrix. We do not declare it, and it is only
needed when the modem must be told about an AP-side IMS. **A custom ImsService on top of the modem IMS (option C) is
possible**: registration from IMSA, calls through QMI VOICE with call type VOICE_IP (0x02), and the rest mapped
through the HAL (a vendor AIDL or a private socket). It is what qcrild + ims.apk do. Effort is about 3–4 weeks. It is
only needed for the native VoLTE UI/toggle/HD icon.
In the Lineage tree, the Orange FR carrier config (`carrier_config_carrierid_32_Orange.xml`, 15 lines) has **no
VoLTE keys**, so `carrier_volte_available_bool` would stay false → options A and C need a CarrierConfig overlay. Option B
does not need one, because Android never sees IMS.

## 5. Step 0 tool (built today; never run on the phone)
- Source: `tools/volte/volte-probe.c` (single C file, raw AF_QIPCRTR, no libs), `tools/volte/test-volte-probe.c`
  (encoder/decoder unit test), `tools/volte/build-volte-probe.sh` (relay: host ASan/UBSan test + NDK r27c static
  aarch64). Checked: clang/gcc `-Wall -Wextra -Werror`, unit test PASS (container + WSL).
- Binary: `firmware/extracted/volte-20260925/volte-probe`, sha256
  `1b416b78a35a883cc6158ac8d1e14fb3ba6686fc0b6ce373f006963389da020c`, staged at laptop `~/A6L-usb-20260915/v75/volte/`
  (`sha256sum -c` OK).
- Commands (Pierre, laptop `~/A6L-usb-20260915`, **after radio2 KEEP**, same boot; step R3 `online` before the
  second run):
  ```
  adb -s HLTE730T-PROBE push v75/volte /tmp/volte && adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; chmod 755 /tmp/volte/volte-probe; /tmp/volte/volte-probe all' 2>&1 | grep -v linker | tee v75/logs/volte-probe-$(date +%H%M).txt
  adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; /tmp/volte/volte-probe imsa-watch 120' 2>&1 | grep -v linker | tee v75/logs/volte-imsa-$(date +%H%M).txt
  ```
- Messages sent (all reads): QRTR lookup; PDC Register (reporting on, this client only) / Get Selected Config
  (HW+SW) / List Configs (SW) / Get Config Info; NAS Get System Info; WDS Get Profile List/Settings; DSD Get System
  Status; IMSA Get Registration/Services Status; IMSS Get Services Enabled; IMSP Get Enabler State.
  `imsa-watch` = IMSA Register Indications + printing. Output `A6L_VOLTE_*`. Unknown TLVs are hex-dumped.
- Expected output, and what each line means:
  - `A6L_VOLTE_PDC_ACTIVE type=SW id=…` + `PDC_INFO … desc='France-Commercial-Orange'` → MBN OK;
    `desc='ROW_Commercial'` → step 0b.
  - `A6L_VOLTE_IMS_SVC 33 IMSA(ims-application) PRESENT` → IMS task is up → `IMSA_REG_STATUS` TLV 0x12
    (0 not registered, 1 registering, 2 registered, per libqmi `QmiImsaImsRegistrationStatus`) + TLV 0x11 error code.
  - `A6L_VOLTE_NAS_SYSINFO ims_voice_support=1` → Orange's LTE cell advertises IMS voice.
  - `A6L_VOLTE_WDS_PROFILE … name=…` / `apn='ims'` → the IMS profile index for step 1.
- Not verified offline: nothing ran against a modem. Possible first-contact issues: PDC answers only by indication
  (handled, 5 s wait) or needs a different TLV layout (then the result code is printed); WDS profile type TLV; IMSA
  may need `Bind` on DSDS builds (single SIM here).

## 6. Risks / unknowns (honest list)
1. **Orange eligibility of an unknown TAC.** VoLTE is granted for "compatible" phones (fiche technique). Step −1 tests it on stock.
2. Why IMSA/IMSS are absent (MBN, timing, or a wait for IMSDCM): step 0.
3. The IMSDCM handshake beyond PDP activate is unknown (app-state/handover messages). imsd RE doc (Codeberg, not reachable from here).
4. The CVD VoLTE session name/version on this ADSP; the CVD 2.3 path already failed (0x1133d); legacy works for CS.
5. PDC writes are persistent on the real EFS (ROM). Keep a PDC `List/Get Selected` log before any change.
6. SRVCC to 3G and IMS emergency: modem-side in B, never testable without a real emergency (never dial 112 for tests).
7. Android "transparent" mode: some framework paths (e.g. `isImsRegistered()`, WFC, RTT) stay off, which is acceptable.

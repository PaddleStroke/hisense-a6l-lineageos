# V15: bind the driver before connecting USB

The last V14 frame shows RAM heartbeats through90seconds, `USB_BIND_BEGIN`, a
successful gadget driver probe, and `USB_BIND_END success=1` at95.036197 kernel
seconds. The host saw no diagnostic USB device. Serial had not been opened.
This localizes the failure after the bind call returns; it does not prove a
panic or identify an exact interrupt, DMA or PHY fault.

The UDC core normally starts the driver and immediately calls its USB connect
path as part of binding. V15 adds a temporary opt-in gate:

- Enabled only with `a6l_manual_usb=1` and machine `hisense,hlte730t`.
- The driver binds and registers its interrupt normally.
- Requests to connect are held without calling the controller pullup operation.
- A later explicit `soft_connect` request releases the gate and reports the
  actual connect result; it does not redundantly start an already-started driver.
- Without both activation conditions, the existing behavior is retained.

The RAM timeline is configuration60seconds, bind90seconds, connect120seconds,
serial150seconds. The collector waits for a serial-write result and heartbeat
at152seconds or later. A lack of enumeration while the gate is held is expected.

If the bound/disconnected stage remains alive and the failure follows release,
the next investigation is the controller/PHY connection and first USB events.
If it fails while disconnected, focus on driver startup/IRQ registration instead.
These are hypotheses to distinguish, not established causes.

The kernel configuration is byte-identical to V14. No DT wiring, regulator
constraints or load addresses are changed. The new relocated kernel hash is
`a499602699e44c79ff308d9d3f39e362c53efe548deb4b19946d6d2c72b957de`.
The patch is saved in `device/hisense/a6l/kernel/a6l-manual-usb-connect.patch`.

Offline QEMU validates CPU boot, RAM userspace and display logging, but cannot
exercise the Qualcomm controller. Captured-bootloader tests check image handling;
the physical trial is still required to validate the gate on the A6L.

The V15 installer must accept only exact stock or V14 as its predecessor, with
the established exact BCB allowlist and complete readbacks. Keep the diagnostic
installed between successful returns to normal Android, as the user requested.

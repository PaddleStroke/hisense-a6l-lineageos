## 1. Haptics → the motor is NOT on the PM660 haptics block (root cause found)
- The stock kernel (`stock-symbolized.elf`, `stock.kallsyms`) contains **no qpnp-haptic driver at all** (no symbol, no
  string, no `qcom,qpnp-haptic` match string), although the stock DT has `qcom,haptic@c000`. The stock vibrator is
  **`timed-gpio`** (`stock-00.dts:14279`): `vib-gpio = <&tlmm 79 0>`, pinctrl `vib_en_pin` = gpio79, function gpio,
  drive 2, output-low. Disassembly of `timed_gpio_probe`/`gpio_enable`: `gpiod_direction_output_raw(79, 0)` at probe,
  raw **1 while on** (active_low = 0), hrtimer off after min(ms, 15000).
- So "PLAY 0x70 stays 0" was a red herring (STATUS busy = the block ran into an unconnected output). No PM660 register
  sequence can move this motor. `a6l_pm660_haptics` is retired.
- New driver `device/hisense/a6l/kernel/a6l-gpio-vibrator/a6l_gpio_vib.c` (compatible `hisense,a6l-gpio-vibrator`,
  `enable-gpios`): input FF device **`a6l_gpio_vibrator`** (memless, FF_CONSTANT + FF_PERIODIC + FF_RUMBLE + gain) —
  what VibratorOL's InputFFDevice looks for (FF_CONSTANT||FF_PERIODIC) — plus debugfs `a6l_gpio_vib/pulse` (1..2000 ms)
  and `on_count`; motor forced off on close/suspend/remove. Any non-zero level = on (no amplitude control, like stock).
- DT: `kernel/a6l-vibrator-v75.dtso` (TLMM gpio79 pin state + `/a6l-vibrator` + `&pm660_haptics { status = "disabled" }`).
  V74 base: gpio79 is not reserved (`gpio-reserved-ranges = <8 4>`) and not used by any node. Merge onto V74 base: PASS.
- Test bundle **v75/rest3**: `a6l_gpio_vib.ko` `be478920…0b92`, `a6l_vib_ovl.ko` `20f80a23…bbb` (applies
  `a6l-vibrator-test.dtbo` = same without the pm660_haptics change), `a6l-vibrator-v75.dtbo` `9067bd49…`, `a6l_vib`,
  `run-rest3.sh` `4b82460a…`. vermagic `7.2.3-a6l-probe+`, 0 warnings, no module deps.

## 2. E-ink frontlight: "parent regmap unavailable" (root cause found)
- The V74 base DT is fine: `pmic@3` = `qcom,pm660l`,`qcom,spmi-pmic` with children `pwm` (LPG), `led-controller@d300`,
  `leds@d800` (the WLED that already drives the LCD backlight, so pmic@3 has a regmap).
- Cause: a **runtime** overlay flips `pm660l_lpg` to okay; `of_platform_notify()` creates the device with parent
  `of_find_device_by_node(pmic@3)`, which only searches the platform bus. pmic@3 is an SPMI device → parent NULL →
  `dev_get_regmap(parent)` NULL → -ENXIO. **Runtime-overlay artefact only**: in the ROM DT (merged at build time)
  qcom-spmi-pmic populates the node with the right parent — no DT change needed.
- Fix in `kernel/frontlight/ovl/a6l_fl_ovl.c`: after applying, find the SPMI pmic@3 device through an already populated
  sibling (WLED; `spmi_bus_type` is static in 7.2), `of_platform_device_destroy()` the orphan LPG device and
  `of_platform_device_create(np, NULL, pmic)`; logs `A6L_FL_OVL LPG … parent=… driver=…`. leds-pwm then binds by deferred probe.
- dtbo header regenerated with `xxd -i` + `__aligned(8)` (magic d00dfeed checked). `run-frontlight.sh` loads
  `led-class-multicolor.ko` first. Bundle **v75/dualux2**: `a6l_fl_ovl.ko` `5b295ac9…`, led-class-multicolor, leds-qcom-lpg,
  leds-pwm, `a6l-eink-frontlight-v75.dtbo` (= dualux build), `run-frontlight.sh` `cc003f10…`.

## 3. GNSS XTRA
- `xtra3grcej.bin` fetched in WSL from path1/2/3.xtracloud.net: 49802 B, `88b7b134…d922` (identical on all 3). Also a fresh
  `xtra3grc.bin` (32166 B). XTRA expires ~7 days: re-fetch with relay `misc2-06-xtra.sh` before a later test.
- **Message format is identical to stock**: `LocApiV02::setXtraData` in stock `vendor/lib64/libloc_api_v02.so` (disassembled):
  msg 0x35, struct totalSize u32 / totalParts u16 / partNum u16 / partData_len + 1024 B / formatType_valid=1, formatType=0,
  1024-byte parts, waits for ind 0x35 and checks partNum. Our TLVs 0x01 u32, 0x02 u16, 0x03 u16, 0x04 (u16 count + data),
  0x10 u32 match; new byte-exact host test.
- **The error codes were misread**: QMI 3 = `QMI_ERR_INTERNAL` (not MALFORMED = 1) and 94 = 0x5E = `QMI_ERR_NOT_SUPPORTED`. The
  modem parsed the message; it refused the content/state. The old code then dropped formatType (stock never does) → 94.
- Changes (`gnss/lib`): `qmiErrorName()`, `qmiErrorIsLayout()`; injection asks GET_PREDICTED_ORBITS_DATA_SOURCE first
  (uses the modem's max part size, logs servers/max file), keeps formatType, retries INTERNAL/ABORTED/NOT_READY/IN_USE twice
  after 3 s, drops formatType only on a layout error (1/0x11/0x13/0x30), always queries validity afterwards. Errors now
  read `request error 3 (QMI_ERR_INTERNAL) format_tlv=yes part_size=…`.
- `test/gnss3-test.sh`: picks the file named by the modem's own server URL (query), then xtra3grcej → xtra3grc → xtra2;
  new step `inject-only` (no fix attempt, fine indoors). HAL: `psds/gps_debug.conf` LONGTERM_PSDS_SERVER_1..3 = path1/2/3
  `xtra3grcej.bin` (the framework downloads what the HAL requests; HAL code gets the lib fixes).
- Host tests **125/125** ASan/UBSan (WSL + Cowork VM); TSan 3/3 clean runs (one earlier run hit the pre-existing timing check
  `host_test.cpp:263 eng.sessionRunning()` under load — not a race report). Replay FIX, NDK static build, HAL syntax rc 0.
  Bundle **v75/gnss3**: `a6l_gnss_test` `6d75cd7e…`, `gnss3-test.sh` `9f58b727…`, xtra3grcej/xtra3grc/xtra2.
- Still unknown: why the modem said INTERNAL. Candidates: wrong file (it asked for grcej), time not yet accepted, engine
  busy. The new run shows which.

## 4. Media recording (capture 0 bytes)
- Facts: `tinycap` always exits 0 (even on open/read failure) and the 25 Sep run printed only `A6L_*` lines, so its message
  was lost; no q6asm/q6adm error in klog → ASM/ADM opens succeeded or the failure was in ASoC/AFE (not grepped).
- Divergence found: upstream `q6adm_device_open()` never sets **`endpoint_id_2`** (kzalloc → 0 = AFE port 0x0000), CAF
  msm-4.4 sends **0xFFFF** (or the EC-ref RX port). On a LIVE_REC COPP that field is the voice-processor Tx reference
  input → suspect for "capture never produces data". Patch `kernel/audfix/a6l-q6adm-endpoint2-v75.patch` (applies to the
  tree, dry-run OK) → `q6adm.ko` `a370f555…` (0 warnings, same vermagic/deps/exports as audio4). The stock *binary* was not
  conclusively decoded for this field (adm_open builds the packet without a literal 0xffff store).
- New **MODE=capture** (capture only, nothing played) in `v75/audio5/run.sh` (`6916a0b6…`): dynamic debug for soc-pcm/q6*,
  variants A MM2 48k/2ch, B MM2 48k/1ch, C MM1 48k/2ch (TX route only, `mixer3/mm1-capture.txt`), D MM2 16k/1ch; prints the
  full tinycap output, `/proc/asound/.../status|hw_params`, ASoC DPCM `state` of MultiMedia1/2, DAPM widget states
  (MM_UL, LPI_MI2S_TX_3, DEC1/ADC/MIC BIAS…), control read-backs and the klog delta; PASS per variant = > 50 % of the
  expected bytes and non-zero samples. `adm_err` now also catches `no backend DAIs`, `AFE enable`, `returned error`,
  `Audio Client already`.
- ROM note: the AOSP example HAL records on **pcmC0D0c (MM1)** while playing on D0p; mainline q6asm-dai gives one ASM
  session per FE and direction-less (`q6asm_audio_client_alloc` returns the *existing* client for the same session), so MM1
  full duplex is likely impossible without a q6asm-dai change → if variant C passes alone but duplex fails, the next fix is
  a per-direction ASM session in q6asm-dai (or a HAL config for device 1).

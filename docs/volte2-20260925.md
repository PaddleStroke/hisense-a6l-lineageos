Agent `volte2`. **Everything is offline: built, host-tested with a fake modem, and syntax-checked against the Lineage AIDL V4
headers. Nothing ran on the phone and nothing touched RF.** The bundle `v75/volte2` is staged on the laptop (`LAPTOP_STAGED_OK`).
Plan and background: docs/volte-20260925.md (plan B = modem-centric IMS, transparent to Android).

## 0. Summary
| item | result |
|---|---|
| IMSDCM (770) protocol | Decoded from the **stock IDL tables** in `vendor/lib64/libqmiservices.so`, using the new `tools/volte/idldump.py` (APS2 relocations + QCCI IDL encoding). Service 770, **IDL 1.15**, 17 requests and 7 indications. PDP_ACTIVATE and PDP_DEACTIVATE match libqmi 1.38 byte for byte. The other message names are inferred from `imsdatadaemon` log strings (§1). |
| Who is the server | **The AP** (confirmed): imsdatadaemon logs `REQ:MSGID:%d from MODEM`, `dcm_connect request from Modem`, and sends `qmi_csi_send_ind`. The modem IMS stack is the QMI client. |
| AP server | New `a6l::qmi::Server` (qmi/src/server.cc). It publishes a QRTR NEW_SERVER {770, instance word 0x01 = major 1, instance 0} from its own socket. The kernel ns (checked in `a6l-baseline-7.2/net/qrtr/ns.c`) takes node/port from the sender, broadcasts the server to the modem node and re-announces it after a modem restart (HELLO). DEL_CLIENT/BYE tell the server when the modem client is gone. |
| IMS PDN | `radio::ImsDcmService` (qmi/src/imsdcm_service.cc): answers PDP_ACTIVATE at once with a PDP id (from 1, never 0). Then it opens its own WDS client, optionally binds mux 9 (0 = no bind), sets the IP family and runs **Start Network on the modem's WDS profile** (6 = `ims` on this phone) or on the APN if the profile is 0. It reads the address and sends PDP_ACTIVATE_IND with the result and the address struct. The WDS client stays open while the PDN is up. A network drop sends PDP_ACTIVATE_IND with a failure result (the stock eCS_ENETNONET path; the IDL has no deactivate indication). It also handles DEACTIVATE, GET_IP_ADDRESS (response + indication 0x22) and LINK_ADDR (logged, ok). The remaining requests (app state, Wi-Fi/HO, …) are answered with success; 0x32 gets NOT_SUPPORTED with its mandatory TLVs zero-filled. |
| AP routing | **Not needed for VoLTE voice (modem-centric):** SIP and voice RTP run on the modem's IP stack. The stock daemon only reports the address to the modem; the AP rmnet is used by ims_rtp_daemon for **video** only. No rmnet link or route is created. This is inferred from the stock design and becomes proven when IMSA reports "registered" in the test below. |
| Daemon | `a6l-imsdcm` (tools/a6l_imsdcm.cc), a vendor binary with init rc, sepolicy and PRODUCT_PACKAGES. **Off by default** (`persist.vendor.a6l.ril.volte=0`). Knobs: env `A6L_IMSDCM_*` or `persist.vendor.a6l.ril.imsdcm_*`. `--imsa` waits for IMSA (33) and prints the decoded registration and service status. |
| IMSA in the radio HAL | ModemCore (slot 1) looks up IMSA as an optional service. When IMSA appears (late, or never), the HAL registers for indications and reads the registration and service status into a cache. Every change is logged as `A6L_RIL_IMS slot1 …`. `getImsRegistrationState` answers isRegistered + THREE_GPP, and `onImsChanged` triggers `imsNetworkStateChanged`. Losing IMSA does not count as losing the modem. |
| PDC/MCFG (read-only) | `volte-probe all` runs twice in the test (low power, then online): `PDC_ACTIVE` / `PDC_INFO desc=` show whether the Orange FR SW MBN is selected. **No selection change was written or run.** Step 0b (PDC select) still needs Pierre's go. |
| Tests | Host tests: **a6l-qmi 271/271, a6l-modemcore 87/87, a6l-volte2 291/291 (3 rounds), a6l-volte2-modemcore 11/11**, ASan+UBSan, in the container and in WSL gcc (relay `volte2-02`). HAL and lib: **SYNTAX rc=0** with clang-r596125 against the tree's AIDL V4 NDK headers (includes RadioNetworkData with the new override and a6l_imsdcm.cc). No `m` was run. |

## 1. IMSDCM 770 as decoded from the stock IDL (tools/volte/idldump.py)
`python3 tools/volte/idldump.py firmware/extracted/vendor/lib64/libqmiservices.so imsdcm imsa`. IDL encoding follows the QCCI
`qmi_idl_lib_internal.h` (hades2013/qmi-framework). Every table decodes consistently up to its LAST_TLV flag.

| id | req TLVs | resp TLVs (after 0x02 result) | ind TLVs | name (source) |
|---|---|---|---|---|
| 0x20 | 0x01 {u8-len APN ≤100, u32 apn_type, u32 rat, u32 ip_family, u32 wds_profile}, 0x10 seq u32, 0x11 subs u32, 0x12 slot u32, 0x13 instance u32 | 0x10 pdp_id u8, 0x11 seq, 0x12 instance | 0x02 result, 0x01 pdp_id u8, 0x10 seq, 0x11 {u32 family, u8-len addr ≤40}, 0x12 instance | PDP_ACTIVATE (libqmi, strings) |
| 0x21 | 0x01 pdp_id u8, 0x10 instance | 0x10 pdp_id, 0x11 instance | — | PDP_DEACTIVATE (libqmi) |
| 0x22 | 0x01 pdp_id, 0x10 instance | 0x10 pdp_id, 0x11 instance | 0x01 pdp_id, 0x10 addr struct, 0x11 instance | GET_IP_ADDRESS (inferred) |
| 0x23 | 0x01 {u16 port, u32 family, u8-len addr ≤40} | — | — | LINK_ADDR (log prints port/family/ipaddr) |
| 0x24 | — | — | 0x01 pdp_id, 0x10 addr, 0x11 instance | ADDRESS_CHANGE_IND (inferred) |
| 0x25–0x2d | u8 + u32 fields | 0x10 u8 | 0x25 {u8,u32}, 0x2b {u8,u32,u32,…} | HO_MEASUREMENT_* / WIFI_QUALITY (VoWiFi; inferred) |
| 0x2e | 0x10 u8, 0x11 u32 | 0x10 u32 | 0x2f {u32,u32}, 0x30 {u8,u32} | REGISTER_APP_STATE / APP_STATE_IND (inferred) |
| 0x31 | 0x10 u8[≤1024, u16 len], 0x11 u32 | 0x10 u32 | — | WLAN_TZ? |
| 0x32 | 0x01 u8, 0x02 u32 | **mandatory** 0x03 u8, 0x04 u32, 0x05 {8×u16, u64} | — | GET_WIFI_QUALITY? |
| 0x33 | 0x01 u32 | — | — | SUB_DESTROY_INSTANCE? |
| 0x34 | 0x01 u64 | — | — | SERVICE_ENABLE_STATUS? |

Enums (libqmi): apn_type 0 ims, 1 internet, 2 emergency, 3 rcs, 4 ut, 5 wlan; rat 0 ehrpd, 1 lte, 2 epc, 3 wlan; family 0 v4, 1 v6.
The address travels as text ("10.x.x.x"). Stock logs it with %s, and the u8 array holds at most 40 bytes, enough for a text
IPv6 address. `A6L_IMSDCM_ADDR=bin` sends 4/16 raw bytes instead, in case the modem rejects the text form.
IMSA (33, IDL 1.36) was checked against the same tables. Get Registration Status response: 0x10 bool, 0x11 err u16,
0x12 status u32, 0x13 string, 0x14 tech. **The indication 0x23 uses different ids:** 0x01 bool, 0x10 err, 0x11 status,
0x12 string, 0x13 tech. Services status (0x21 response / 0x24 indication) uses 0x10 sms, 0x11 voice, 0x12 vt, 0x13–0x15 tech,
0x16/0x17 ut. Register indications (0x22) uses 0x10 reg and 0x11 services, both u8.

## 5. Risks / unknowns
- Nothing has run against the real modem. The IMSDCM layouts come from the stock IDL, but the **handshake order is unknown**. The modem may wait for REGISTER_APP_STATE (0x2e) or SERVICE_ENABLE_STATUS (0x34) semantics beyond "success". Unknown requests are logged as hex so the next round can implement them.
- The QRTR instance: stock may register with a per-subscription instance (logs "GetInstanceId … Multisub"). Default 0 (word 0x01); variant `A6L_IMSDCM_INSTANCE=1`.
- The address as text vs binary (both are implemented).
- Whether the modem publishes IMSA at all with the current MBN (t25-76 was taken in low power). If the SW MBN is not Orange, step 0b is needed (PDC select + activate = modem reset; RAM EFS makes it reversible). **Not done; needs Pierre's go.**
- Bind mux 9 without DPM/WDA (IPA not loaded) is refused and the call continues unbound. Whether an unbound Start Network is accepted is untested on SDM660 (the 24 Sep modem-only data test suggests yes).
- IMS PDN and the Android default data PDN at the same time: separate WDS clients and mux ids (the HAL uses 1–8, IMS uses 9). Their behaviour together under DSDS is untested.
- The daemon is off by default; `persist.vendor.a6l.ril.volte=1` is the switch once the test passes. The emergency PDN (apn_type 2) goes through the same path. It is never tested (no 112 tests).

## 0. Summary
| item | result |

| Real blocker (most likely) | **IMSA and IMSS answered `INVALID_OPERATION` (err 70) to every query, even before 770 existed.** The stock qcril binds both clients to the subscription first: `ImsaModemEndPointModule::handleQmiBinding` sends IMSA **0x0033 {0x10 u32 sub}**, and `ImssModemEndPointModule::handleQmiBinding` sends IMSS **0x0098 {0x01 u32 sub}** (both disassembled in `libril-qc-hal-qmi.so`). | Fix | `a6l-imsdcm --imsa` now uses one QMI client for IMSS and IMSA and runs the qcril sequence. (1) IMSS bind sub 0. (2) Get Service Enable Config 0x0090 (logged). ## 1. Stock decode (how to redo it)
- IDL: `python3 tools/volte/idldump.py firmware/extracted/vendor/lib64/libqmiservices.so imsdcm imsa imss`.
  IMSS is 18, IDL 1.70. IMSA is 33, IDL 1.36: REQ 0x0033 {0x10 u32} = bind.
- imsdatadaemon dispatch: `da2c` (log `REQ:MSGID:%d from MODEM`) → `sub w8,w19,#0x20; cmp #0x14` → table
  `0x4f560` (R_AARCH64_RELATIVE):

  | id | handler | name (stock string) |
  |---|---|---|
  | 0x20 | 15b7c | PDP_ACTIVATE_REQ |
  | 0x21 | 16244 | PDP_DEACTIVATE_REQ |
  | 0x22 | 16c38 | GET_IP_ADDRESS_REQ |
  | 0x23 | 172f8 | LINK_ADDR_REQ |
  | 0x25 | 17634 | WIFI_QUALITY |
  | 0x26 | 1794c | STOP_WIFI_QUALITY |
  | 0x27 | 17b1c | UPDATE_WIFI_QUALITY |
  | 0x28–0x2a, 0x2c, 0x2d | … | HO_MEASUREMENT_INIT/START/STOP/STATUS/UNINIT |
  | 0x2e | 18948 | REGISTER_APP_STATE_REQ |
  | 0x32 | 18ad8 | WLAN_TZ_REQ |
  | 0x33 | 18d4c | SUB_DESTROY_INSTANCE_REQ |
  | 0x34 | 18ee8 | SERVICE_ENABLE_STATUS_REQ ("RCS Service type mask") |

  0x24, 0x2f, 0x30 and 0x31 have no request handler: they are indications (0x2f is sent at `130b4` with BT_CRITERIA, and 0x30 at `8884` on DATAD_MODEMLL).
- qcril (`vendor/lib64/libril-qc-hal-qmi.so`): the IMSA bind is at `78de20` (`mov w1,#0x33`, struct {valid=1, u32 sub}), and the IMSS bind is at `78e888`
  (`mov w1,#0x98`, u32). The IMSS set is at `9937a4` (`mov x0,#0x8f`, 0x48-byte struct), and the IMSS get is at `99d978` (`#0x90`).
  `set_ims_registration_v02` sets req offset 47/48 (valid/value) = TLV 0x18 from the requested registration state.
  Tools: `~/vo28/{a64dis,annot,xref}.py` in the Cowork session (capstone). They are not in the repo; the addresses above are enough to redo the decode.

## 7. Risks (honest)
- The TLV meanings of IMSS 0x8F/0x90 come from qcril's struct offsets and log strings. 0x18/0x19 = ims_service_enabled is
  solid ("IMS has_state"). That 0x10/0x11 = volte is inferred from the srv-status handler; setting it to 1 is what the Android VoLTE switch does.
- IMSS Set may persist in the modem EFS. Today that EFS is the RAM copy, so a reboot discards it. **In the ROM it persists**, which is the wanted effect.
- The ROM rc now runs `a6l-imsdcm --imsa` with `imsdcm_imss=enable`. The service is still off by default (`persist.vendor.a6l.ril.volte=0`).
- DSDS: sub 0 is assumed (SIM in slot 1, as all tests so far). The HAL binds with its own slot index.
- No Android ImsService: there is no VoLTE icon and no `isImsRegistered()`. This is expected in plan B.

## 1. Code base and why it changed

* **Sireesh Kodali's RFC** "net: ipa: Add support for IPA v2.x" (Sep 2021) and its descendants, msm8953-mainline
  `msm8953-6.1.0/ipa`, `alikates/6.5/ipa` and `6.5.2/ipa`. The last of these is ipa-legacy, which kvoice ported. They
  bolt v2 onto the v3 GSI driver through an `ipa_dma` abstraction and need two bam_dma extensions (metadata and immediate
  commands). The authors reported that on v2.6L it got an IP but passed no packets. The last commit on `6.5.2/ipa` (Dec 2023) is
  "[FIXME] net: ipa-legacy: disable non-command DMA transactions", which shows the lineage was abandoned.
* **`ipa2-lite`** (msm8953-mainline, first in the 6.x main branches, now in `6.12/main` … `7.1.3/main` and `barni2000/7.1.3/develop`):
  * commit 87776a02 "net: add driver for Qualcomm IPA 2.X", plus the fixups "update size and flags on skipped RX
    descriptors", "initialize system headers and set max_mtu" and "create modem netdev before it might be used";
  * commit f1f6e1d3 "arm64: dts: qcom: msm8953: add IPA": node `qcom,ipa-lite-v2.6`, one register region
    `0x7900000 0x47000`, IRQs `ipa` (edge) and `dma` (level), `RPM_SMD_IPA_CLK`, `iommus`, `modem-remoteproc`.

  It is a new, self-contained 3.4 k-line driver: its own BAM FIFO handling, NAPI RX/TX, SRAM init through immediate
  commands, a QMI server and client, the uC handshake and SSR. It implements only what the modem needs, and the
  modem programs the filter and route tables for its own pipes. It supports v2.5 and v2.6L.
* **Also checked:** the msm8953-mainline branch list (all `*ipa*` and all `main`/`develop` branches up to 7.1.3). pmaports and
  GitLab could not be reached from here (403/robots), so the pmOS kernel config was not read. The evidence that data
  works on msm8953 is indirect: the pmOS v24.06 release notes, and the driver's continued rebases and fixups.
* **Choice:** ipa2-lite. The sources are in the repo: upstream copy in `ipa2-lite/upstream-7.1.3/`, the A6L version in `ipa2-lite/src/`.

### A6L changes (`a6l-ipa2-lite-fix.py`, idempotent; `a6l-ipa2-lite-sdm660.diff`, 110 changed lines)

* **Driver name `ipa2-lite`.** The mainline `ipa.ko` also registers a platform driver named "ipa".
* **Compatible `qcom,sdm660-ipa-lite`** (v2.6L).
* **Module parameters:**
  * `clk_hz` (default 40 MHz, as on msm8953; downstream v2 uses 75/150/200 MHz) and `clk_idle_hz`;
  * the interconnect vote (`icc_mem_*_kbps`, `icc_cfg_kbps`). It is **optional** and applies only if the DT node has `interconnects`. The values
    come from the stock msm-bus SVS vector: IPA→EBI ab 80000 / ib 640000 KBps.
* **Diagnostics:**
  * `A6L_IPA …` dmesg lines: HW version, BAM revision, IOMMU on/off, SRAM restricted/size and the full layout, SRAM-init result,
    uC INIT_COMPLETED, QMI service up, INIT_DRIVER OK, INIT_COMPLETE indication, modem present/absent;
  * a read-only sysfs `/sys/bus/platform/devices/14780000.ipa/a6l_diag`, with the IPA/BAM IRQ state and, per pipe 0–14, the BAM ctrl, rd/wr
    offsets, IRQ status and the IPA EP ctrl/hdr/hdr_ext/route/mode/status/aggr/holb/dbg-counter.
* `MODULE_SOFTDEP("pre: qcom_q6v5_mss")` is informational only; the bundle controls the load order.

## 2. The SDM660 hardware and DT (stock → overlay)

The stock node is `qcom,ipa@14780000`, with `qcom,ipa-hw-ver = <6>` (v2.6L), `ipa-base 0x14780000/0x4effc`, `bam-base 0x14784000`, IRQs SPI 333
and SPI 432, `core_clk` = the RPM IPA clock, `ipa_smmu_ap` = anoc2 SID **0x19c0** with **S1 bypass**, and the msm-bus vectors
(master 90 → EBI, APPS → IPA_CFG).

Overlay A (`device/hisense/a6l/kernel/ipa/dt/a6l-ipa-v75.dtso`) adds this node under `/soc@0`:
```
ipa@14780000 { compatible = "qcom,sdm660-ipa-lite", "qcom,ipa-lite-v2.6";
  reg = <0x14780000 0x4f000>;                   /* BAM +0x4000, IPA regs +0x40000, SRAM/uC mailbox +0x45000 */
  interrupts = <0 333 1>, <0 432 4>; interrupt-names = "ipa", "dma";
  clocks = <&rpmcc 68>;                         /* RPM_SMD_IPA_CLK (7.2 dt-bindings: 68) */
  interconnects = <&a2noc 0 &bimc 5>; interconnect-names = "memory";   /* MASTER_IPA -> SLAVE_EBI (7.2 sdm660.h) */
  iommus = <&anoc2_smmu 0x19c0>; modem-remoteproc = <&remoteproc_mss>; };
```
In the V74 DTB (and so in 7.2), anoc2_smmu (`qcom,sdm630-smmu-v2`) is enabled and used only by SIDs 0x1a00/0x1a01. The kernel has
`ARM_SMMU_DISABLE_BYPASS_BY_DEFAULT=y`, so the node needs `iommus`; without it every IPA DMA would fault.
**Fallback B** (`a6l-ipa-identity-v75.dtso`) adds the compatible `qcom,sc7180-mss-pil`. That compatible is in arm-smmu-qcom's
`qcom_smmu_client_of_match`, so the device gets an **identity (bypass) domain**, which is the stock S1-bypass behaviour. It is a
hack for testing only; §5 lists the caveats. Both variants are embedded in `a6l_ipa2_ovl.ko` (`identity=1`).

### Hypotheses: why the 2021 RFC passed no packets on v2.6L, and what ipa2-lite changes
1. **AP_LAN_RX status/pad handling.** The RFC dropped or stalled on exception/status packets. Later commits in its own branch were
   "Skip entire unprocessed packets" and "Remove pad_align from AP_LAN_RX". ipa2-lite: LAN_RX has status only, is always
   refilled, and skipped descriptors get their size and flags reset (fixup).
2. **System header table not initialised.** On v2.6L the apps header table lives in DDR ("system"; APPS_HDR_SIZE is 0), and the
   global route register selects the system table. Without `HDR_SYSTEM_INIT`, routing to the AP pipes uses garbage headers. ipa2-lite
   fixed this in a named commit ("initialize system headers").
3. **Dependence on dmaengine/BAM semantics.** Immediate commands and per-descriptor metadata/EOT/INT flags went through bam_dma, which
   has no clean way to express them. The last RFC-lineage commit disables non-command DMA outright ([FIXME]). ipa2-lite writes BAM
   descriptors directly: INT on RX, EOT on TX, IMM+EOT on commands.
4. **The rmnet/QMAP checksum flags do not match the endpoint config.** If userspace enables MAPv4 checksum while IPA has no checksum offload,
   every packet is dropped. → Use rmnet flags `0x01`, which the HAL uses by default.
5. **Wrong AP-side config for the modem init handshake.** The route index count, the restricted-bytes shift or the missing
   INIT_COMPLETE indication after the uC is up leave the modem without filter rules for EP4. ipa2-lite matches downstream (§3 table); status
   visible via `A6L_IPA` lines.
6. **SDM660-specific (new): SMMU translation versus stock S1 bypass.** If the IPA/BAM also issue SID 0x19c0 transactions on behalf of
   modem-owned pipes, translation faults them. → Fallback B, the identity domain.
7. **SDM660-specific: clock or bus starvation** at 40 MHz and with no votes. → `IPA_PARAMS="clk_hz=75000000"`; the icc vote is in overlay A.
8. **SDM660-specific: IRQ trigger types.** They were copied from msm8953; the stock DT has trigger 0. If the `ipa` IRQ never fires,
   the uC-loaded event is missed. The driver also checks the SRAM flag at probe, and `a6l_diag` shows `irq_stts`.

## 5. Attended test (V74 recovery, fresh boot). Steps marked RF need Pierre's explicit go, and Pierre types them himself

Run from the laptop in `~/A6L-usb-20260915`. Push: `adb -s HLTE730T-PROBE push v75/ipa2 /tmp/ipa2`, plus `v74/radio2 → /tmp/radio2`
and `v74/ril → /tmp/ril` as usual.

1. **Load IPA (no RF). It must run BEFORE radio2.**
   `adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export D=/tmp/ipa2; export MODE=load; sh /tmp/ipa2/run.sh' 2>&1 | tee v75/logs/ipa2-load-$(date +%H%M).txt`
   * **Expect:**
     * `A6L_IPA hw ver … bam rev … iommu yes`;
     * `A6L_IPA sram restr 0x… size 0x…` (note the size; ≥ 0x2000 expected);
     * `A6L_IPA sram tables initialised via immediate commands`, then `A6L_IPA modem absent`;
     * `rmnet_ipa0` and `ipa_lan0` exist → **`A6L_IPA2_LOAD_PASS`**.
   * **Watch:** `arm-smmu … Unhandled context fault … 0x19c0`. If it appears, reboot and retry with `export IDENTITY=1;`.
2. **RF: modem.** Pierre runs radio2 as on 23 Sep, with `export A6L_KEEP=1;` so that the modem stays up for step 4:
   `adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1; export A6L_KEEP=1; export D=/tmp/radio2; export A6L_WLAN_MAC=persist; sh /tmp/radio2/run.sh'`
3. **Handshake (no RF).**
   `adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export D=/tmp/ipa2; export MODE=status; sh /tmp/ipa2/run.sh'`
   * **Expect** all five boxes ticked: QMI service up → INIT_DRIVER OK → uC INIT_COMPLETED → INIT_COMPLETE indication → modem PRESENT
     → **`A6L_IPA2_MODEM_READY`**.
   * **The modem must stay up for 300 s**; `radio2` must still report `A6L_MODEM_STABLE_PASS`.
4. **RF: data call.** First make sure the modem is ONLINE and registered (`ril-test.sh ro`; `online` is RF), then:
   `adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1; export D=/tmp/ipa2; export MODE=data; export APN=; export KEEP=60; sh /tmp/ipa2/run.sh' 2>&1 | tee v75/logs/ipa2-data-$(date +%H%M).txt`
   (set `APN=` to the operator APN if the default profile fails).
   * **Expect:** `A6L_QMI_DATA_UP if=rmnet_data0 … addr=[…] dns=[…]`, then **`A6L_IPA2_PING_PASS`** (the DNS server and 1.1.1.1 are pinged by IP,
     through /32 host routes only, so the Wi-Fi/USB routes are untouched) and **`A6L_IPA2_DNS_PASS`** if `nslookup` exists in /tmp/bin.
   * rx/tx counters on rmnet_ipa0 and rmnet_data0 are printed.
   * **If ping fails:** keep the whole output. Useful fields: the rmnet_ipa0 tx count (did the AP send?), the pipe 4/5 rd/wr offsets and the dbg counters in
     `a6l_diag`, and `ipa_lan0` rx (exceptions). For hex dumps, run `echo 1 > /sys/module/ipa2_lite/parameters/dump` before step 4.
   * **Variants for the next session:** `IPA_PARAMS="clk_hz=75000000"`, `IDENTITY=1`.
5. **Finish.** Do not `rmmod ipa2_lite`: its remove path shuts the modem down. Stop via `ril-test.sh stop`, or reboot.

**Stop criteria:** an oops, a context-fault storm, or the modem crashing within 300 s of the IPA handshake. In that case, reboot and keep `dmesg`.

## 6. Risks and honest estimate
* **Nothing has run on hardware.** ipa2-lite works on msm8953 (same IPA v2.6L). The evidence is indirect but reasonable: pmOS v24.06 release
  notes, and 2.5 years of rebases and fixups. On SDM660 it has never run.
* **SDM660 unknowns:**
  * the SMMU (translated vs. stock bypass; fallback B is a DT hack. If `qcom_q6v5_mss` is loaded while probing, it also matches the
    fallback's compatible, so ipa2_lite must be loaded first; run.sh does that);
  * the IRQ trigger types;
  * the SRAM size;
  * the clock rate;
  * whether this modem firmware accepts the non-downstream table offsets (it should: they come over QMI).
* **The load order matters.** The probe resets the whole IPA, so it must happen before the modem boots, and the bundle refuses a running modem. For the ROM
  (flash agent), `ipa2_lite.ko` + `rmnet.ko` must load **before** `qcom_q6v5_mss` (a modules.load order or a softdep in modprobe config),
  and the overlay-A node belongs in the V75 DT (`a6l-ipa-v75.dtso`).
* **Radio HAL contract.** The netdev is `rmnet_ipa0` (same name). WDA endpoint type 4 / interface 1 with rmnet flags 1 is unchanged. The sysfs
  `modem/rx_endpoint_id=5`, `tx_endpoint_id=4` exist. Driver name `ipa2-lite` (upstream "ipa"; only ModemManager keys on that).
* **Throughput:** no IPA aggregation, 256-descriptor rings and a 2 KiB RX buffer (MTU 2012). Fine for browsing; not tuned.
* **Estimate:**
  * probe and handshake to `A6L_IPA2_MODEM_READY` in one attended session: likely (~60–70 %);
  * ping by IP in the first data session: ~40–50 %;
  * if it fails, 1–3 more sessions with the diagnostics above.

  This is much better than the 2–4 weeks estimated for the RFC route, because the hard v2 data-path work is already done upstream in ipa2-lite.

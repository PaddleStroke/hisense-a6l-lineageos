# audfix: silent media playback (ADM EBADPARAM) and call volume (24 Sep 2026, agent `audfix`)

All of this was done offline. Nobody touched the phone. Kernel `7.2.3-a6l-probe+` (out-a6l-phone-v67).

## 1. Silent media playback: root cause

**The failing command is not the ADM open.**
* Opcode `0x10325` is **ADM_CMD_MATRIX_MAP_ROUTINGS_V5**. ADM_CMD_DEVICE_OPEN_V5 is `0x10326`.
* The "DSP returned error[2]" message comes from `q6adm_matrix_map()`. That function runs with the routing device, which
  is why the log line names q6routing.
* The COPP open succeeded every time. The DSP rejected the matrix mapping with ADSP_EBADPARAM.

**The mechanism** (upstream `q6routing.c`, identical in 7.2.3):
1. `struct msm_routing_data` has **one** `sessions[MultiMediaN]` entry with **one** `port_id`. The RX mixers
   (`<BE> Audio Mixer MultiMediaN`) and the TX mixers (`MultiMediaN Mixer <BE>`) both write to it with the same put
   handler. **The last route set wins.**
2. audio3's `fe-routes.txt` and the ROM `mixer_paths_a6l.xml` top level set `LPI_MI2S_RX_0 Audio Mixer MultiMedia1=1`
   and then `MultiMedia1 Mixer LPI_MI2S_TX_3=1`. After that, `sessions[0].port_id` = **LPI_MI2S_TX_3**. As a side
   effect, the RX control also reads back 0.
3. On playback, `q6routing_stream_open(... stream_type=PLAYBACK)` ignores `stream_type`. It opens the COPP on
   **INT3_MI2S_TX** with the TX port's hw_params (path LIVE_REC, set by the earlier capture probe), and that open
   succeeds. It then maps **ASM session 1, which is open for WRITE,** onto the **ADM TX matrix**. The DSP returns
   EBADPARAM, no ADM→AFE route exists, and playback is silent.
4. Voice worked because CVP does not use the ADM matrix.

**Things checked and ruled out:**
* **AFE port.** `LPI_MI2S_RX_0` maps to `AFE_PORT_ID_INT0_MI2S_RX` = **0x102E** (q6afe.c:948 in the tree). That is the
  same port stock uses (`audio_platform_info.xml`: headphones → INT0_MI2S_RX) and the same one voice used today.
  0xB030 is RX_CODEC_DMA_RX_0 on newer SoCs and does not apply to SDM660.
* **Topology.** Mainline opens with NULL_COPP (0x10312), and the open is accepted, so there is no EBADPARAM on 0x10326.
  Stock uses an ACDB topology with an app_type. That affects post-processing only, not routing, so no change is needed.
* **The matrix payload layout.** It is the same as the msm-4.4 `adm_matrix_map` layout: matrix_id, num_sessions, then
  {session_id, num_copps} and the u16 copp ids. The mainline pkt_size counts u32 per copp. For 1 copp that equals the
  stock padded size.

## 2. The fix
`device/hisense/a6l/kernel/audfix/a6l-q6routing-per-direction-v75.patch`
(sha256 `1a8c2587…0dc`, applies to the 7.2.3 tree, dry-run OK) changes four things:
* It adds `tx_sessions[MAX_SESSIONS]` next to `sessions[]` (which stays for playback). The TX mixer macro uses new
  `msm_routing_{get,put}_audio_mixer_tx` handlers. RX and TX routes of the same FE now coexist and both read back correctly.
* `q6routing_stream_open()` picks the table by `stream_type`. It derives the ADM path (PLAYBACK/LIVE_REC) from the
  stream direction and logs `A6L_Q6ROUTING …` if the BE hw_params disagree. It also bounds-checks `stream_id`.
* `q6routing_stream_close()` and `get_session_from_id()` search only the table for that direction, so closing the
  capture no longer closes the playback COPPs.
* Probe initialises both tables.

Build: `tools/build-audfix-v75.sh` (own M= dir). **q6routing.ko sha256 `d11343cb0d1e5e3be46d5af3b2e2f8757265af5d20271738d9e52721a90ceae4`,
W=1 0 warnings**, vermagic `7.2.3-a6l-probe+ SMP preempt mod_unload aarch64` (same as kvoice), depends `q6adm,snd-soc-core`.

For the `flash` agent: apply the patch to the kernel tree along with the q6asm-dai xlate patch. No DT change is needed.

**Remaining risk: full duplex on ONE FE.** Mainline `q6asm-dai` allocates the ASM audio client per DAI (session = dai id+1).
A capture opened on MultiMedia1 while MM1 plays reuses the same ASM session, and the DSP will likely reject the second
stream open. Mainline boards (db845c/sm8250 UCM) use MM1 for playback and MM2 for capture. The `media` test below
measures both cases:
* If `A6L_AU4_MM1_DUPLEX no`, the ROM should capture on **MultiMedia2 = pcm device 1**. mixer_paths top level would then
  be `MultiMedia2 Mixer LPI_MI2S_TX_3=1` instead of MM1. The AOSP example HAL uses device 0 for input, so it would need
  a patch or config for that. That is audio3's/flash's area, and they have not changed it yet.
* Playback alone works with the current `mixer_paths_a6l.xml` once the patch is in.

**Zero-build confirmation, if wanted:** in the old kvoice/audio3 state, set ONLY `LPI_MI2S_RX_0 Audio Mixer MultiMedia1=1`
and do NOT set the MM1 TX route, then tinyplay. This should already play with the upstream module.

## 3. Call volume
**Stock** (`vendor/etc/mixer_paths_mtp.xml`; the stock ELF's `msm_anlg_cdc_snd_controls` was decoded):
* Headphones use RX1/RX2 Digital Volume **84 (0 dB)**, "RX HPH Mode"=HD2 and COMP0 RX1/RX2=1 (compander).
  `voice-headphones` = `headphones`.
* **"HPHL/HPHR Volume" (9) exist only for the tasha/tavil WCD93xx codecs.** The internal PM660L analog codec has no
  HPH gain control. Its only controls are ADCn Volume, EAR PA Gain/Boost, RX HPH Mode, boost enums and loopback.
* Call loudness on stock comes from the ACDB CVP/CVS volume table. The HAL sends "Voice Rx Gain"
  {session, vol index, ramp 20 ms}, which becomes VSS_IVOLUME_CMD_SET_STEP. We run CVD **without ACDB**, so no volume
  table is loaded. Sending SET_STEP without a calibration table is untested, so it was **not** added.

**Proposal** (safe):
* Default for voice on the headset: raw **84** (0 dB, same as stock digital).
* Optional steps: **87 (+3 dB)** and **90 (+6 dB)**. Hard cap **90**.
* A digital gain above 0 dB only clips signals above −6 dBFS. Downlink voice sits far below that.
* Speaker/TFA and earpiece are unchanged (the earpiece is broken on this unit).
* For the ROM: the `voice-headphones` volume goes to 84 and the stream volume stays in AudioFlinger. Revisit this once a
  CVP volume table is available.

**What to expect in each mode:**
* **`load`:** `A6L_Q6ROUTING_PATCHED yes`, both MM1 routes read back On, and D0p and D0c open.
* **`tone`:** `A6L_PLAY_RC … 0` ×3 and `A6L_AU4_TONE_PASS`, with **no** `q6adm … cmd = 0x10325` line. Pierre hears a
  faint tone L, R, then both. On FAIL, the klog lines printed show which command failed.
* **`media`:** `A6L_AU4_MEDIA_PASS` (playback on MM1 plus capture on MM2 at the same time, capture > 100 kB). The line
  `A6L_AU4_MM1_DUPLEX ok|no` is informative only.
* **`call`:** same flow as kvoice, with digital 0/+3/+6 dB. Ask Pierre about loudness and distortion.

**Safety:** a digital volume above raw 90 is refused, and the read-back check mutes and aborts. The first tone runs at
−30 dB digital with −30 dBFS content.

## 6. Untested / unknown
* Nothing here has run on the phone.
* The EBADPARAM diagnosis comes from the source logic. It fits every observed symptom: the error is on 0x10325 and not on
  0x10326, voice works, and the fe-routes order is RX then TX. The DSP-side reason was not proven with a trace.
* MM1 full duplex may fail at the ASM level (see §2).
* The CVS volume step (SET_STEP) is not implemented.
* There is no equivalent of the stock HD2/compander, which may explain part of the "not very loud" impression.

# wifi-hal: Android Wi-Fi vendor HAL for ath10k/nl80211 (r5 review fix F5), 29 Sep 2026

Agent `wifi-hal`. Offline only: no phone, no adb. **Nothing here has run on the phone.** `m` was not run: the Lineage tree's
`out/soong/.temp` is root-owned (same blocker as senshal). Instead the code was compile-checked with the tree's clang
(r596125) and the tree's own soong flags, and host-tested. See §6.

## 1. Problem (F5, docs/hardware-review-20260928.md)
`BOARD_WLAN_DEVICE` is unset, so soong links `libwifi-hal-fallback` into `android.hardware.wifi-service`. Its
`init_wifi_vendor_hal_func_table()` returns `WIFI_ERROR_NOT_SUPPORTED`. Result: `IWifi.start` fails, and Android Wi-Fi
cannot start, although ath10k + a plain nl80211 wpa_supplicant got WPA2 + DHCP + Internet in recovery
(docs/wifi-20260926.md).

One detail the review did not mention: `WifiLegacyHalFactory::getHals()` does not stop at the linked HAL. When
`initVendorHalDescriptorFromLinked()` fails, it calls `initVendorHalsDescriptorList()`. That reads
`/vendor/etc/wifi/vendor_hals/*.xml` (`<WifiVendorHal version="1"><path>…</path><primary>1</primary>`) and
`dlopen()`s each library listed. This product shipped no descriptor, so it ended with zero HALs.

## 2. Options evaluated (in the local tree)
| option | verdict |
|---|---|
| `BOARD_WLAN_DEVICE := qcwcn` (`hardware/qcom-caf/wlan/qcwcn/wifi_hal`) | **No.** Built around QCA vendor nl80211 commands (`QCA_NL80211_VENDOR_SUBCMD_*`, cld80211) of the proprietary qcacld driver. Mainline ath10k implements none of them, so most calls would fail or misreport. |
| `bcmdhd` / `synadhd` / `nxp` / `realtek` / … | Vendor-specific private commands. Not applicable. |
| `BOARD_WLAN_DEVICE := emulator` (`device/generic/goldfish/wifi/wifi_hal`, libwifi-hal-emu) | **No.** It is generic nl80211/rtnetlink for mac80211_hwsim, but it fakes things: APF v6100 with 4 KiB emulated in RAM (the framework would believe packets are filtered in firmware), keep-alive offload "success" that drops packets, a no-op country code, a hard-coded 2.4 GHz channel list (its `memcpy` even copies bytes, not channels), and version "1.0". The review said explicitly not to assume it. It was used only as the structural reference. |
| `device/linaro/dragonboard` (db845c, ath10k_snoc on mainline) | Not in this tree, so it was not evaluated. Only the in-tree options were compared. |
| `WIFI_HAL_INTERFACE_COMBINATIONS` / `WIFI_HIDL_FEATURE_*` only | Necessary but not sufficient. The chip modes are computed in the AIDL HAL, but `start()` still needs a legacy HAL that initializes. |
| **Own small nl80211 legacy HAL `libwifi-hal-a6l`, loaded via the vendor_hals descriptor (chosen)** | Keeps `BOARD_WLAN_DEVICE` unset (no change to the Lineage tree, no new soong_config value, which the `board_wlan_device` string variable would reject). It implements only what is true for ath10k. Every other function stays on the AIDL HAL's `NOT_SUPPORTED` stubs, which the framework already handles (no gscan, link-layer stats, APF, RSSI monitor, NDO, keep-alive, logger rings, RTT, NAN). |

## 3. What was implemented
`device/hisense/a6l/wifi/hal/` (new):
* `a6l_wifi_hal.cpp` → `/vendor/lib64/libwifi-hal-a6l.so` (`cc_library_shared`, vendor, 64-bit; libnl, libcutils, liblog; `wifi_legacy_headers`):
  * `wifi_wait_for_driver_ready`: waits (default 30 s, `ro.vendor.a6l.wifi.driver_wait_s`) for `wlan0/phy80211` **and**
    `vendor.a6l.wlan.state=ready`. The AIDL HAL calls this before `SetWifiUpState(true)`, and `a6l-radio.sh` sets the
    persist MAC with the link down, so the two can no longer race. It fails fast with `UNKNOWN` when wlan0 is absent and
    `persist.vendor.a6l.radio!=1` (modem off means no WCN3990). It returns `TIMED_OUT` at once when the script reported
    `missing`. If wlan0 exists but the property never becomes `ready*` it returns `TIMED_OUT` (r5 review F38; it used to proceed with a warning); the only fallback is the opt-in `ro.vendor.a6l.wifi.ungated=1`. `a6l-radio.sh` resets the property to `starting` on each start and publishes `ready`, `ready:mac-failed`, `ready:no-persist-mac` or `ready:link-up` (repeated start with wlan0 up: the link is not touched).
  * `wifi_initialize` / `wifi_event_loop` / `wifi_cleanup`: there is one session per start, with an eventfd. The event
    loop blocks until cleanup. Cleanup calls the handler synchronously and never waits for the loop thread. This matches
    `WifiLegacyHal::stop()`: that function holds the global recursive lock, and `runEventLoop()` takes the same lock after
    the loop returns. Restart is supported (the chip reconfigures by stop/start).
  * `wifi_get_ifaces` / `wifi_get_iface_name`: all `/sys/class/net/*/phy80211` netdevs, with stable handles.
  * `wifi_get_supported_feature_set`: `INFRA`. `INFRA_5G` is added if the wiphy has an enabled 4.9–5.9 GHz channel.
    `SCAN_RAND` is added if cfg80211 advertises `NL80211_FEATURE_SCAN_RANDOM_MAC_ADDR`. The data comes from an
    `NL80211_CMD_GET_WIPHY` split dump. If nl80211 fails, it reports `INFRA` only instead of breaking start. The AIDL HAL
    fails `getFeatureSet` on any error.
  * `wifi_get_valid_channels`: enabled wiphy frequencies filtered by BG / A / A_DFS (`NL80211_FREQUENCY_ATTR_RADAR`).
  * `wifi_set_country_code`: `NL80211_CMD_REQ_SET_REG` (cfg80211 user hint; the signed regdb is in `/vendor/firmware`).
    This is used by the AP path (`IWifiApIface.setCountryCode`).
  * Firmware and driver version come from `ETHTOOL_GDRVINFO` (`SIOCETHTOOL`, already allowed to `hal_wifi`).
* `a6l_wifi_vendor_hal.xml` → `/vendor/etc/wifi/vendor_hals/a6l_wifi_vendor_hal.xml` (`prebuilt_etc`, `required` by the lib).
* `driver_cmd_a6l.c` → `lib_driver_cmd_a6l` (`BOARD_WPA_SUPPLICANT_PRIVATE_LIB`; it uses `wpa_supplicant_cflags_default`
  so the `driver_nl80211` structs match). Without a private lib, the supplicant is built with `ANDROID_LIB_STUB` and every
  DRIVER command fails, including the framework's STA `setCountryCode("COUNTRY xx")`. That would leave cfg80211 in world
  domain `00` in client mode. Implemented: `COUNTRY xx` → `REQ_SET_REG`, and `MACADDR`. Anything else returns -1, which
  is the stub result. The P2P hooks return exactly the stub values. hostapd keeps the stub build.
* `compile-check.sh` and `tests/host-test.{sh,cpp}` (§6).

Board / product:
* `wifi/BoardConfig-wifi.mk` (new, included by `rom/BoardConfig-rom.mk`, `hals/BoardConfig-hals.mk`,
  `rom/full/BoardConfig-full.mk`): `BOARD_WPA_SUPPLICANT_DRIVER/BOARD_HOSTAPD_DRIVER := NL80211`,
  `WPA_SUPPLICANT_VERSION := VER_0_8_X`, `BOARD_WPA_SUPPLICANT_PRIVATE_LIB := lib_driver_cmd_a6l`,
  **`WIFI_HAL_INTERFACE_COMBINATIONS := {{{STA}, 1}}, {{{AP}, 1}}`**. `BOARD_WLAN_DEVICE` stays unset.
  `WIFI_HIDL_FEATURE_DUAL_INTERFACE := true` was **removed**: it claimed STA+AP and STA+P2P concurrency.
* `wifi/wifi-hal.mk` (new, inherited by `rom/rom.mk`, `hals/hals.mk`, `rom/full/full.mk`): `PRODUCT_PACKAGES +=
  libwifi-hal-a6l a6l_wifi_vendor_hal.xml`. It **replaces** `soong_config_set,wpa_supplicant,nl80211_driver,CONFIG_DRIVER_NL80211_QCA`,
  so the supplicant and the private lib are plain nl80211, as in the recovery test. The QCA flag only adds qcacld
  vendor-command paths.
* `rom/bin/a6l-radio.sh`: after the wlan0 MAC step it runs `setprop vendor.a6l.wlan.state ready`. If wlan0 is missing
  after 90 s it sets `missing`, and on `stop` it sets `stopped`. `rom/tests/test-a6l-radio-start.sh` checks this.
* `rom/sepolicy/vendor/hal_extras.te`: `get_prop(hal_wifi_default, vendor_a6l_prop)`. nl80211 generic netlink,
  `SIOCETHTOOL`, sysfs and `/vendor/etc` reads are already granted by system/sepolicy.

Unchanged and consistent: `wifi.interface=wlan0` (rom.mk + init rc). ath10k_core/ath10k_snoc are loaded by
`a6l-radio.sh` (`rom/modules/radio.txt`), so no `WIFI_DRIVER_MODULE_*` is set and libwifi-hal's driver load/unload is a
no-op. The supplicant service (`-g@android:wpa_wlan0`, AIDL, `p2p_device=1`) and the regdb (`wifi/wifi-regdb.mk`) are
also unchanged.

## 4. Interface combinations: why only [1 STA] or [1 AP]
The kernel source (`a6l-7.2-voice` `ath10k/mac.c`, TLV firmware = WCN3990) advertises `ath10k_tlv_if_comb`: up to
{≤2 STA, ≤2 AP/P2P-GO/P2P-client, ≤1 P2P-device}, max 4 interfaces, **1 channel**, plus IBSS. The `qcs` variant with 2
channels applies only if the firmware has `WMI_SERVICE_ADAPTIVE_OCS`. P2P modes exist unless the firmware has
`ATH10K_FW_FEATURE_NO_P2P`. **No `iw phy` output from this phone was captured in the repo.**

STA+AP concurrency would need `wifi_virtual_interface_create` (NL80211_CMD_NEW_INTERFACE for wlan1). That is not
implemented and never ran on this firmware. P2P is not declared (`android.hardware.wifi.direct` absent), so the
combination reports exactly STA, or AP on wlan0 (hostapd switches the iftype). `startIdxOfApIface()` = 0 in this mode.
The framework stops STA to start the hotspot, as on any device without STA+AP. Widen this only after §5 step 8.

## 5. Attended validation plan (booted ROM with `persist.vendor.a6l.radio=1`; RF needs Pierre's go)
Logcat tags: `WifiHAL-a6l`, `android.hardware.wifi-service`, `wpa_supplicant`, `WifiService`, `WifiHalDeviceMgr`.
Also `dmesg | grep A6L_ROM_RADIO`.
0. Build check (flash agent, tree synced): `m libwifi-hal-a6l a6l_wifi_vendor_hal.xml lib_driver_cmd_a6l wpa_supplicant
   android.hardware.wifi-service`. Then check that `vendor/lib64/libwifi-hal-a6l.so` and
   `vendor/etc/wifi/vendor_hals/a6l_wifi_vendor_hal.xml` are in the image, and that `strings vendor/bin/hw/wpa_supplicant |
   grep -c "a6l: COUNTRY"` = 1.
1. **IWifi.start**: `getprop vendor.a6l.wlan.state` = `ready`. Logcat shows `processing config file:
   a6l_wifi_vendor_hal.xml`, `driver ready: wlan0 present…`, `initialized, 1 wireless netdev(s)`, `Adding interface
   handle for wlan0`, `Legacy HAL start complete`. No `Failed to initialize legacy HAL`.
   Check `adb shell cmd wifi status` and `dumpsys wifi | grep -i -E "supportedFeatures|isStaApConcurrency"`.
2. **Settings toggle** on: the scan list appears (world domain first, then the country from telephony/location).
   `iw reg get` shows `country FR` after `COUNTRY` (logcat `a6l: COUNTRY FR -> REQ_SET_REG ok`).
3. **WPA2** association to the Livebox from Settings. For WPA3/SAE, see the docs/wifi-20260926.md failure table.
4. **DHCP / Internet**: IP from 192.168.1.x, validated network (no "no internet" badge), a browser page loads.
   `dumpsys connectivity` shows wlan0 as default.
5. **Off/on** ×3: Settings off, then on. Each cycle ends with `event loop exited` and a new `initialized`, reconnects
   automatically, and has no `Legacy HAL stop failed or timed out`.
6. **Suspend reconnect**: screen off 2 min, then 10 min, then wake. Wi-Fi is still connected, or reconnects within
   ~10 s. Check `dmesg` for ath10k WoW/`wmi` errors. Compare the connected MAC with the per-network randomized MAC
   (Settings privacy setting) and with the persist MAC `7c:b3:7b:99:40:46` when "device MAC" is selected (H28).
7. **Radio off case**: with `persist.vendor.a6l.radio=0`, the Wi-Fi toggle must fail cleanly (log `wlan0 absent and
   persist.vendor.a6l.radio!=1`) with no system_server crash loop.
8. **Hotspot** (after 1–6 pass): enable tethering with Wi-Fi on. STA goes down, then hostapd starts on wlan0 (AP),
   `iw dev` shows `type AP`, a client associates, and gets DHCP + Internet over mobile data (IPA). Also test 2.4 and
   5 GHz, and turning the hotspot off returns to STA. Then capture `iw phy` ("valid interface combinations" and
   "Supported interface modes") and `iw list | grep -A8 combinations`. Only then decide whether to add STA+AP
   (needs `wifi_virtual_interface_create`) or P2P.

## 6. Offline evidence (WSL, relay `wh-01…wh-62`)
* `wifi/hal/compile-check.sh /home/a6l/android/a6l-lineage24 …` → **A6L_WIFI_HAL_COMPILE PASS**. The tree's clang
  r596125 with the global soong cc flags from the tree's last ninja, `-Wall -Wextra -Werror`, target
  aarch64-linux-android37. `lib_driver_cmd_a6l` was compiled with wpa_supplicant's own ninja cFlags, both with and
  without `-DCONFIG_DRIVER_NL80211_QCA`. The `wifi_feature_flags.cpp` of the AIDL HAL compiles with our
  `WIFI_HAL_INTERFACE_COMBINATIONS` as one `-D` argument. Every libnl/libcutils symbol that `libwifi-hal-a6l` imports
  is exported by the tree's built `vendor/lib64/libnl.so` and `libcutils.so`.
* `wifi/hal/tests/host-test.sh` → **A6L_WIFI_HAL_HOST_TEST PASS** (g++ with ASan/UBSan, fake `/sys/class/net`, fake
  properties). Covered:
  * the driver-ready gate: radio off gives UNKNOWN, missing gives TIMED_OUT, it waits for `ready`, and no property
    means proceed;
  * 3 start/stop cycles, a synchronous cleanup handler, and a late event-loop start;
  * interface filtering (rmnet ignored) and stable handles;
  * checks that link-stats/APF/virtual-iface/keep-alive are not faked.
  The nl80211/ethtool paths need a real cfg80211 phy (attended).
* `rom/tests/test-a6l-radio-start.sh` → PASS (new check: `vendor.a6l.wlan.state ready`). `rom/tests/test-rom-static.sh` → PASS.

## 7. Risks / open
* The Lineage tree copy (`device/hisense/a6l`, 25 Sep) does not yet have `wifi/`. The pipeline must sync the device
  dir before `m`.
* No gscan / link-layer stats / RSSI monitor from this HAL is normal for a minimal HAL. Screen-off PNO in current
  Android goes through wificond (nl80211 scheduled scan), not this HAL. Whether WCN3990 firmware advertises
  `sched_scan` shows in `iw phy` (§5 step 8); §5 step 6 is the real test of screen-off reconnect.
* Country: the STA path depends on the new private lib (COUNTRY). If `REQ_SET_REG` is rejected (e.g. regdb signature),
  channels stay in world domain. Association still works on non-passive channels.
* SELinux: the ROM is still permissive. The new `get_prop` rule is the only addition this path needs on top of
  system/sepolicy.

## E-ink trial and tradeoff

The mirror supports an explicit --auto-small-regal trial flag. r6t opts into it
in the existing service arguments, retaining user/group/socket permissions.
Only ordinary settled Auto updates with fewer than15% genuinely changed gray
pixels can use retained REGAL partial refresh. A successful current-epoch
quality/REGAL baseline, correct orientation, no active fast burst and satisfied
appearance readiness are required. Exact pixels are counted so large changes
with equal tile averages cannot masquerade as tiny damage.

Initial images, post-A2 cleanup, large page changes, explicit refresh modes,
manual refresh and failure/ACK recovery keep their established paths. Small
REGAL updates do not increment the full-quality-clean counter; a due clean is
deferred while only small changes continue. This can defer cleanup indefinitely
and leave ghosting. The15% threshold is a proposed trial value, not a recovered
stock constant. Manual refresh and larger changes retain cleanup.

Independent review and real-source host/sanitizer/private-queue fixtures pass,
with nine complete fake-daemon scenarios per host/sanitizer build including
ERR, actual reply timeout, manual refresh, epoch/readiness and resynchronization.
The final source passed372 helper assertions; independent review reran368 of
them. Strict arm64 NDK compilation passed. The retained stock generator in
QEMU produces39 frames for quality→REGAL→REGAL→quality on these minor rasters;
post-A2 forced quality remains79. Partial refresh may be less intrusive but is
not a promised FPS improvement or an optically validated flash-free mode.

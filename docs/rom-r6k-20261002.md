# A6L r6k candidates — follow-up to r6j physical tests

Built, verified and installed on 3 October after the user reported r6j remained
usable after an overnight sleep, with a delayed wake. Android validation follows.

## Physical r6j feedback

Pierre reports no garbled text, no Display Settings crash, and usable hardware
graphics. E-ink now fills the screen with no white side bars. Page changes are
faster but still take about 3–4 seconds, far from stock's roughly one second.
Camera closes with a critical unknown error. Light/dark changes work but happen
about one second after the newly selected screen becomes visible. Rear wallpaper
is still the LCD wallpaper; a white override had not been implemented in r6j.

The requested E-ink tab must contain all controls directly, rather than one entry
leading to a second page. The candidate embeds standard Settings preferences
backed by a permission-protected provider in the persistent controller process,
so that the existing appearance controller retains ownership of its preferences.

## Validation and screen readiness details

Inline settings provider access is protected by WRITE_SECURE_SETTINGS, including
an explicit call() permission check. Its closed setting/value contract passes
81 boundary checks. E-ink controls refresh only while their tab is foreground;
updates stop on pause/view destruction. Hardware-button screen changes do not
leave the switch command relying on a cached target. Both English and French
resources, provider registration and existing privileges pass 46 app checks.

The actual white-layer methods pass 15 cases for hidden initial creation, ordered
rapid switches, rotation, parent replacement and cleanup. Wallpaper and layout
changes use the same pending WM transaction, preventing an older queued show
from overwriting a later hide. Readiness checks both sequence and wallpaper mode.

After local/global night configuration matches, WM requests sequence-tagged new
buffers through BLAST, serialized behind existing transition syncs. Activity/token
subtrees include windows replaced by theme relaunch; live wallpaper is excluded.
The merged redraw transaction's valid present fence must signal before frame
readiness is published. Fence waits run on a dedicated worker with a 500 ms bound;
WM group/deferred-start bounds are 1.5 seconds. Invalid/disabled/timed-out fences,
stale sequences, changed wallpaper and group/commit timeout never claim success.
Native preparation has a bounded fail-open path, so failed preparation does not
leave both screens dark indefinitely. Actual redraw-helper fixtures pass 26
failure/ordering cases. This does not establish that the phone's HWC returns a
usable present fence; the next physical logs must confirm that capability.

The camera candidate rebuilds only the HAL metadata dependencies, retaining the
signed IPA and libcamera core byte-for-byte. E-ink algorithms preserve output and
physical timings: 1,536 full-image comparisons, 33,554,432 integer blend values,
56 packed-image comparisons, sanitizer/emulated ARM64 tests and service suites
pass. These are correctness/offline results, not measured phone speedups.

## Physical feedback, 3 October

The E-ink tab crashes Settings. Captured exception is a null TextView in
AndroidX SeekBarPreference.onBindViewHolder: its expected value-label view is
absent from the Settings slider layout. Direct controls therefore remain
unaccepted. The corrective candidate uses Settings' own labeled slider.

Camera still closes with a critical unknown error. Unlike r6j, r6k reaches
active repeating capture; the new provider abort rejects 'Discontiguous planes'
in generic_camera_buffer.cpp. Minigbm image-plane descriptors must be imported
using their actual strides, offsets and image FD slots rather than treating
all handle FDs as independent packed image storage.

User confirms theme changes precede target screen illumination, but switching
takes about three seconds. Saved preparation logs show repeated three-second
fail-open paths. Rear updates sometimes show irregular horizontal black shapes
before the correct frame about one second later. Home-page swipes and both
notification/Quick Settings drawers must suppress animations on E-ink and
restore LCD behavior. Physical wake takes about ten seconds. Recorder playback
and now UI sounds are silent; microphone waveform alone remains insufficient
to establish usable capture. Audio routing and mute/volume need fresh snapshots.

The saved kernel stream reaches s2idle at 577.636946 seconds, after a brief
earlier suspend exit; USB then disappears. No GPU fault/hangcheck precedes that
entry. Remaining live diagnostics require an awake USB connection, requested
without a restart so the current boot evidence can be retained.

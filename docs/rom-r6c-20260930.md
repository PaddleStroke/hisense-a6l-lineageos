## 1. Display: `vendor.graphics.allocator` exits 1 at every start (root cause, from source)
Evidence (r6b kmsg): the whole display stack comes up (`[drm] Initialized msm 1.13.0 for 5000000.gpu on minor 0` at 32.64 s,
`renderD128 -> EGL mesa`, `[drm] Initialized msm-kms 1.13.0 for c901000.display-controller on minor 1` at 33.22 s, both DSI
connectors connected), then from 102.4 s `Service 'vendor.graphics.allocator' (pid N) exited with status 1`, 74 times; its
`onrestart restart surfaceflinger` SIGKILLs surfaceflinger and zygote in a loop.
- The DRM devices on the phone are `renderD128`/`card0` = driver `msm` (GPU only, `separate_gpu_kms=1`) and `card1` =
  `msm-kms` (DPU). No simpledrm (a6l_simplefb is only the LCD fallback).
- `external/minigbm` (Lineage 24 tree, `ce79bbee`): `cros_gralloc_driver.cc init_try_nodes()` opens renderD128.. then card0..;
  `drv.c drv_get_backend()` picks the backend whose name equals `drmGetVersion()->name`. The backend list has `backend_msm`
  only `#ifdef DRV_MSM` (drv.c, msm.c); the generic library (`libminigbm_gralloc`, `cflags: generic_cflags`) is built without
  it, and no dumb backend is called `msm`/`msm-kms`. -> no backend -> `drv_create` fails -> `Failed to initialize driver`
  -> `Main.cpp` exits 1. The composer then finds no IAllocator.
- Why it worked before: the 21 Sep V71 run (`diagnostic/framework-phone-v71.sh`) insmodded `a6l_simplefb.ko` -> the allocator
  used the simpledrm card (our recorded minigbm patch); QEMU uses the same simpledrm path. The ROM is the first run with the
  real msm-kms display and no simpledrm.
- **Fix** (`device/hisense/a6l/a6l-software-graphics.mk`, the product's only graphics makefile, inherited by
  lineage_gsi_a6l.mk): `$(call soong_config_set,minigbm,platform,msm)`. `external/minigbm/Android.bp` `minigbm_defaults`
  selects `msm_cflags` (`-DDRV_MSM -DHAS_DMABUF_SYSTEM_HEAP -DQCOM_DISABLE_COMPRESSED_NV12`) for every minigbm library, so
  the same `libminigbm_gralloc` used by `android.hardware.graphics.allocator-service.minigbm` AND by `mapper.minigbm` gets the
  msm backend; all dumb backends (simpledrm, virtio_gpu, vkms) stay, so QEMU and the simplefb fallback are unchanged.
  Mapper: `ro.hardware.gralloc=minigbm` = `mapper.minigbm` (unchanged, same library).
- Buffers: allocated on renderD128 with `DRM_IOCTL_MSM_GEM_NEW` (`MSM_BO_WC|MSM_BO_SCANOUT`), exported as dma-buf; freedreno
  imports them on its own render fd, the composer imports them into card1 by PRIME. **Linear only**: `ro.hardware.vulkan=pastel`
  makes cros_gralloc add CPU usage to every GPU buffer (`is_running_with_software_rendering`), and the new
  `vendor.minigbm.debug=nocompression` (`drv.c` reads `vendor.minigbm.debug`) disables the a6xx-layout UBWC modifier outright
  (Adreno 512 is a5xx; a5xx UBWC in Mesa/DPU not verified).
- **Composer checked from source, no change needed**: drm_hwcomposer `ResourceManager::Init()` walks `/dev/dri/card%`
  (`vendor.hwc.drm.device` is not set anywhere in our tree); `DrmDevice::IsKMSDev()` requires crtcs+connectors+encoders, so
  the GPU-only card0 is skipped and card1 (msm-kms) is the display device; the allocator opens the render node, so it never
  competes for DRM master.
- Verified offline: build `strings libminigbm_gralloc.so` has `DRM_IOCTL_MSM_GEM_NEW failed` (msm backend) and `simpledrm`
  (image check); QEMU: allocator started once, registered IAllocator, 0 exits in 5 runs (Test-RomV1Qemu now FAILS on any
  allocator exit, `allocator_exits`); QEMU boot_completed not reached today for r6b nor r6c (webview timing, §7.1).
- **Not verifiable offline** (first boot will tell, logcat is now persisted): GEM allocation with MSM_BO_SCANOUT on the GPU
  device, DPU scanout of GPU-allocated linear buffers, freedreno a5xx import. Fallback if the msm path misbehaves (not built):
  a dumb backend named `msm-kms` (`INIT_DUMB_DRIVER_WITH_NAME(msm_kms, "msm-kms")` in dumb_driver.c/drv.c + the
  simpledrm-style drmDropMaster in init_try_node, since card1 is the composer's master) = dumb buffers on card1, i.e. the
  V71 simpledrm data path on the real display. EGL=angle does not help: allocation fails before any EGL.

## 2. USB: adbd runs, the UDC is never bound (root cause, from source)
Evidence (r6b kmsg): early-boot gadget action at 102.05 s without a failed command (configfs + FunctionFS mounted), gadget
HAL started 103.19 s, early-adb rule `start adbd` 103.25 s (adbd pid 1210, never exits), usbd (pid 1309) at 104.87 s:
`ctl.start adbd` + IUsbGadget lookup; **no** `sys.usb.ffs.ready=1` action ever ran; then only
`udc a800000.usb: soft-connect without a gadget driver` every ~18.7 s (charge guard).
- usbd (`system/core/usbd/usbd.cpp`): `persist.sys.usb.config=adb` -> `ctl.start adbd` + `setCurrentUsbFunctions(ADB, timeout 0)`.
  Our HAL sets `vendor.a6l.usb.hal=1` on that first call -> init's early-adb rules (gated by `hal=0`) are off from then on.
- adbd (`packages/modules/adb daemon/usb_ffs.cpp open_functionfs`) writes the descriptors, **then** sets `sys.usb.ffs.ready=1`
  (ep1/ep2 appear). In r6b that did not happen inside the 1.6 s before usbd's call. QEMU r6c shows why it can take long: init
  runs property-trigger actions behind the queued boot actions (exec_start chains): adbd started 155.7 s, the ffs.ready rule
  ran at 166.7 s.
- So the HAL owned the binding, and **the HAL cannot write the gadget**: its service runs `user system`, but configfs creates
  every attribute root:root 0644 (`fs/configfs/inode.c configfs_new_inode`: no inherited owner, `set_default_inode_attr` only
  sets the mode) and the UDC's `soft_connect` is `DEVICE_ATTR_WO` = root 0200 (`drivers/usb/gadget/udc/core.c`, r5 tree).
  `Gadget::apply()` fails at its first write (`idVendor`, EACCES), `setFunctions` returns ERROR, nothing is linked or bound,
  and nobody else will bind either. The host tests never saw it (fake tree writable).
- **Fixes**:
  1. `rom/init/init.a6l.usb.rc` (early-boot): `chown system system` for exactly the files the HAL writes: g1/`UDC`, `idVendor`,
     `idProduct`, `bDeviceClass`, `bDeviceSubClass`, `bDeviceProtocol`, `configs/b.1/strings/0x409/configuration`, and
     `/sys/class/udc/a800000.usb/soft_connect` (+ `chmod 0220`). Links go into `configs/b.1` (shell 0770, HAL has group shell).
  2. HAL `a6l_gadget_core.cpp`: **adopt** - if the gadget is already bound with exactly the requested composition (idProduct
     + ordered f* link targets, `Gadget::matches`) it is taken over without unbind (usbd's boot call no longer tears down an
     early-adb session). **Hand back** - a composition that cannot be written (unbind/unlink/ids/links fail) returns the new
     `kApplyFailed`; `UsbGadget.cpp` then sets `vendor.a6l.usb.hal=0`, so init's early-adb rules bind adb again (also on a later
     `sys.usb.ffs.ready=1`). `udc()` ignores a `sys.usb.controller` absent from /sys/class/udc; bind errors are rate-limited
     (1st, then every 100th) with a 2 s back-off after 10 failures (QEMU r6c first build logged 562 identical lines).
  3. init: `on property:init.svc.adbd=restarting && vendor.a6l.usb.hal=0` -> `setprop sys.usb.ffs.ready 0` (an adbd crash
     before the takeover otherwise leaves ffs.ready=1 and the bind rule never runs again).
  With these, adb comes up with only init + adbd (early rule), or init + adbd + usbd + the HAL (the HAL binds as soon as
  ep1/ep2 exist); system_server is not needed.
- **Charge guard** (`power/rom/a6l-chg-guard.sh`, Q6): it writes `soft_connect` only when a gadget is bound (UDC `function`
  non-empty) at this AND the previous evaluation (never while one is being bound), and writes `connect` only to undo its own
  `disconnect` (the gadget owners - init rule / HAL - pull up themselves after each bind). r6b's error every ~19 s is gone.
- Tests: `usb/tests/run-host-tests.sh` **A6L_USB_HOST_TESTS PASS** (141/141 x3, ASan/UBSan; new: adopt an init binding with
  timeout 0 without touching UDC/pull-up, re-bind after adbd restart, no adoption of a different composition, EACCES ->
  kApplyFailed, unbind impossible -> kApplyFailed, missing UDC rate-limited); `check-usb-wiring.sh` **51/51** (new: every
  HAL-written file chowned, HAL user system, hand-back, adopt; two stale pipeline regexes fixed); `check-usb-syntax.sh` PASS;
  `power/test/sim-power.sh` **A6L_POWER_SIM PASS** (new Q6 cases).
- Not changed: sepolicy for an enforcing build (hal_usb_gadget_default on configfs/sysfs_udc) - builds are permissive.

## 3. First-boot format: 28.5 s of discard (fixed)
r6b kmsg: `fs_mgr_do_format: Format /dev/block/by-name/userdata` 5.82 s, `mke2fs 1.47.2` 5.88 s, `Discarding device blocks`
until **34.43 s**, the whole format 0.3 s after that. `system/fs/fs_mgr/fs_mgr_format.cpp format_ext4()` runs

unless the profile says `discard = false` (`misc/mke2fs.c`: `discard = get_bool_from_profile(fs_types, "discard", discard)`;
profile = `$MKE2FS_CONFIG` or `/etc/mke2fs.conf`).
- **Fix**: `/vendor/etc/mke2fs.a6l.conf` (`rom/vendor-etc/mke2fs.a6l.conf` = the built `/system/etc/mke2fs.conf` + `discard =
  false` in `[defaults]`); `init.qcom.rc on fs`: `export MKE2FS_CONFIG /vendor/etc/mke2fs.a6l.conf`, `mount_all`, `export
  MKE2FS_CONFIG /system/etc/mke2fs.conf` (init's `export` = setenv in init, inherited by the mke2fs fork; restored so vold keeps

- **`discard` mount option kept** on /data and /metadata: it is the stock /data option on this eMMC (stock vendor

## 4. Persistent boot log: logcat, getprop, ps; and /metadata was FULL
Found while reading the r6b metadata copy (laptop `~/r6b-meta2/meta.img`, e2fsck'd): ext4 with a **4 MiB journal** (1024 of
2560 blocks; mke2fs default below 32768 blocks) and 1348 blocks of overhead -> ~4.6 MiB usable; r6b's log (8 MiB cap per boot
+ a whole `.prev`) left **51 free blocks**, and aconfig's `platform_storage_records.pb` / `mainline_storage_records.pb` were
**0 bytes** (and the next boot's log stopped at 16 KiB). The requested "<= 7 MiB" does not fit; the budget is now 3 MiB.
- `rom/debug/a6l-bootlog.sh` (userdebug/eng only, service `a6l_bootlog`, su, permissive), started **`on fs` right after
  `mount_all`** (`init.a6l.bootlog-debug.rc`; parsed after the imported init.qcom.rc, so its `fs` action runs next), no longer
  at post-fs. Layout `/metadata/a6l/`:
  - `cur/kmsg.aaa, .aab, ...` = `/dev/kmsg` from 0 s (log_buf_len=4M) through `split -b 256K`; keep the first 2 + last 2 segments.
  - `cur/logcat.aaa, ...` = `/system/bin/logcat -b all -v threadtime` (stdout, flushed per read batch; `-f` would be
    stdio-buffered), started when `logd.ready=true`, restarted if it exits; keep first 1 + last 2 segments. (Streaming instead
    of `logcat -d` every 5 s: nothing is lost when a ring wraps between two dumps, and far fewer eMMC writes.)
  - `cur/props.txt`, `cur/ps.txt`: `getprop`, `ps -A -o PID,PPID,USER,S,RSS,WCHAN,TIME,CMDLINE` every 30 s (latest only).
  - `cur/bootlog.txt`: start/stop, dropped segments, D-state stacks (30 s / 90 s while the display group runs) - sysrq-w into kmsg.
  - `cur/pstore/`: last 128 KiB of up to 4 /sys/fs/pstore files (previous boot's ramoops).
  - `prev/` = the previous boot, trimmed when rotated (kmsg 1+2, logcat 1+1, no pstore). r6b's `boot-kmsg.txt` -> last
    256 KiB as `prev/kmsg-r6b.txt`; `boot-kmsg.txt.prev`, `pstore-prev/` deleted.
  - Budget: cur <= 7 x 256 KiB + snapshots + pstore tails; `du /metadata/a6l` > 3072 KiB or `df` free < 1024 KiB -> delete
    `prev/`, then stop logcat + snapshots (kmsg continues, bounded).
- QEMU r6c (read from the disk image during the run): `cur/kmsg.*` 4 segments, `cur/logcat.*` from `--------- beginning of main`,
  props 35 KB, ps 31 KB, free 467 blocks (1.8 MiB) with ~2.1 MiB of logs (§7.1).
- Tests `rom/tests/test-rom-static.sh` B9 + B12-B15 (functional runs of the script with shims: stream order, head/tail
  segments, logcat after logd.ready, snapshots, pstore, rotation/trim, r6b migration, low-free and size-cap budget paths).
- Read-out tool (laptop, attended): `tools/read-metadata-bootlog.sh` (§8), host test `tools/tests/test-read-metadata-bootlog.sh`

## 5. Update tool: `adb exec-in 'cat > node'` truncated the tail (fixed)
`tools/RomUpdateAdbV1.py AdbRecoveryDevice.program()` now re-chunks the engine's stream into <= 256 MiB chunks (MiB-aligned
offsets): local temp file -> `adb push` to `/tmp/a6l-upd-chunk` -> `toybox sha256sum` on the phone must equal the laptop sha
(else STOP, nothing written for that chunk) -> `toybox dd if=chunk of=<partition node> bs=1M seek=<MiB> conv=notrunc` ->
the written range is read back on the phone (`dd iflag=skip_bytes,count_bytes | sha256sum`) and compared -> chunk removed;
after the last chunk: sync, flushbufs, drop_caches (the engine's full readback follows as before). A payload shorter/longer
than the range is refused. Never `exec-in`, never the whole-disk node. Kept: adb state `recovery` accepted
(Run-LaptopRomUpdate-v1.py) and the exec-out marker in `read()`.
Tests `tools/tests/test-rom-update-keepdata.py` **ROM_UPDATE_TESTS PASS 14/14** (fake adb now implements `push` and refuses
`exec-in`; new `adb_chunked_program`: 1 and 4 chunks from odd-sized stream pieces land byte-exact, a chunk corrupted in transit
is refused before its dd with the partition unchanged, a short payload is refused).

### 8.3 Read the logs of any boot (from the V75 recovery; read-only on the phone)
Force off (hold Power ~15 s), Power+Vol-down -> V75 recovery (`adb devices` = HLTE730T-PROBE recovery), then on the laptop:
```
cd ~/A6L-usb-20260915/rom-r6c
bash extra/read-metadata-bootlog.sh logs/meta-r6c-1        # -> META_READ_OK
```
It does exactly the manual steps below (use them if the script is not at hand):
```
adb -s HLTE730T-PROBE shell 'T=/system/bin/toybox; $T grep -q "^sdhci_msm " /proc/modules || { $T insmod /sdhci-msm.ko; $T sleep 6; }; for b in /sys/class/block/mmcblk*p*; do $T grep -qx PARTNAME=metadata $b/uevent && $T cat $b/dev; done'
                                                    # -> MAJ:MIN of mmcblk1p40 (use the printed numbers below)
adb -s HLTE730T-PROBE shell '/system/bin/toybox mkdir -p /dev/block/a6lmeta; /system/bin/toybox rm -f /dev/block/a6lmeta/md; /system/bin/toybox mknod /dev/block/a6lmeta/md b MAJ MIN'
adb -s HLTE730T-PROBE exec-out '/system/bin/toybox printf A6L_META_BEGIN_7d41; /system/bin/toybox cat /dev/block/a6lmeta/md 2>/dev/null' > raw.bin
python3 -c "d=open('raw.bin','rb').read();m=b'A6L_META_BEGIN_7d41';i=d.find(m);open('meta-orig.img','wb').write(d[i+len(m):]);print(len(d)-i-len(m))"   # 10485760
cp meta-orig.img meta.img; e2fsck -fy meta.img      # replays the journal of a boot that died (on the COPY)
mkdir dump; debugfs -R 'rdump /a6l dump' meta.img
cat $(ls dump/a6l/cur/kmsg.* | sort) > kmsg.txt; cat $(ls dump/a6l/cur/logcat.* | sort) > logcat.txt
cat dump/a6l/cur/bootlog.txt; less dump/a6l/cur/props.txt dump/a6l/cur/ps.txt
```
`cur/` = the last boot, `prev/` = the one before (trimmed); `bootlog.txt` lists dropped middle segments (a segment boundary
may cut a line). First reads:
```
grep -a -E "A6L_STAGE|graphics.allocator' \(pid|surfaceflinger' \(pid|zygote' \(pid" kmsg.txt | tail -20
grep -a -E "minigbm|gralloc|allocator|SurfaceFlinger|hwc|drm_hwcomposer|EGL|freedreno" logcat.txt | head -60
grep -a -E "usb.gadget-service.a6l|adbd|UsbDeviceManager|sys.usb" logcat.txt kmsg.txt | head -40
grep -a -E "soft-connect|A6L_CHG_GUARD usb" kmsg.txt | head
```
Copy `logs/meta-r6c-*` to the desktop `captures/`.

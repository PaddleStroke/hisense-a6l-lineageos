# Password-free routine A6L operations

The user explicitly requested permanent access without repeated sudo prompts,
and entered the Ubuntu password through the prepared Windows launcher. No
password is embedded in scripts, configuration, or reports. The existing SSH
key remains the login mechanism; no permanently open SSH connection is needed.

## Installed scope

* `/etc/udev/rules.d/99-a6l-access.rules`: direct owner access for user
  `pierrelouis`, restricted to the spare's established physical port `3-2` and
  known Android, EDL, fastboot and diagnostic-gadget identities. The Android,
  fastboot and gadget rules also match serial identity. EDL has no reliable
  USB serial at enumeration; the flashing worker still checks the full Sahara
  identity before uploading its programmer. No blanket USB rule is installed.
* `/usr/local/sbin/a6l-host-control`: root-owned isolated Python helper. Its
  only arguments are `status`, `pause`, or `resume`; it runs no project code
  or phone commands. It manages only fwupd and ModemManager, checks for busy
  firmware/modem activity, records its own runtime masks under a root-only
  `/run` directory, and restores previous service states. It refuses to resume
  services while development USB is present.
* `/etc/sudoers.d/a6l-host-control`: NOPASSWD only for those three exact helper
  invocations, for `pierrelouis` on `system76-pc`. General sudo still requires
  a password. No login password, global timeout or firewall setting changed.

All three files are root-owned and not writable by `pierrelouis`. The helper
uses a fixed environment, absolute command paths, strict arguments and an
exclusive runtime lock. USB/flashing scripts now run as the ordinary user.

The initial installation rolled back after requiring an exact USB mode of
0600. An earlier Ubuntu rule preserves plugdev group access at 0660. The
corrected installer verifies direct owner read/write and no world access,
preserving that pre-existing group policy. The corrected installation passed.

## Verified results

Desktop records: `logs/host-access-install-v2.json` and
`logs/host-access-verification-v1.json`.

* Helper status succeeds with `sudo -k -n`, so it does not depend on a cached
  sudo credential.
* Ordinary `sudo -k -n /usr/bin/id` and helper arguments beyond the allowed
  form are denied without a password.
* A real helper pause/status/resume/status cycle passed, returning both
  services to their original active state.
* The ordinary user can open the spare's current Android USB node for read
  and write. No USB data was transmitted in that permission check.
* The adapted worker/import/payload/XML checks passed without accessing USB.
  The known Linux programming protocol remains byte-for-byte unchanged.
* Android remains booted; there was no phone reboot or flash during setup.

EDL and diagnostic-gadget rules take effect on future enumeration. Actual
unprivileged EDL programming has not yet been physically tested. The next
trial must confirm access and all existing pre-write checks before writing.

## Tools for subsequent trials

The laptop and desktop now have `*-user-v1.py` variants of the V12 worker,
offline inspector, install, restore and capture coordinators, generated by
`Prepare-UnprivilegedA6LTools.py`. All their one-shot capture directories are
unused. The source and generated hashes are in
`tools/a6l-user-tools-v1-manifest.json`.

These variants remove interactive `sudo -v`, run workers and the collector
without sudo, and use only the fixed helper for host-service changes. They
retain the existing device, partition, payload, timeout and readback checks.
They still reference V12's image; prepare a new version explicitly before
testing a changed kernel. Do not launch the old root-based coordinators and
expect the new policy to suppress their prompts.

For a future unrelated administrator task, sudo may still ask for a password.
The Windows `.cmd` launcher used here is specifically a one-time installer,
not a general root console; rerunning it will stop at the existing report.

## Reversal

First inspect `sudo -n /usr/local/sbin/a6l-host-control status` and, once the
phone has returned to Android, resume any owned pause. With normal sudo
authorization, remove only the three installed files listed above, then run
`udevadm control --reload-rules`. On the next device enumeration, the previous
USB rules apply. Removing the sudoers file restores the prior sudo policy.

References: Ubuntu's [sudoers manual](https://manpages.ubuntu.com/manpages/jammy/man5/sudoers.5.html)
documents command-specific NOPASSWD matching; systemd's
[udev manual source](https://cgit.freedesktop.org/systemd/systemd/tree/man/udev.xml)
documents device matching and owner/mode assignments.

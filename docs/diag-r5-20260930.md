# diag-r5: diagnostic boot images + module test kit for the r5 msm freeze (30 Sep 2026)

Offline work only: no adb/fastboot/EDL, nothing written to the phone. The laptop was used only to stage and check the kit.
Kit: laptop `~/A6L-usb-20260915/diag-r5/` (WSL `/home/a6l/diag-r5/kit`), KIT-SHA256SUMS `ec2ced04…`, phone set SHA256SUMS `6a12095c…`.

## 1. Why (and one correction to the r6b reading)
- r6 and r6b both show `A6L_ROM display: insmod msm.ko ...`, the two adreno dummy-regulator lines, then a black LCD (backlight on).
  The black LCD alone proves nothing: the console is earlycon on the splash buffer, and MDSS takes that path over during msm probe.
- **r6b does not prove a freeze.** USB/adbd start in early-boot, after `mount_all`, and `mount_all` was still formatting the
  110 GB userdata (started 5.8 s, still running at 30 s, see §7). So r6b had no USB whether or not msm froze.
  r6 is the real evidence: its display group was an early-init `exec_start`, so init stopped behind the insmod (msm, or a
  later module / the LCD wait of that group).
- The same list works on V67 from the V74/V75 recovery. Between that and r6 there are 4 differences: kernel config (r5/r5p),
  module rebuilds, the ROM DT, and the ROM context (base group, ueventd, early timing, eMMC load). The images below separate
  them one at a time, with a live kernel log on the laptop.

  (GPU firmware of the proven bundles), `SHA256SUMS` (checked on the phone). Provenance: `provenance-r5.txt`, `provenance-v67.txt`.
- `d.sh` steps (every action goes to kmsg BEFORE it runs, prefix `A6L_DIAG`):
  `setup` (debugfs, sysrq=1, printk 8, softlockup/hardlockup panic 0 + all-CPU backtraces, watchdog_thresh 5, printk
  ratelimit off, firmware to /lib/firmware, pstore copy, heartbeat `A6L_DIAG hb <uptime>` every 2 s),
  `pre` (display list up to drm_dp_aux_bus + snapshot), `msm [params]` (always `separate_gpu_kms=1`),
  `gpuoff` / `dispoff` (driver_override on `*.gpu` / `*.display-subsystem`), `panels`, `one <ko>`, `rom` (base + whole display
  list in ROM order), `snap <tag>` (modules, deferred, genpd, clk/regulator/interconnect summaries, gpu/mdss/iommu state),
  `ioload [s]` (READ-only userdata read load, like r6b's mke2fs), `status`, `pstore`.
  Each insmod runs in the background and is watched: at 15/45/120 s without return: `STUCK` line (wchan, state), `/proc/pid/stack`,
  sysrq-w and sysrq-l. DETECT_HUNG_TASK is off in all kernels, so this is the only hung-task report.
  Env: `A6L_DIAG_PAUSE` (s before each insmod, default 2), `A6L_DIAG_NOKFENCE=1` (sample_interval=0 before loading),
  `A6L_DIAG_MODS` (force a module dir).
- msm params used for the bisect: `skip_gpu=1` = adreno driver not registered (display only); GPU only = `dispoff` then msm
  (`modeset=0` is not usable: the whole module returns -EINVAL).
- `host/`: `diag-stream.sh <name>` (adb `dmesg -w` → `logs/<name>-<UTC>.log`, laptop timestamps, reconnects after a reboot),
  `diag-push.sh`, `diag-run.sh <step> [args]` (starts the step detached with setsid; `DIAG_ENV=` for env),
  `diag-pull.sh <tag>` (snapshots, kit log, pstore-prev, dmesg → `logs/<tag>-<UTC>/`), `diag-bootwrite.sh` (§6).

## 5. Root-cause hunt on the r5 delta (task C)
### 5.1 msm.ko r5 vs V67
- Same source: the V67 bundle msm `306084b0` and r5 `971ff205` define the same functions (2240 vs 2242; `a6xx_snapshot_gmu_bo`
  and `vm_op_enqueue` are only no longer inlined). Size deltas are +44 B in list-handling functions (LIST_HARDENED inline
  checks) and 28nm PLL/PHY duplicates. New imports: `__list_*_valid_or_report`, `__check_object_size` (ioctl paths), `__versions`.
- Build flags of `msm_drv.o` identical except `-fmacro-prefix-map` (tree path). The r5 tree = V67 source.patch + the rom-v2
  series, which only touches modules (audio, camss, hi846, smbx, btqca, LPI); so vmlinux r5 vs V67 differs by config only.
### 5.2 Config delta (config-diff-v67-r5.txt) against msm/adreno/iommu/dma/firmware
Same in V67 and r5 (not suspects): INIT_ON_ALLOC/FREE (off in both), STRICT_MODULE_RWX, CFI + SCS, IOMMU_DEFAULT_DMA_STRICT,
ARM_SMMU(_QCOM), QCOM_IOMMU, CMA/DMA_CMA, ZONE_DMA/DMA32, PM_DEVFREQ + governors + DEVFREQ_THERMAL, interconnect, FW loader
(USER_HELPER=y without fallback in both: request_firmware never uses a helper, so STATIC_USERMODEHELPER="" does not matter),
NO_HZ_IDLE/CPU_IDLE (the `NO_HZ n->y` line is the legacy alias; idle config identical), DETECT_HUNG_TASK (off in both).
Ranked suspects (all still hypotheses):
1. **ROM DT** (not config): no display/GPU/MDSS/iommu/clock node differs from V74, but it adds pm660l L2/L5 RPM regulator nodes
   (microSD sdhc_2 now enabled: vmmc/vqmmc), LPG/PWM, flash LED, camss/cci, watchdog, ramoops. Tested by diag-v67-dt6b / diag-r5p-dtv74.
2. **LIST_HARDENED + BUG_ON_DATA_CORRUPTION**: a latent list misuse in msm/drm/component/iommu code becomes BUG() in probe, while
   holding locks (with irqs off -> other CPUs spin -> whole-system hang). K1 turns the BUG into a WARN. The live stream would show
   `list_add corruption` / `kernel BUG at lib/list_debug.c`.
3. **KFENCE**: guard-page objects and a sampling timer; changes where 1 kmalloc per 100 ms lands. Runtime-testable
   (`A6L_DIAG_NOKFENCE=1`) and removed in K1.
4. HARDENED_USERCOPY: only on copy_to/from_user (ioctls), not on the probe path. Low. (`hardened_usercopy=off` exists if needed.)
5. The rest (FS_ENCRYPTION/INLINE_CRYPT, BLK_INLINE_ENCRYPTION, SYSVIPC/FHANDLE, FW_CACHE, PM_WAKELOCKS, ARMV8_DEPRECATED
   emulation, netfilter/crypto/HID, MODVERSIONS, THERMAL delay 0->100 ms (a trip would power off, not hang lit)): no plausible
   link to msm probe. The r5m image tests them all at once.
### 5.3 Kernel variants (2 built, from the unchanged r5 tree; `tools/build-diag-r5-kvariants.sh`, `collect-diag-r5-kvariants.sh`)
| variant | config | Image sha256 | modules |
|---|---|---|---|
| **r5m** (priority 1) | V67 .config + rom-v2 fragment + `configs/a6l-diag-r5m.config` (MODVERSIONS, thermal delay 100, CFI_PERMISSIVE) = r5p minus the whole android fragment (diffconfig in merge.log) | `ee555b875597d6018e0f2e5a82eace2a897316a7b1ecb2f8f3aa2803f3bd2de9` | own: in-tree kit set + OOT tps65185, panel-ft8719, panel-a6l-epd-dsi (epd-v73 source); `firmware/extracted/diag-r5-20260930/kernel-r5m/` |
| **k1** (priority 2) | r5p + `configs/a6l-diag-k1.config` (KFENCE=n, BUG_ON_DATA_CORRUPTION=n) | `b32e1ffb3625fc3694db903cf29cb0d7fdfbd38f4425595013374f2cfc1c19ac` | own set (as r5m). Module.symvers = r5p minus the 2 KFENCE exports, all CRCs equal, and still NOT module-compatible (below) |
**ABI trap found by the QEMU test:** the r5 fuse.ko on k1 fails `__kmem_cache_create_args(fuse_inode) failed with error -22`.
KFENCE=n removes `_SLAB_SKIP_KFENCE` from `enum _slab_flag_bits`, so every later `SLAB_*` bit moves; flags are constants, so
MODVERSIONS/Module.symvers cannot see it. Rule: a kernel config change that touches such enums needs its own module set, even
with an identical Module.symvers. (r5 -> r5p = CFI_PERMISSIVE only, no such change; the QEMU self-test of the r5 set on r5p passes.)
Out dirs `/home/a6l/kernel/out-a6l-diag-{r5m,k1}`. A 3rd variant (LIST_HARDENED/HARDENED_USERCOPY off) changes the module ABI
and needs a module rebuild; build it only if r5m passes and k1 still freezes.

## 7. Separate issue: first-boot userdata format is very slow
r6b: `fs: mount_all` at 5.7 s, the format of userdata (~107 GiB, `formattable`) still running at 30 s, which blocks mount_all and
everything after it (post-fs, the boot log, USB/adbd). fs_mgr runs `/system/bin/mke2fs` without `-E nodiscard`, so mke2fs first
discards the whole partition (the fstab `discard` flag is the separate online-discard mount option). On eMMC a full-device
discard/erase of 107 GiB can take minutes. Proposed fix (NOT applied, ROM unchanged):
1. mke2fs: `discard = false` in the mke2fs profile that fs_mgr's mke2fs reads (e2fsprogs honours a `discard` boolean in
   mke2fs.conf `[defaults]`/fs_types); Android's mke2fs.conf is a system file, so this needs a small override in the tree.
   Alternative: have the installer pre-create the ext4 on userdata (then `formattable` never triggers).
2. /data and /metadata: drop the `discard` mount option (Android's idle maintenance runs fstrim; online discard on eMMC slows
   every delete).
3. Measure first: time of the first-boot format with the r6b log (`A6L_STAGE fs: mount_all` -> `mount_all done`).

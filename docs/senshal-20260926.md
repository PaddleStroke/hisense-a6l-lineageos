## 1. What changed

`android.hardware.sensors@2.0-subhal-impl-1.0` loads it. The sensor list is static, so the sensors exist even if the
ADSP comes up after the multihal.

### How the IIO engine works (`a6l_motion.c`)
It uses the same facts as `a6l_imu`: channels are `le:s32/32`, the timestamp is `le:u32/64`, and there are no `_raw`
attributes.
* **Buffers:** there is one kfifo per physical sensor. It is enabled while any of its handles is active. The poll thread
  does the enable and disable itself: it enables the scan elements, sets length 256 and a watermark, then opens
  `/dev/iio:deviceN` non-blocking. A failure (ADSP late, EACCES) is retried every 2 s.
* **Sample rate:** SMGR always samples at the native maximum. Requested rates are served by decimation per handle.
* **Latency:** `maxReportLatency` only raises the kfifo watermark (≤ 64 samples, half the latency budget). A later
  client that needs lower latency causes a re-enable with watermark 1. `fifoMaxEventCount` = 0 because no FIFO survives
  AP suspend.
* **Flush:** drains the kfifo, then sends `META_DATA_FLUSH_COMPLETE`. Flushing an inactive sensor returns -EINVAL.
* **Units:** scale × raw gives m/s² and rad/s. The magnetometer is gauss × 100 → µT, detected on the first sample
  (|v| < 3 → gauss).
* **Axes:** SMGR NED → Android with `+y+x-z` (Android X = raw y, Y = raw x, Z = −raw z), as in the sens doc.
* **Timestamps:** the SMGR DSP ticks (u32, 32768 Hz) are unwrapped across the 2³² wrap and mapped to CLOCK_BOOTTIME with a
  minimum-latency filter (drift allowance 100 ppm).
  * After 3 s the tick rate is measured. If it is more than 10 % off, the measured rate is used.
  * Timestamps are strictly increasing per sensor and never in the future.
* **Gyro bias:** a stationary detector (1 s windows, sd < 0.01 rad/s, |mean| < 0.05 rad/s, EMA). The calibrated gyro
  subtracts the bias; the uncalibrated one reports it.

### Magnetometer calibration (`a6l_magcal.c`)
* **Point selection:** up to 64 raw points at least 6 µT apart, with ring replacement.
* **Fit:** a linear least-squares sphere fit.
* **Accepted when:** 15 ≤ r ≤ 120 µT, rms < 8 % r, and ≥ 10 of 26 direction bins around the centre are covered.
* **Accuracy levels:**
  * UNRELIABLE (0): no bias.
  * LOW (1): the bias was loaded from file, or the field has left the sphere (EMA of relative deviation > 25 %).
  * MEDIUM (2): a fit covers ≥ 10 bins.
  * HIGH (3): a fit covers ≥ 16 bins with rms < 4 %.
* **Persistence:** `/data/vendor/sensors/mag_bias` holds `A6L_MAGCAL 1 bx by bz r acc`. It is written atomically
  (tmp + fsync + rename), at most every 30 s, and on close.
* **Limit:** a flat table turn alone does NOT calibrate, by design (a plane cannot fix the vertical offset). The user
  must tilt the phone in a figure 8.

### Properties
All are read when the HAL opens; `setprop` and then restart the multihal:

| property | default | effect |
|---|---|---|
| `persist.vendor.a6l.sensors.map` | `+y+x-z` | axis map for all three sensors |
| `….map.accel` / `.gyro` / `.mag` | — | per-sensor override (for example if `a6l_imu turn` says `A6L_IMU_FRAME INCONSISTENT`) |
| `….mag_unit` | `auto` | also `gauss` or `ut` |
| `….magcal` | `1` | `0` turns the calibration off: status UNRELIABLE, bias 0 |
| `….tick_hz` | `32768` | tick rate before it is measured |
| `….motion` | `1` | `0` hides accel/gyro/mag from the list (fallback) |

### Integration (merged in the repo)
* **`rom/rom.mk`:**
  * Trout (`android.hardware.sensors@2.1-Google-IIO-Subhal`) and its `sensor_hal_configuration.xml` are removed.
  * It keeps the multihal and inherits `stk3338.mk`.
  * Feature XMLs: accelerometer, gyroscope, **compass (new)**, light, proximity.
* **`hals/hals.mk`:** same change, and it inherits `stk3338.mk`.
* **`rom/v2/sensors/hals.conf` and `hals/sensors/hals.conf`:** now list only `android.hardware.sensors@2.0-subhal-impl-1.0.so`.
* **`rom/vendor-etc/a6l-unavailable-features.xml`:** the compass line is removed, with a comment explaining how to put
  it back. The camera stays withdrawn.
* **`hals/sensors/sensor_hal_configuration.xml`:** marked OBSOLETE and no longer installed.
* **`rom/vendor-etc/ueventd.rc`:** 4 new `no_fnm_pathname` rules (scan_elements/*_en, buffer/enable, length, watermark →
  0664 system).
  * **Finding:** the existing rules `/sys/devices/*iio:device*` use fnmatch with FNM_PATHNAME, where `*` never
    crosses `/`. They therefore never matched the nested IIO paths. The ueventd sources were checked (devices.cpp: 162
    fnmatch, 183/197 attribute glob).
* **`rom/bin/a6l-modules.sh adsp`:** after the sound-card wait, it waits ≤ 10 s for 3 `qcom-smgr-*` devices, then chowns
  their buffer and scan-element files and `/dev/iio:deviceN` to system. This is the fallback if ueventd does not apply.
  `sh -n` OK.
* **`stk3338.mk`:** installs `a6l-sensors-hal.rc`.
* **SELinux:** no policy yet (the ROM is permissive). An enforcing ROM needs `hal_sensors_default`:
  * `iio_device` chr_file r/ioctl;
  * `sysfs` r/w on the IIO attributes;
  * `vendor_data_file` dir/file rw on `/data/vendor/sensors`.

## 3. Attended test (booted ROM; needs the flash agent's rebuild first)
```
adb shell dumpsys sensorservice | grep -E 'SMGR|STK3338'      # 6 SMGR + 2 STK3338 sensors
adb shell dmesg | grep 'adsp: sensors'                        # 3 lines "qcom-smgr-* -> system"
adb logcat -d -s sensors.a6l                                  # "qcom-smgr-accel on: ... rate=<N> Hz", "mag unit auto: ... gauss"
adb shell ls -l /sys/bus/iio/devices/iio:device*/buffer/enable   # system system (ueventd or fallback)
```
Then Pierre:
1. **Auto-rotate:** rotate the phone; the UI must follow (accel).
2. **Compass:** open a compass app and wave the phone in a figure 8 for about 10 s.
   * Status goes from UNRELIABLE to MEDIUM or HIGH.
   * `cat /data/vendor/sensors/mag_bias` (root) shows the bias.
   * The heading must match a known direction (window or street). If north and south are swapped, or east and west,
     re-run `a6l_imu turn` and set `persist.vendor.a6l.sensors.map.mag`.
3. **Gyro:** `dumpsys sensorservice` shows `Rotation Vector`, `Game Rotation Vector`, `Gravity` and `Orientation`
   (AOSP fusion). A sensor test app shows the gyro ≈ 0 at rest.
4. **Proximity:** a call with the top edge covered turns the screen off (unchanged, stk).

**Rollback without a rebuild:**
* `setprop persist.vendor.a6l.sensors.motion 0`, then restart the multihal; or
* put the compass `<unavailable-feature>` line back.

## 4. Risks / unknown
* **Units and map not measured:** the SMGR units (gauss) and the NED→Android map are not measured yet. The v75/sens
  `flat`/`turn` tests check them, and the properties allow correcting them without a rebuild.
* **Tick rate:** the SMGR timestamp tick rate (32768) is assumed. It is measured at runtime after 3 s, but a wrong
  value gives about 3 s of imprecise timestamps once per enable.
* **Batching:** there is no real batching while the AP is suspended. SMGR indications arrive over QRTR regardless;
  kernel behaviour is unchanged.
* **Stationary threshold:** the gyro bias detector could absorb a very slow constant rotation (< 0.05 rad/s for 1 s).
  The AOSP fusion re-estimates the bias anyway.
* **ueventd:** the `no_fnm_pathname` rules follow the source but are unproven on the phone. The a6l-modules chown is
  the fallback.

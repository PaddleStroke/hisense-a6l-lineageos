# Android HAL/service layer for the mainline A6L (agent `hals`, night 23→24 Sep 2026, offline only)

**Status:** sources, rc files, configs and a vendor sepolicy fragment are in `device/hisense/a6l/hals/`. They cover
hardware already shown on the phone. **Nothing was built with `m`, and nothing ran on the phone.** The `flash` agent
integrates them. The only new native code is `a6l_macs` (C, ~250 lines). It was host-built and tested against fake
persist images. The NDK build and the netns MAC-set test are in relay `hals-06-build.sh`, which was still queued at
hand-off: the relay was busy with another agent's long job. Read `.relay/outbox/hals-06-build.out`.
Approach: plain AOSP default HALs plus the linux-msm companions, as mainline-kernel Android ports do (Linaro db845c:
AOSP `bluetooth-service.default` over HCI_CHANNEL_USER, wpa_supplicant/nl80211, rmtfs/tqftpserv/pd-mapper;
postmarketOS SDM660: rmtfs + qcom-diag + bootmac).
RF rule kept: **the modem starts only when `persist.vendor.a6l.radio.enable=1`**. The default is unset, so the
modem stays off.

## 1. Integration list for `flash`

1. `lineage_gsi_a6l.mk`: `$(call inherit-product, device/hisense/a6l/hals/hals.mk)`.
   `BoardConfig.mk`: `include device/hisense/a6l/hals/BoardConfig-hals.mk`. It adds `BOARD_VENDOR_SEPOLICY_DIRS` and
   the NL80211 supplicant flags.
2. Run `tools/build-radio-userspace.sh`, or make sure `external/linux-msm/{qrtr,rmtfs,tqftpserv}` are in the tree.
   `rmtfs`, `tqftpserv` and `qrtr-lookup` are built from there.
3. `hals-06` copies `prebuilt/diag-router` (radio2 build, sha `bf32c096…`) and generates `usb-gadget/`, which is the
   AOSP gadget example with UDC `a800000.usb` and the module renamed to `android.hardware.usb.gadget-service.a6l`.
   **Check that both exist before `m`.**
4. Merge `rootdir/etc/ueventd.a6l-hals.rc` into the vendor `ueventd.rc` (realinit/flash own that file).
5. Kernel cmdline: `firmware_class.path=/vendor/firmware` (the rc writes it too, as a fallback). The firmware tree is
   the same as in v74/radio2 `firmware/`, under `/vendor/firmware/qcom/hisense/a6l/…`, plus `ath10k/`, `qca/` (BT)
   and `sns.reg`.
6. **Modules** that must be loaded before these services (vendor_dlkm/modprobe, owned by flash): `qrtr qrtr-smd
   qcom_pd_mapper qcom_rmtfs_mem qcom_q6v5_mss` (+ deps from v74/radio2 `modules/order.txt`), `ath10k_core
   ath10k_snoc`, `bluetooth btqca hci_uart` (serdev on `serial1`, V74 DT) + `rfkill`, `qcom_q6v5_pas` (ADSP),
   `qcom_sns_reg qcom_smgr qcom_smgr_accel qcom_smgr_gyro qcom_smgr_mag`, `tmd3702` (v74/als2), fuel gauge/charger
   from power-sensors-prep-20260917.
7. **RAM-container mode** (realinit-launch.sh): add `androidboot.a6l.container=1` to the filtered cmdline. `a6l-usb.rc`
   then leaves configfs alone and the recovery's adbd keeps working.
8. Persist: to read `sns.reg` / `wlan_mac.bin` as files, mount `persist` **read-only** at `/mnt/vendor/persist`
   (fstab). `a6l_macs` also works without the mount: it does a read-only scan of `/dev/block/by-name/persist`.

## 2. Per area

### Modem companions (rmtfs, tqftpserv, pd-mapper, diag-router)
- Files: a6l-radio.rc, rootdir/bin/a6l-modem.sh, prebuilt/diag-router, sepolicy/a6l_radio.te.
- pd-mapper: **in-kernel** (`CONFIG_QCOM_PD_MAPPER=m`), so no daemon, only the module. qrtr-ns: in-kernel on 7.2
  (the QRTR nameservice is in the qrtr module), so no daemon.
- The flow copies run.sh (radio2): **RAM copies** of modemst1/modemst2/fsg/fsc into tmpfs, then rmtfs `-o`, tqftpserv,
  diag-router, the check that diag-router is still alive, then `echo start` to mss. EFS changes are lost at reboot, by
  design (writing them back to the eMMC is Pierre's call).
- Verified offline: `sh -n` on both scripts; the logic matches the run.sh that passed 300 s on 23 Sep. Not built or run as
  init services.
- Attended test (booted ROM or RAM container, **needs Pierre's RF go**): `adb shell setprop persist.vendor.a6l.radio.enable 1`
  (as root), then `adb shell /vendor/bin/a6l-modem.sh status` and `dmesg | grep A6L_MODEM`. Expected: 4× `copy …`,
  `state=running`, diag-router log `A6L_DIAG qrtr modem CNTL client … connected`, no `fatal error received` for 300 s.
  `qrtr-lookup` lists 4097 on node 0 (ours) and node 1. Stop with `setprop persist.vendor.a6l.radio.enable 0`.
- Risks: init starts rmtfs etc. as root (hardening TODO). If the persist property is set, the modem also starts after a
  reboot. That is intended, but Pierre must know it.

### RIL / calls / SMS / mobile data: NOT YET
- The AOSP reference RIL (AT over a tty) cannot drive QMI. No maintained open-source Android RIL for mainline QMI exists
  that I know of. `qcrild`/`libril-qc-*` (stock) need the downstream kernel (IPA/rmnet_ipa, qmi_encdec, diag, smd
  devices) and Android-9 VNDK: not usable. ModemManager/oFono are Linux-desktop stacks. A ModemManager-backed IRadio shim
  would be a large new project (AIDL radio HAL of ~10 interfaces).
- Mobile data also needs **IPA** on SDM660 (IPA v3.1 is not in the mainline sdm630 DT/driver data), plus rmnet. Voice
  also needs the audio path (q6voice), which mainline doesn't have for this SoC.
- Decision: ship **without a radio HAL**. The lineage GSI's telephony framework runs with no IRadio (Wi-Fi-only tablet
  behaviour). Do not declare `android.hardware.telephony.*`. The modem is still worth running: Wi-Fi depends on it (WLAN
  firmware and QMI service 69 live in the modem PD). Candidate later project: a minimal AIDL IRadio built on libqmi
  (UIM/NAS/WMS for SMS, then WDS + a mainline IPA port for data).

### Wi-Fi
- Files: a6l-wifi-bt.rc, wifi/*.conf, BoardConfig-hals.mk (NL80211 supplicant/hostapd), hals.mk packages, `a6l_macs`.
- HAL: AOSP `android.hardware.wifi-service` with `BOARD_WLAN_DEVICE` **unset**, which means `libwifi-hal-fallback`
  (stubs). **Open point:** whether the AIDL wifi service accepts the fallback (it may fail to create a legacy HAL, and
  then Wi-Fi never enables). hals-05 prints `wifi_hal_fallback.cpp` and `wifi_legacy_hal_factory.cpp` to decide. Plan B
  is `BOARD_WLAN_DEVICE := emulator` + `PRODUCT_SOONG_NAMESPACES += device/generic/goldfish`: goldfish
  `libwifi-hal-emu` is a generic nl80211 legacy HAL (Cuttlefish uses it). Plan C is `qcwcn` (hardware/qcom-caf wlan
  HAL, QCA vendor commands are ignored by ath10k).
- MAC: `a6l_macs wlan` reads `Intf0MacAddress=` (mounted `wlan_mac.bin`, or a raw read-only scan of the persist
  partition). It waits up to 120 s for wlan0 and sets the address with SIOCSIFHWADDR **only while wlan0 is down**.
  `ro.boot.wifimacaddr` is not used by any component in this tree (grep), so it was not used here. Caveats: the Wi-Fi
  framework randomises the MAC per network by default, and `getFactoryMacAddress` (ethtool perm addr) still reports
  ath10k's random probe address. A DT/nvmem `local-mac-address` is the only way to fix the permanent address, and it
  does not suit a shared image.
- Verified offline: `a6l_macs` host build `-Wall -Wextra -Werror` clean. Parse tests on a fake 32 MB persist image
  (key straddling a 64 KiB read boundary, decoy placeholder `000AF58989FF` skipped) → `7c:b3:7b:99:40:46` (the real
  value seen on 23 Sep); a missing key gives rc 2, a missing iface rc 3, an UP iface is left alone (rc 4), a multicast
  `-a` is rejected. The SIOCSIFHWADDR path on a dummy wlan0 in a netns is in hals-06.
- Attended test (RF go): modem on as above → `dmesg | grep A6L_MACS` shows `wlan wlan0 set 7c:b3:7b:99:40:46`. In
  Settings, turn Wi-Fi on and scan; the Livebox should be listed. Then `cmd wifi status`, and `logcat -s
  WifiHAL android.hardware.wifi-service wpa_supplicant`. Association is Pierre's choice (credentials).
- Risks: fallback HAL (above); P2P not declared; 23 Sep saw a `wlan_process` crash after an SSR (watch it); board
  file generic (board-2.bin from stock bdwlan, calibration unknown).

### Bluetooth
- Files: a6l-wifi-bt.rc (`vendor.a6l-bt-addr`), sepolicy/hal_bluetooth_default.te, `a6l_macs bt`.
- HAL: AOSP `android.hardware.bluetooth-service.default`. It turns rfkill off, waits for hci0 through the MGMT
  index list, and opens it with **HCI_CHANNEL_USER** (net_bluetooth_mgmt.cpp), as db845c does with the same WCN3990.
  **No btattach/hciattach:** the V74 DT gives the UART the `serial1` alias, and the `qcom,wcn3990-bt` serdev child
  probes hci_uart/QCA by itself (23 Sep: hci0, crbtfw21.tlv + crnv21.bin, "setup on UART is completed"). The run-bt.sh
  sysfs rebind was only a V71 workaround.
- **Found:** WCN3990 reports the QCA default BD address, so btqca sets `HCI_QUIRK_USE_BDADDR_PROPERTY`. There is no DT
  `local-bd-address`, so the kernel keeps hci0 **unconfigured**, and the AOSP HAL only reads the *configured* index list:
  it would wait forever. `a6l_macs bt` sends MGMT `SET_PUBLIC_ADDRESS` (same as `btmgmt public-addr`). The address
  is WLAN MAC + 1 (the usual Qualcomm factory convention; **not checked** against stock NV 447 /
  `persist.vendor.service.bdroid.bdaddr`). Override: `-a xx:..` in the rc.
- Verified offline: build, argument parsing, dry-run. The mgmt code follows `include/net/bluetooth/mgmt.h` opcodes
  (0x0003/0x0004/0x0036/0x0039) but has not run against a kernel: there is no BT socket family in this container.
- Attended test (RF go, BT): `/vendor/bin/a6l_macs bt -x 0 -w 5 -n` → expect `hci0 UNCONFIGURED` (this confirms the
  finding). Then without `-n` → `set 7c:b3:7b:99:40:47`. Turn Bluetooth on in Settings → logcat
  `android.hardware.bluetooth-service.default`: `hci interface 0 found`, `HCI Reset successful`. Scan should list
  nearby devices.
- Risks: on every user-channel open the kernel re-runs QCA setup (NON_PERSISTENT_SETUP); whether the public address is
  re-applied at that open still has to be watched (`dumpsys bluetooth_manager` address). Audio (A2DP/SCO offload) is
  not wired.

### Sensors
- Files: hals.mk (`android.hardware.sensors-service.multihal` + `android.hardware.sensors@2.1-Google-IIO-Subhal` from
  `device/google/trout/hal/sensors/2.1`, the only IIO sub-HAL in the tree), sensors/hals.conf,
  sensors/sensor_hal_configuration.xml (**DRAFT**), rootdir/bin/a6l-sensors.sh, a6l-sensors-misc.rc.
- a6l-sensors.sh (blocking, ≤20 s, before class hal): starts the ADSP remoteproc if needed, waits for accel+gyro IIO
  names, and chowns the IIO attributes and `/dev/iio:deviceN` to system. SELinux permissive does not bypass DAC.
- Open points: (1) the SMGR IIO `name` strings. The XML uses `qcom-smgr-accel`/`qcom-smgr-gyro` as placeholders;
  hals-06 greps the driver, and on the phone run `cat /sys/bus/iio/devices/*/name`. (2) The XML schema: hals-06 runs
  xmllint against trout's XSD and prints trout's sample. (3) Which sensor types trout supports (accel/gyro buffered;
  magnetometer probably not). (4) **TMD3702 (rear ALS/prox) is polled sysfs only, with no IIO buffer/trigger.** The trout
  sub-HAL needs buffers, so light/proximity need either an `iio_triggered_buffer` + hrtimer trigger in tmd3702.c
  (small kernel change, preferred) or our own small sub-HAL. Not done. The front STK3338 never answered.
- Attended test: booted ROM → `dumpsys sensorservice` lists accelerometer + gyroscope. Then rotate the phone: the UI
  auto-rotates if enabled. Axis signs: flat on the table, accel z ≈ +9.8.
- Risks: the multihal starts with no sensors if the ADSP/SMGR are late (the prep waits 20 s). Axis mapping is identity
  until measured.

### Vibrator: NOT included
The kernel has `pm8xxx-vibrator` (=y) and `qcom-spmi-haptics` (=m); both are input force-feedback devices. The tree
has no FF-based AIDL vibrator HAL: Lineage `vibrator-service.legacy` is timed_output/LED, and the AOSP example is a
fake. The motor was **not felt** in the 18 Sep tests. No HAL is shipped (the framework runs without a vibrator), so
the UI does not claim haptics. Next: fix the PM660 haptics DT/drive first, then a ~150-line FF vibrator HAL
(EVIOCSFF + write EV_FF).

### Health / power / thermal
- `health-service.example` reads `/sys/class/power_supply`. On 21 Sep the phone reported voltage, capacity, current
  and temperature through the mainline fuel gauge, so BatteryService should show real %. Test: battery icon % vs
  `cat /sys/class/power_supply/*/capacity`, plug/unplug USB. **Charging policy is the kernel charger driver's
  defaults (smb2/qcom_smbx), with no Android-side control. Thermal:** the example HAL reports fake temperatures and
  there is no thermal mitigation (no thermal-engine). Power: example HAL (no boost). Watch the temperature on long
  sessions.

### USB (dwc3 configfs: adb/mtp)
- a6l-usb.rc + the generated `usb-gadget/` fork (UDC `a800000.usb`; **verify** with `ls /sys/class/udc` on the phone,
  and fix one sed if it differs) + `android.hardware.usb-service.basic` (Lineage, no Type-C role switching). MTP is
  FunctionFS-based (`ffs.mtp`): mainline has no `mtp.gs0`, which is why `sys.usb.configfs=2`.
- Test (installed ROM, not the container): adb works at boot (`sys.usb.config=adb` from
  `persist.sys.usb.config`). In Settings > USB, choose "File transfer": the laptop sees an MTP device.
- Risks: the early-adb stanza and the gadget HAL both write configfs (the HAL tears down and rebinds, which is normal);
  the dwc3 `dr_mode` is peripheral in the probe DT (no OTG).

### GNSS: NOT YET
- There is no mainline GNSS driver for this path. On SDM660 the GNSS engine is in the modem and exposed as the QMI
  **LOC** service (0x10). Existing open code: ModemManager's QMI LOC support (Linux-desktop) and postmarketOS
  `gnss-share` (it shares NMEA from a device node; it is not a Qualcomm QMI client). Android would need a GNSS AIDL HAL
  that is a QMI LOC client (register events, start session, forward NMEA/position) over QRTR, plus XTRA assistance
  data. Not started. `android.hardware.location.gps` is not declared. Precondition: the modem stays up with its QMI services (23 Sep). Whether LOC (service 16) is
  registered has NOT been checked: look for service 16 in the radio2 qrtr-lookup output (laptop v74/logs).

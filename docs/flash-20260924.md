Bootloader facts used (docs/bootloader-inspection-20260914.md, boot-compatibility.md, captured ABL strings):
- No `fastboot boot` (RAM boot) in the ABL command table → the ROM boots from the **boot partition**; fastboot flashing
  is unreliable here → the install goes through **EDL/Firehose** like every recovery install so far.
- Boot image header v1, kernel = `Image.gz` + appended DTB, fixed 512 KiB kernel offset (same layout as V71/V74).
- In normal (non-recovery) boot the ABL loads the DTBO from the **dtbo partition** (`BootLinux: failed to get dtbo image`
  otherwise) — the recovery path embeds it in the image. rom-v1 therefore writes the V74 `recovery-dtbo.img` table
  (425 bytes, the qcom,board-id selection overlay) into dtbo. The stock dtbo would not apply to our mainline DT.
- For a system-as-root non-A/B boot the ABL appends ` skip_initramfs rootwait ro init=/init root=/dev/mmcblk0pNN`.
  With a mainline 7.2 kernel and a real ramdisk this is harmless: the initramfs is still unpacked and `/init` runs
  (`skip_initramfs` only reaches init's argv, which Android's first-stage init ignores; `root=` is ignored).
- AVB: vbmeta flags=2, unlocked (`devinfo` = verified unlocked baseline) → result 5 accepted (continue mask 0x39).

## 2. Proposed layout (DEFAULT) and alternatives — Pierre decides

**Default (implemented, staged): replace boot + dtbo + system + vendor, format userdata, keep everything else.**
Backup of every written region + every region the ROM may write, same EDL session, before any write.

Alternatives (not staged; say which one you want and it is a small change of `RomFlashLayoutV1.py`):
- **A. Keep stock userdata bytes as a full backup** (107 GiB read over EDL ≈ 1.5 h at ~20 MB/s; laptop has 810 GB
  free). Only this makes a byte-exact return of the stock Android data possible. Default: not done (spare phone).
- **B. ROM in the recovery slot** (boot LineageOS from the fastboot menu → Recovery, recovery-DTBO path = the path V71/V74
  proved): keeps stock boot/Magisk untouched and avoids the dtbo-partition path, but loses the V74 diagnostic recovery
  and stock Android still cannot boot (system replaced). Not recommended.
- **C. Keep modem EFS read-write from the first boot** (`persist.vendor.a6l.rmtfs_rw=1`): the normal stock behaviour;
  default is read-only until the radio is proven stable (§4).
- **D. Encrypted /data (FBE)**: later (needs fscrypt + keymint policy work). rom-v1 /data is plain ext4.

## 4. Boot flow and hardware bring-up in the installed ROM
1. ABL → kernel → first-stage init: loads sdhci-msm, mounts `/dev/block/by-name/system` (switch_root) and vendor.
2. selinux_setup (split policy, **permissive**: `androidboot.selinux=permissive`) → second stage.
3. `early-init`: `a6l-modules.sh display` (blocking): tps65185 → GPU chain → `msm.ko separate_gpu_kms=1` → FT8719 LCD
   panel → V73 e-ink panel → edt-ft5x06 (front+rear touch). If `renderD128` exists: `persist.graphics.egl=mesa`
   (freedreno); else ANGLE/SwiftShader. If no 1080x2340 DSI connector appears: `a6l_simplefb` fallback (splash
   framebuffer, software UI as in the V64–V70 runs). The e-ink DSI connector (384x725) is **forced off** before the
   composer starts (otherwise drm_hwcomposer makes it a 2nd display and holds DRM master); `a6l_epdd_v3 --lease auto`
   takes it back later (M1 design).
4. `fs`: `mount_all` → first boot formats /data (ext4); persist ro.
5. `boot`: USB (`sys.usb.controller=a800000.usb`, configfs; the `a6l_manual_usb=1` gate is released by writing
   `soft_connect` after every UDC bind — same gate as the recovery), backlight chown, `a6l-modules.sh adsp` (sensor
   registry → ADSP start → sound card "Hisense A6L" → TMD3702 on i2c c176000 0x49).
6. **Radio stays OFF** (RF rule) until `persist.vendor.a6l.radio=1`: then `a6l-radio.sh start` = radio2 order: qrtr →
   rmtfs, tqftpserv, diag-router (refuses to start the modem if diag-router died) → modem modules → `echo start` →
   wlan0 → MAC from `/mnt/vendor/persist/wlan_mac.bin` (`Intf0MacAddress=`) → BT modules.
   **rmtfs serves the REAL modemst1/modemst2/fsg/fsc partitions** (`-P`), read-only by default (`-r`: the modem's EFS
   writes are kept in RAM and lost at reboot, nothing on the eMMC changes). `persist.vendor.a6l.rmtfs_rw=1` = stock
   behaviour (writes go to modemst1/2). Both partitions are in the install backup and the restore compares them.
7. Debug: `androidboot.a6l_logcat=1` streams logcat W/E into the kernel log (used by the QEMU test).

SELinux permissive, unlabelled vendor scripts (explicit `seclabel`s). Enforcing needs the per-area sepolicy the other
agents started (hals/eink/audio) — not in rom-v1.

## 5. Installer and restore (EDL/Firehose, same safety model as the V74C tools)

Laptop kit: `~/A6L-usb-20260915/rom-v1/` (tools + `images/`), recovery kit reused from `~/A6L-usb-20260915/a6l-recovery-kit`
(programmer sha `60032425…`, Sahara identity serial f17933a2 / hwid 0008c0e100430000 / pkhash `06a0604b…`).

| file | role |
|---|---|
| `Launch-RomV1Install.py` / `Launch-RomV1Restore.py` | start the coordinator under the GNOME idle/suspend inhibitor (refuse if the capture dir exists) |
| `Run-LaptopRomInstall-v1.py` | checks stock Android state (fingerprint, unlocked/orange, port 3-2, battery ≥ 60 %, ≥ 12 GB free), host pause, `adb reboot edl`, runs the worker (≤ 5500 s), host resume |
| `Run-LaptopRomRestore-v1.py` | host pause, waits ≤ 180 s for EDL 9008 on 3-2 (tries `adb reboot edl` once), runs the worker in restore mode |
| `Write-LaptopRomV1.py` | EDL worker: kit hashes, exact spare identity before the programmer upload, **XML allowlist** (reads of known regions only; `program` only for the one range registered just before it; `power` only after all readbacks; no erase/patch) |
| `RomFlashEngineV1.py` | device-independent install/restore logic (same code for the real Firehose and the offline virtual eMMC) |
| `RomFlashLayoutV1.py` | geometry (checked against the live primary GPT: header+entries CRC and every used partition by name) |
| `Verify-RomV1Stage.py` | offline: tool + image pins, recovery kit hashes, GPT/layout, guard self-test, edl import with USB disabled; `--restore` also verifies the backup files |

**Install sequence** (one EDL session): GPT primary+tail = verified spare backup → vbmeta = stock, devinfo = unlocked
baseline → **backup reads**: boot, dtbo, misc, metadata, modemst1, modemst2, fsg, fsc, persist, recovery, vbmeta, devinfo, vendor,
system (full partitions), userdata first 64 MiB + last 1 MiB (≈ 7.7 GB) → BCB must be empty or `bootonce-bootloader` →
**second independent read** of every small region (must match) and system/vendor/dtbo must equal the 14 Sep stock hashes
(else refuse; `--allow-nonstock` only after review) → `backup-manifest.json` → writes: boot (64 MiB), dtbo (8 MiB), vendor
(EROFS size), system (EROFS size), metadata first MiB zeroes, userdata first MiB zeroes → full readback of every written range (sha must match) →
power **off**. Estimated 12–20 min (EDL ≈ 15–20 MB/s: V74C session read+wrote+read 70 MB in 17 s).

**Restore sequence**: backup files re-hashed against the manifest → GPT check → reads misc/metadata/modemst1/modemst2/fsg/fsc/persist
and compares with the backup → writes back boot, dtbo, vendor, system (full partitions, byte-exact pre-install contents incl.
the Magisk boot) + the ROM-changed regions → userdata: first MiB and last 16 KiB zeroed (default) → readback → **reset**.
Result: every partition except userdata is byte-identical to the moment before the install. Stock Android then finds
userdata wiped with `forceencrypt=footer` and asks for recovery/wipe (`FS_MGR_MNTALL_DEV_NEEDS_RECOVERY`): the recovery slot
holds the V74 diagnostic recovery, so either (a) run the existing `Run-LaptopDiagnosticRestore-user-v74c.py` (restore mode
writes stock recovery) and let stock recovery wipe data, or (b) choose alternative A (full userdata backup) before install.
`--userdata=original` writes back the saved head/tail instead (only meaningful if LineageOS never mounted /data).

**Entering EDL for the restore** — our kernel has no `reboot edl` (mainline pm660 PON knows only bootloader/recovery):
- from stock Android: `adb reboot edl` (as always);
- from LineageOS or the V74 recovery: `adb reboot bootloader` works (PON 0x02); from the ABL there is no known EDL command.
  Practical path: boot the **V74 recovery** (fastboot menu → Recovery), then write-free rescue with adb is possible
  (§7 plan B), or use the hardware EDL entry Pierre used on 14 Sep if any (not documented in the repo — to confirm).
- Plan B restore without EDL (V74 recovery, adb, `sdhci-msm` loaded): `adb exec-in 'dd of=/dev/mmcblk1pNN bs=4M' < <backup>.bin`
  for boot/dtbo/system/vendor with the partition numbers from `/sys/class/block/*/uevent` (PARTNAME). Untested; attended only.

## 9. 24 Sep morning: the QEMU blocker (agent `gnss`, taking over from `flash`)

### 9.1 Diagnosis: two causes, neither was a watchdog, lmkd or the timeout multiplier
1. **r5 restart every ~90 s.** Postmortem `system_server_crash@…`:
   `IllegalArgumentException: Invalid feature flag: android.security.aapm_feature_disable_insecure_wifi_autojoin` in
   `AdvancedProtectionConfigLoader` ("Failure starting core service" → zygote exits → init SIGKILLs it). The console shows
   why: `mkdir /metadata/aconfig … Read-only file system`, and aconfigd reports "failed to copy … to
   /metadata/aconfig/maps/…". rom-v1's fstab had **no /metadata**, so the directory was the read-only EROFS mount point,
   aconfigd could not build the flag storage, and `AconfigFlags.getFlagValue()` returned null for every flag.
   `ro.hw_timeout_multiplier=5` was already set; the "SIGKILL" in the logs is just init reaping the zygote group.
2. **r6, after the /metadata fix.** system_server lasted about 16 min and then died with
   `java.lang.OutOfMemoryError: … target footprint 16777216, growth limit 16777216` (PermissionPolicyService). The
   lineage_gsi product inherits no dalvik-heap config, so every VM, system_server included, had the 16 MiB default.
3. Debug infrastructure: the `a6l_logcat` service died on every crash dump (`logcat: Output error: Invalid argument`)
   because /dev/kmsg rejects writes over 992 bytes. That is why the crash text never reached the console.

### 9.2 Fixes (device/hisense/a6l/rom/, tools/)
- `rom/vendor-etc/fstab.qcom`: `/dev/block/by-name/metadata /metadata ext4 noatime,nosuid,nodev,discard wait,check,formattable`
  (second stage, before /data). fs_mgr formats it on the first boot:
  "is wiped and /metadata ext4 is formattable. Format it" → mounted.
- `rom/rom.mk`: `inherit-product frameworks/native/build/phone-xhdpi-4096-dalvik-heap.mk` (heapgrowthlimit 192m,
  heapsize 512m; checked in vendor build.prop), `inherit-product-if-exists gnss/gnss.mk` (GNSS HAL, docs/gnss-20260924.md),
  `bin/a6l-logcat.sh`.
- `rom/init/init.qcom.rc`: `a6l_logcat` now runs `/vendor/bin/a6l-logcat.sh`, which writes one line per kmsg record, cut
  to 900 characters. A test-harness-only trigger `ro.boot.a6l_stayawake=1` (set on the QEMU cmdline only) keeps the
  screen on. Without it, r7's guest autosuspended (s2idle) 434 s after boot_completed, which is normal on the phone but
  stops the observation.
- Installer: `RomFlashLayoutV1.py` adds `metadata` (1472536, 20480 sectors, checked against the live GPT by
  `check_layout_against_gpt`). It goes into the backup and the second read, `install_writes` adds `metadata-zero`
  (first MiB), and it joins `ROM_MAY_WRITE`, so the restore compares it and writes the stock bytes back.
  `RomFlashEngineV1.py` handles every `*-zero` label. `Test-RomV1Flash.py` asserts that metadata is zeroed after the
  install and byte-identical after the restore.

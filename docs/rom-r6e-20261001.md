## 1. What the r6d logs show (logs/r6d-boot/)
There are three different things behind "the phone freezes 2 to 3 min after boot":

**(A) Autosuspend that looks like a freeze (meta-r6d-1, the setup boot).** This is not a stall. From 229.7 s on, the kernel
log has `PM: suspend entry (s2idle)` ... `PM: suspend exit` cycles every 30 to 50 s (screen off). Pierre's power-button wake at
05:03:13 brought the UI back, and the log ran on until 624 s. Three things make this suspend look like a hang:
- The display is not blanked (P2 g): the last frame stays up with the backlight on.
- USB dies across the suspend: `dwc3 a800000.usb: failed to enable ep0out` at the first suspend. Nothing holds a wakeup
  source while the cable is in, so the phone suspends on USB too. adb stays enumerated, but `adb shell` fails.
- During s2idle the buddy detector prints `watchdog: CPU4: Watchdog detected hard LOCKUP on cpu 5` and `rcu_preempt
  detected stalls` with `(false positive?)`. Every NMI backtrace shows `cpuidle_enter_s2idle`, so these are idle CPUs in
  s2idle, not real lockups.
- At suspend there are also WARNs: `camss_ahb_clk status stuck at 'on'` (cci_suspend_runtime) and `mdss_ahb_clk status stuck at 'on'`
  (mdss_runtime_suspend). They are not fatal: the phone resumed many times.

**(B) Storage writeback stops (meta-r6d-2, meta-r6d-3).** On /metadata the kernel log ends at 107.7 s and 72.4 s. In both
boots the last boot-log action is `budget: used 2.8 MiB -> previous boot deleted`. Other evidence:
- No `suspend entry` was logged.
- The files are cut at page boundaries (kmsg.aad 57344, logcat.aai 90112, tombstones.txt 12288 bytes).
- `e2fsck` had to replay the journal.

So /metadata got no more writeback after that point, although the phone kept running for a while from the page cache. This
matches the coordinator's hypothesis: the deletes queue online discards. ext4 issues them from the jbd2 commit
(`ext4_process_freed_data` -> `mmc_blk_issue_erase_rq` -> CMD38 + busy wait while the host is claimed). If the eMMC never
finishes, that jbd2 commit hangs, then every writer to that file system hangs, and finally /data too (same eMMC queue).
In meta-r6d-1 the same delete happened before boot_completed and did not hang, so the hang is not deterministic.

**(C) Sudden death and reset (live-093436, Pierre's live adb capture).** This one does NOT look like an IO stall:
- At 376.6 s the IO PSI is `full avg10=0.02`, Writeback is 0 kB, Dirty is 872 kB and MemAvailable is 3.0 GB.
- The logcat stream ends at 01:28:32, right after these lines:
  - `drmhwc: sync_wait(fd=13) returned: -1 (errno: 62)` (a GPU/display fence timed out)
  - `Failed to commit pset ret=-16 (EBUSY)`
  - `SurfaceFlinger: present failed for display 0: BAD_DISPLAY`
- The next boot is meta-r6d-3 (same RTC; its logcat says 01:29:54 at 72 s uptime). It started about 10 s after the last line,
  which points to a whole-SoC hang reset by the watchdog (qcom-wdt + watchdogd).
- `pstore-prev:` is empty after it: ramoops kept nothing.

This boot had no kernel log at all (`dmesg: klogctl: Operation not permitted`), so the cause is open. The r6e debug aids
are there to tell (B) from (C) on the next boot.

**Also found: the radio daemons never ran in any ROM build so far.** Every 5 s the kernel log has
`/vendor/bin/a6l-radio.sh[194]: /vendor/a6l/radio/bin/rmtfs: can't execute: Permission denied`, and the same for
tqftpserv and diag-router. The cause: `/vendor/a6l/radio/bin/*` are PRODUCT_COPY_FILES outside a standard bin dir, so the
build gave them mode **0644** in vendor.erofs (verified by extracting the r6d vendor image). As a result:
- no rmtfs, so the modem never booted, which explains the empty gsm.sim.state;
- no WLAN firmware services;
- `bt_up` (a6l_macs public address for hci0) was never reached.

## 2. P1 changes
**a) No `discard` mount option** (`device/hisense/a6l/rom/vendor-etc/fstab.qcom`, `fstab.qcom.fbe`): removed from /metadata and
/data, and from the commented phase-2 FBE line. No other entry had it.
- Both the first-stage fstab in the boot ramdisk and /vendor/etc/fstab.qcom come from this file, so **boot.img changes**:
  same kernel and DTB, only the ramdisk fstab differs.
- Freed blocks are still trimmed, but in batches. Android's idle maintenance (StorageManagerService ->
  vold `fstrim` = FITRIM ioctl on the writable fstab mounts, run while idle + charging, at most once a day) does not need the
  mount option.
- Caveat: FITRIM sends discards through the same mmc erase path. If online discard is the hang, an idle fstrim can hang too
  (at night, on the charger). That makes it a deliberate test, see §8: `adb shell sm idle-maint run` while
  streaming dmesg. If it hangs, discard is confirmed broken on this eMMC and idle fstrim must be blocked as well (decision).
- The first-boot mke2fs runs without discard (r6c profile, unchanged).

**b) eMMC command queueing: nothing to remove. CQE was never on.**
- sdhci-msm calls `sdhci_msm_cqe_add_host` only when the node has `supports-cqe`. The ROM DTB node `/soc@0/mmc@c0c4000`
  (V74 base + overlays) has no such property. Its properties: hc/cqhci/ice regs, `bus-width 8`, `non-removable`,
  `max-frequency 50000000`, `no-sdio`.
- The kernel log has no CQHCI/CQE line. The card comes up as `mmc1: new HS200 MMC card ... hDEaP3 116 GiB` (Hynix name pattern).
- `CONFIG_MMC_CQHCI=y` is built in but unused.
- `tools/build-rom-v2-dt.sh` now fails the DT build if `supports-cqe` ever appears on that node, and prints the node. r6e log:
  `emmc: /soc@0/mmc@c0c4000 supports-cqe absent (CQE off), max-frequency=50000000 no-sdio`.
- The V75 recovery DT is a separate file and is not touched.
- Note: Linux has no Hynix TRIM quirk. The only Hynix quirk is BROKEN_HPI for EXT_CSD rev 5 (0x014a).

**c) r5 sdhci-msm vs V67:**
- The sources are identical. `drivers/mmc/host/{sdhci-msm,sdhci,cqhci-core}.c` and `drivers/mmc/core/{block,queue}.c` have
  the same sha256 in `a6l-baseline-7.2` (the V67 tree) and `a6l-rom-r5-src`. Both modules report `srcversion D81B3CB8570A29CDC4595BA`.
- The only module differences are build-related: r5 has `modversions` in its vermagic and is stripped (67 552 bytes vs 529 224).
- Block-related config changes V67 -> r5 (`config-diff-v67-r5.txt`):
  - `BLK_INLINE_ENCRYPTION=y` + `_FALLBACK=y` (`MMC_CRYPTO` n, and the non-FBE fstab does not use inlinecrypt, so this is inert);
  - `PM_WAKELOCKS=y`;
  - `SUSPEND_SKIP_SYNC=n`.
- Nothing in mmc, block discard or ext4 changed.

**NEW d0) Radio binaries executable.** New `device/hisense/a6l/rom/config.fs` (`[vendor/a6l/radio/bin/*]` mode 0755 root:shell),
plus `TARGET_FS_CONFIG_GEN += device/hisense/a6l/rom/config.fs` in `BoardConfig-rom.mk`.
- The image check now extracts vendor.img and checks the modes.
- r6d negative control: 644 FAIL x5.
- Consequence for testing: with persist.vendor.a6l.radio=1 (already set since r6b) the r6e boot is the first ROM boot in which
  rmtfs/tqftpserv/diag-router run. The modem (MSS) then boots, followed by WLAN (wlan0 MAC from persist) and `bt_up` (a6l_macs

## 3. Debug aids (userdebug only: `rom/debug/bootlog.mk` block `ifneq ($(TARGET_BUILD_VARIANT),user)`)
**d) Live kernel log over adb.**
- `ro.debuggable` is **0** on this Lineage userdebug build, because `vendor/lineage/config/common.mk` sets
  `PRODUCT_NOT_DEBUGGABLE_IN_USERDEBUG := true` unless WITH_ADB_INSECURE is set. So there is no `adb root`, and r6d's
  `adb shell dmesg` failed with `klogctl: Operation not permitted`.
- `init.a6l.bootlog-debug.rc`, at `on post-fs-data` and again at boot_completed:
  - `write /proc/sys/kernel/dmesg_restrict 0`
  - `chmod 0644 /dev/kmsg` (first-stage init creates it 0600)
  - `printk_devkmsg on`
- With these, toybox `dmesg` / `dmesg -w` (reads /dev/kmsg) works as the shell uid. SELinux is permissive.
- `ro.logd.kernel=true` is set in vendor (it was already true at runtime in r6d) for `logcat -b kernel`.
- Laptop helper `extra/live-capture.sh`: dmesg -w + logcat + a PSI/meminfo/eMMC-inflight sampler, auto-reconnect, and it
  echoes `A6L_IOSTALL` on the terminal.

**e) IO-stall detector** `/vendor/bin/a6l-iowatch.sh`, service `a6l_iowatch` (root, su, started at post-fs-data, runs forever).
- Every 5 s it does a background `echo uptime > X.tmp && fsync X.tmp && mv X.tmp X`, both on `/metadata/a6l/heartbeat` and on
  `/data/local/tmp/a6l-heartbeat`.
- A writer that is still alive after 15 s of awake time counts as a stall. The time is counted in `sleep 1` ticks, so
  suspend is not counted.
- On a stall it writes to `/dev/kmsg` only:
  - `A6L_IOSTALL target= pid= age= uptime=`, then PSI io, `/sys/block/mmcblk1/inflight`, the eMMC lines of /proc/diskstats
    (in-flight), the mmc1 debugfs `ios` and `err_stats` (it mounts debugfs if needed);
  - up to 40 D-state tasks (pid, comm, wchan) and the stuck writer's /proc stack;
  - then `sysrq w` + `sysrq l`.
- Repeats at most every 60 s, then logs `A6L_IOSTALL recovered target=... after Ns`. Every 60 s: `A6L_IOWATCH alive t=... heartbeats
  meta=N data=N max_s ...`.
- At start it logs `A6L_IOWATCH mount /metadata ext4 <options>` and `/data`, which shows that `discard` is gone, plus
  `dmesg_restrict` / `/dev/kmsg` mode.
- The report path uses only shell builtins and /proc + /sys reads. Test hook: `ro.boot.a6l_iowatch_test=fifo` turns the
  first /metadata heartbeat into a FIFO that blocks for 45 s.

**f) Kernel debug options: none (kernel unchanged, r5p Image).**
- `CONFIG_DETECT_HUNG_TASK` adds `last_switch_count`/`last_switch_time` to `struct task_struct`. That is a layout change
  that every module touching `current` would see, the same trap as KFENCE in diag-r5, even if Module.symvers stayed equal.
  So it was skipped.
- The detector's `sysrq w` gives the same blocked-task stacks on demand.
- Already in r5p: SOFTLOCKUP_DETECTOR, HARDLOCKUP_DETECTOR_BUDDY, MAGIC_SYSRQ, DEBUG_FS, PSTORE_RAM/CONSOLE/PMSG.

## 4. P2 (findings; no code change except where stated)
**g) The screen does not blank on sleep.** The path is in place, so there is no fix I could defend:
- **Off path in the composer.** DisplayPowerController sends brightness -1, and drm_hwcomposer
  `HwcDisplay::SetBrightness(-1)` turns that into `nullopt`. `SysfsBacklightController` then writes `bl_power=4`. Our 0002
  patch only adds the e-ink hold.
- **Power mode.** `SetPowerMode(Off)` does a blocking teardown commit (CRTC inactive). msm DSI then disables
  `panel-ft8719-tianma-1080x2340`:
  - `drm_panel_of_backlight`: backlight_disable;
  - unprepare: DCS display off + enter sleep.
- **Permissions.**
  - The WLED is built in (`CONFIG_BACKLIGHT_QCOM_WLED=y`, probed at 1.4 s).
  - `a6l_dualux.rc` `on boot` chowns `bl_power` to system 0664.
  - The composer runs as system.
  - So bl_power should have been writable. I checked this and dropped a ueventd change.
- **What the r6d logs hold.**
  - r6d-1 has `SurfaceControl: Excessive delay in setPowerMode()` at the wake.
  - The screen-off part of its logcat is in the segments the size budget dropped.
- **Attended checks** (Pierre: `svc power stayon usb` first, so the timeout does not suspend the phone while you look):
  1. `adb shell input keyevent 26` (screen off). Then, if adb still answers:
     `adb shell 'cat /sys/class/backlight/backlight/{bl_power,brightness,actual_brightness}'`.
  2. `adb logcat -d -s drmhwc SurfaceFlinger DisplayPowerController | tail -40`
  3. `adb shell dmesg | grep -iE 'dsi|panel|wled|drm' | tail`
- **Reading the result.**
  - bl_power 0 = the composer write failed: look for "Failed to turn backlight off".
  - bl_power 4 with actual_brightness > 0 = WLED driver.
  - Panel lit with backlight 0 = the panel kept its RAM image: unprepare not reached, so the teardown commit failed
    ("Failed to set display active: disabled").
- **Related, needs a decision (not done):**
  - Nothing keeps the system awake on USB. In r6d-1 the first s2idle broke the gadget (`failed to enable ep0out`). The phone
    autosuspends on USB, and adb dies with it.
  - For debugging: `adb shell svc power stayon usb` (Settings global, survives reboots).

- Parallel session (in the final r6e): `rom/android/patches/external/drm_hwcomposer/0003-a6l-display-power-backlight.patch` blanks the WLED from `SetPowerMode(Off)` and restores it on wake. If the panel goes dark on the next boot, that patch is the fix; the checks above still apply.

**h) Bluetooth.**
- `android.hardware.bluetooth-service.default` (AOSP `BluetoothHci::initialize`) first opens the Linux HCI socket
  (`NetBluetoothMgmt::openHci`: mgmt READ_INDEX_LIST, rfkill, HCI_CHANNEL_USER on a *configured* controller), then the
  `vendor.ser.bt-uart` path. When both fail it calls `initializationComplete(UNABLE_TO_OPEN_INTERFACE)` but does **not**
  return. It goes on into `H4Protocol(mFd=-1)` and the FdWatcher's `FD_SET(-1)`, hence the FORTIFY abort (an upstream bug).
- The Bluetooth stack then aborts on any non-success status (`hci_backend_aidl.cc:43`).
- What is missing on our side: a configured hci0. The WCN3990 comes up UNCONFIGURED (QCA default BD address, hals doc
  24 Sep), and `a6l_macs bt` must set the public address. a6l-radio.sh starts it in `bt_up` after the modem/WLAN sequence,
  which never ran in r6d (radio binaries 0644).
- With r6e's config.fs fix, `vendor.a6l-bt-addr` should run after the modem starts. Then the HAL should find hci0
  (`hci interface 0 found`).
- Check: `adb shell getprop init.svc.vendor.a6l-bt-addr`, `adb shell dmesg | grep -iE 'bluetooth|hci0|qca'`, then
  toggle BT in quick settings.
- If it still aborts, the next fix is a hardware/interfaces patch that returns after the failed initializationComplete.
  It only moves the crash into the stack, so the real fix stays hci0.

- Parallel session (in the final r6e): `rom/android/patches/hardware/interfaces/0001-a6l-bluetooth-transport-startup.patch` (return after the failed initializationComplete, wait up to 30 s for the BT socket family) and `a6l-radio.sh` runs `bt_up` before the modem waits.

**i) Cropped glyphs (Mesa freedreno a512).** No change to the Mesa defaults.
- **Setting the flags.** Android reads `FD_MESA_DEBUG` as the property `debug.mesa.fd.mesa.debug` (os_misc.c:
  lowercase, `_`->`.`, `mesa.` prefix, then the `debug.` prefix is tried). The flags are read once per process at screen
  creation (eglInitialize in the app, not in zygote).
- **Testing.** `adb shell setprop debug.mesa.fd.mesa.debug <flags>`, then restart only the app being tested:
  `adb shell am force-stop com.android.settings`, reopen it, and `adb exec-out screencap -p > x.png`. Settings showed the
  glitch. SystemUI is persistent: `adb shell am crash com.android.systemui`.
- **Flags, in the order I would try them:**
  1. `inorder`: no reordering of draws/blits. If the glyph-atlas upload (texSubImage blit) lands after the draw that samples
     it, glyphs come out partly missing or stale.
  2. `nofp16`: no mediump lowering. fp16 texture coordinates into a 1-2 k atlas lose about a texel, so glyph edges get
     clipped. This fits "cropped", not "garbled".
  3. `noblit`: the generic blit path instead of the a5xx blitter for the A8/R8 sub-rect uploads.
  4. `sysmem`: no GMEM tiling. It rules out bin/scissor clipping at tile edges.
  5. `nobin`: no hw binning (visibility stream drops).
  6. `notile`: linear internal buffers (texture layout of partial uploads).
  7. `flush`: flush after every draw. This is a big hammer: if it fixes the glyphs, the bug is in batch ordering.
- **Reading it.** Combine flags with commas. The first flag that fixes it narrows the bug to one area. `msgs`/`perf` add
  logcat context.

## 7. Decisions / open
1. **Radio is now really on.** persist.vendor.a6l.radio=1, and rmtfs etc. finally execute, so the modem, WLAN and BT start on
   the r6e boot. This is the first ROM boot with the modem up. To keep the stall test clean you could disable radio for one
   boot, but there is no shell path for that: persist.vendor.* cannot be set without root. It would need a build switch. My

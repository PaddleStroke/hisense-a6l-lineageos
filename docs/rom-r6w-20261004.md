## Root cause and measured progress

All three sensors supply about 30 Hz. r6u's native CPU software ISP, with two workers and scalar per-pixel routines, completed main/selfie/wide frames at 6.63/9.81/17.22 Hz. r6v's exact SIMD and six workers improved these to 19.34/23.25/30.01 Hz. SurfaceFlinger independently measured the main preview around 19.8 fps and the other previews in the mid-20s. Full field of view is retained. This leaves real CPU/preview costs to fix, rather than an exposure or sensor-rate explanation for the main camera's original sluggishness.

The phone has four capacity-1024 and four capacity-640 CPU cores. Equal-sized worker slices can leave completion waiting for slower workers. r6w lets each of the six workers claim independent, even 64-row chunks until all rows are processed. It preserves global Bayer/halo coordinates, private scratch/stat slots, integer exposure/autofocus reductions and the completion barrier. No cores are reserved and affinity is unchanged.

Preview NV12Scale consists of independent Y and UV scaling calls. r6w runs those exact calls concurrently using one persistent UV worker, waits for both before returning or releasing buffers, and retains the original serial path for unsupported/odd geometry. Pixels, interpolation and crop arithmetic remain unchanged. It also removes duplicate whole-buffer synchronization when the NV12 planes share the same descriptor; required START/END synchronization is retained.

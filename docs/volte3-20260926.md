# volte3: VoLTE steps 3 (call domain) and 4 (VoLTE call audio session), step 5 notes (26 Sep 2026)

Agent `volte3`. **All of this is offline.** It was built, host-tested and syntax-checked. Nothing ran on the phone, and
nothing touched RF. The bundle `v75/volte3` is staged on the laptop, and `sha256sum -c` passes there
(`LAPTOP_STAGED_OK`). It builds on docs/volte-20260925.md (plan B) and docs/volte2-20260925.md (steps 1–2), plus
kvoice-20260924.md and audio6-20260925.md for the call audio.
The aim: if IMS registers in the next attended session, a VoLTE call can be tried straight away, with the domain
reported and the audio up.

## 0. Summary
| item | result |
|---|---|
| **Key finding: which CVD session VoLTE uses** | The stock qcrild does not hard-code the VoLTE VSID. It **asks the modem**. `qcril_qmi_nas_get_subscription_info` sends **NAS 0x007C (Get Subscription Info)**, and its TLVs 0x13, 0x14 and 0x15 (u32) go to `qcril_am_set_vsid` as vs_type 2 (VOICE = CS), 1 (IMS = VoLTE) and 3 (IMS on WLAN). This was found by disassembling `libril-qc-hal-qmi.so`: the vs_type numbering comes from `qcril_am_get_current_ims_vs_type`, which returns 1 or 3. The TLV layout comes from the stock IDL (`libqmiservices.so`, NAS IDL 1.246, resp 0x007C: 0x10 enum8, 0x11 enum8, 0x12 u8, **0x13/0x14/0x15 u32**, 0x16 enum8, 0x17 u32). The same TLVs arrive in indication 0x0048. The only built-in table in qcrild is {0x10C01000, 0x10DC1000} (CS voice for sub 1 and sub 2). The audio HAL receives `vsid=…;call_state=…` from qcrild (`qcril_am` → AudioSystem::setParameters). Stock mixer_paths.xml has **no `volte-call` path**, only `voicemmode1-call`. (`volte-call` exists only in the unused `mixer_paths_i2s.xml`, with "VoLTE Stub".) **Expected:** this MPSS (AT.3.1) reports LTE VSID = 0x11C05000 (VoiceMMode1, "multimode"). A VoLTE call on SIM 1 would then use the same session as the CS call proven on 24 Sep, and no change would be needed. **The attended `ims-status` reads the real value**, and the test picks the session from it. |
| Step 3: signalling | `a6l-qmi dial-ims <num> [s]`. It prints the IMS state first: IMSA reg/services, NAS IMS voice support (SysInfo 0x29/0x2A) and the VSIDs. It then dials with call type VOICE, so the modem chooses the domain (voice_domain_pref = 3 in the Orange MBN). `A6L_CALL_TYPE=ip` forces VOICE_IP instead. Each change of a call's state, type or mode is printed as `A6L_QMI_CALL_DOMAIN … domain=ims|ims-wlan|cs`. It detects SRVCC (IMS→CS on the same call id), decodes the audio-RAT-change indication (0x0063), and hex-dumps every other VOICE indication (handover, speech codec, …) for offline decoding. The final line is `A6L_VOLTE3_CALL_RESULT domain= connected= srvcc= rat_during= lte_vsid=`. The VOICE indication register adds handover (0x14), speech codec (0x15) and **audio RAT change (0x23)**. The 0x23 TLV comes from the stock qcrild request struct: it sets byte 38 of the 52-byte `voice_indication_register_req`, which is TLV 0x23. |
| Incoming IMS calls | They come in through the same all-call-status (0x2E) with type VOICE_IP and mode LTE. The HAL already reports every call type as a normal call (`getCurrentCalls`, `isVoice = true`). The CLI `call-wait` lines (`A6L_QMI_IND_CALL`) now show `type= mode= domain=`. A host test covers an MT IMS call parse. |
| HAL | `A6L_RIL_CALL_DOMAIN slot1 id=N ims type=voice-ip mode=lte`, plus `… ims -> cs (SRVCC)`. `vendor.a6l.voice.domain=ims|cs` is published **before** `vendor.a6l.voice.active=1`. **Bug fixed: `sendImsSms`.** Once volte2's `getImsRegistrationState` reports registered, AOSP GsmSMSDispatcher sends through `sendImsGsmSms`. The generated stub answered NOT_SUPPORTED, so SMS would have broken as soon as IMS registered. It now uses the same WMS raw send, and the modem picks IMS or CS itself (sms_domain_pref). |
| Step 4: audio | Kernel `a6l-q6mvm-volte-session-v75.patch` (q6mvm.c only) adds the module parameter **`q6mvm.mmode1_session`** (string, 0644). It is read at every MVM passive-session create (once per call). Values: `default` (the path default "11C05000", unchanged behaviour), `cs` ("default modem voice"), `volte` ("default volte voice", the downstream msm-4.4 VoLTE session name), `mmode1`, `mmode2`, or 8 hex digits (a VSID string such as `10C02000`). It logs `A6L_Q6VOICE mvm passive session '<name>' (path 6)`. The existing VoiceMMode1 FE/DAI and routes are reused: the session name, not the DAI, decides which modem stream the ADSP session joins. So no second DAI, DT change or mixer path is needed. `a6l-q6voiced -s <session>` writes the parameter before it opens the PCMs (root, for tests). ROM: `a6l-q6voiced.rc` has init write the parameter on `vendor.a6l.voice.domain=ims|cs`, **only if `persist.vendor.a6l.voice.session_switch=1`**. The values are `persist.vendor.a6l.voice.session_ims` (default `volte`) and `…session_cs` (default `default`). This switch is needed only if the modem reports an LTE VSID different from the CS one. |
| Builds | `q6mvm.ko` for `7.2.3-a6l-probe+` (out-a6l-phone-v67), W=1 with 0 warnings. All symbols resolve. MODVERSIONS is off in v67, so there is no CRC coupling with audio6's `q6voice-common.ko`. **rom-v2 series** has the patch appended after the kvoice series: `A6L_KSERIES_PASS`, all 6 patches apply, qdsp6 builds with 0 warnings. a6l-qmi and a6l-imsdcm are NDK r27c static. `a6l-q6voiced` builds for NDK static and for the host (`-Werror`). |
| Tests | Host (WSL gcc, ASan/UBSan): **a6l-qmi 271/271, modemcore 87/87, volte2 291/291, volte2-modemcore 11/11, new a6l-volte3 147/147** (3 rounds: domain rules, MT IMS parse, audio-RAT, subscription-info codec + summary, typed dial wire bytes, VoLTE indication register TLVs, VSID/IMS-voice queries over the fake modem). HAL and lib: **clang `-fsyntax-only -Werror` vs the tree's AIDL V4 NDK headers, rc=0** (twice, the second time with sendImsSms). `volte3-test.sh`: `bash -n` / `dash -n`, plus a mock dry-run of MODE=call/status: session auto-picked from the VSID, audio started at origination, RESULT line, emergency numbers refused. No `m` was run. |

## 3. Attended test (V74 recovery, **fresh boot**, laptop `~/A6L-usb-20260915`; RF steps are typed by Pierre)

```
adb -s HLTE730T-PROBE push v75/audio6 /tmp/audio6; adb -s HLTE730T-PROBE push v75/volte3 /tmp/volte3

# 2. NO RF, NO SOUND: audio modules with the volte3 q6mvm (NOT audio6 MODE=load)  -> A6L_VOLTE3_AUDIO_READY q6mvm mmode1_session=''
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export MODE=audio; sh /tmp/volte3/volte3-test.sh' 2>&1 | grep -v linker
```

Step 5 starts `a6l-imsdcm` (770) again, because volte2-test stops it at the end. It waits up to 180 s for `registered=1`,
sets `q6mvm.mmode1_session` from the modem's LTE VSID, and starts `dial-ims`. As soon as the call is dialling, it runs
audio6 `MODE=call GAIN=0` (holds the VoiceMMode1 PCMs, headset paths), then hangs up after SECS. **If IMS does not
register, the same command makes a CS (CSFB) call** with the proven session: `domain=cs session=default`.

**How to read the result** (lines `A6L_VOLTE3_VSID`, `A6L_QMI_CALL_DOMAIN`, `A6L_VOLTE3_RESULT`, and Pierre's answers):
| what you see | meaning / next |
|---|---|
| `A6L_VOLTE3_VSID … lte_vsid=0x11C05000(VoiceMMode1)` | VoLTE uses the multimode session; `session=default` (nothing new on the audio side) |
| `lte_vsid=0x10C02000(VoLTE)` → `session=volte` | VoLTE has its own session; the test uses "default volte voice". If there is no audio: rerun step 5 with `SESSION=10C02000` (the VSID string), then `SESSION=default` |
| `lte_vsid=absent` / `qmi-error` | NAS 0x007C is not answered on this firmware: step 5 keeps `default`; if VoLTE audio is silent, try `SESSION=volte` |
| `A6L_QMI_CALL_DOMAIN … mode=lte(4) domain=ims` + `A6L_QMI_CALL_RAT in-call rat=lte` (no CSFB) | **step 3 PASS: the call is VoLTE** |
| `domain=cs` + `rat=umts CSFB` while `registered=1` | the modem chose CS: IMS voice is not available (`A6L_VOLTE3_IMSA … voice=0`), or NAS `lte_ims_voice=0` (the cell/operator does not offer it), or the vdp. Retry with `A6L_CALL_TYPE=ip` (forces IMS) and keep the error |
| `A6L_QMI_SRVCC` | handover to CS during the call (weak LTE): audio must continue (same MMode1 session if VSIDs are equal) |
| Pierre hears the voicemail greeting, and his message is in the voicemail afterwards (888 on stock) | **step 4 PASS**: two-way VoLTE audio. Wideband (HD) should sound clearer than the 24 Sep CS call |
| call up, `domain=ims`, silence | wrong session: the klog line `A6L_Q6VOICE mvm passive session '…'` shows the name used; try the other values (`volte`, `10C02000`, `cs`, `default`) one per call |

## 4. Step 5: the Android side (plan B: no ImsService)
- **Calls:** AOSP telephony dials with `IRadioVoice.dial`, and our HAL sends QMI VOICE Dial with type VOICE. The modem
  then puts the call on IMS by itself. Android sees an ordinary GsmCdmaCall: `getCurrentCalls` returns it as usual,
  whether CS or IMS, MO or MT. Telecom sets MODE_IN_CALL. The HAL publishes `vendor.a6l.voice.domain`, then
  `vendor.a6l.voice.active`. a6l-q6voiced opens the voice PCMs, and a6l-audio-route switches the codec. So the Dialer
  works unchanged: **plan B needs no ImsService for calls**.
  - Because no ImsService is bound, `ImsPhone` is never in service. `GsmCdmaPhone.dial` therefore always takes the
    CS path, the IRadioVoice path used above.
  - Emergency calls go through `emergencyDial` with QMI type EMERGENCY. The modem uses IMS emergency or CS as its MCFG
    says. (Untestable: never dial 112.)
- **Registration / service state:** voice registration reports LTE when the phone is camped on LTE (existing
  `getVoiceRegistrationState`), and the status bar shows "4G". `IRadioNetwork.getImsRegistrationState` (volte2)
  answers `isRegistered` + THREE_GPP from IMSA, and `imsNetworkStateChanged` fires on changes. **The framework uses
  it for SMS:** `SmsDispatchersController.isIms()` then selects `sendImsGsmSms`, which is why `sendImsSms` was added
  today.
  - `isImsRegistered()`, the VoLTE status-bar icon, the Settings "4G calling/VoLTE" toggle, Wi-Fi calling and RTT all
    stay off. That is expected, since no MmTelFeature is registered.
- **HD icon:** the Dialer shows HD when the connection has `PROPERTY_HIGH_DEF_AUDIO`. For RIL calls,
  GsmCdmaConnection derives this from `DriverCall.audioQuality`. The AIDL `android.hardware.radio.voice.Call` has
  `audioQuality` (AudioQuality AMR_WB / EVS_WB / …). **Next step (small):** decode the QMI VOICE speech-codec
  indication (hex from step 5), keep the codec per call in ModemCore, and fill `Call.audioQuality`. Android then
  shows HD for VoLTE (AMR-WB/EVS) without an ImsService. This needs no framework change. **Not done yet:** the TLV
  layout has to be confirmed from the step-5 log first.
- **IRadioIms (Android 14+ AIDL, still in Android 17):** `setSrvccCallInfo`, `updateImsRegistrationInfo`,
  `startImsTraffic`/`stopImsTraffic`, `triggerEpsFallback`, `sendAnbrQuery`, `updateImsCallStatus`. It exists so that
  an **AP-side** ImsService (vendor IMS stack) can tell the modem about its registration, traffic and calls. With
  modem-centric IMS (plan B) the modem already knows all of this.
  - Our HAL does **not** declare IRadioIms. It is optional in the compatibility matrix.
  - It would only matter for option A (joan-volte AP ImsService) or option C (our own ImsService over the modem IMS:
    registration from IMSA, calls as VOICE_IP, needed only for the native VoLTE UI/toggle).
- **Carrier config:** plan B needs no Orange overlay. `carrier_volte_available_bool` stays false, and Android never
  tries IMS itself.
- **ROM switches:**
  - `persist.vendor.a6l.ril.volte=1` starts `a6l-imsdcm` (volte2). Keep it 0 until step 5 passes.
  - `persist.vendor.a6l.voice.session_switch=1` is needed only if the LTE VSID ≠ the CS VSID.

## 5. Risks / unknowns (honest)
- **Nothing ran on hardware.** The main risks, in order:
  1. IMS does not register (volte2 unknowns: IMSDCM handshake, MBN, Orange TAC eligibility).
  2. NAS 0x007C semantics are inferred from qcrild disassembly plus the IDL layout (the numbers are exact; the "CS/LTE/WLAN" meaning comes from the vs_type use).
  3. The session name the ADSP expects for a separate VoLTE stream (`default volte voice` vs the VSID string) is untested. The parameter lets the attended test try each one without rebuilding.
- The audio-RAT-change TLV meaning (0x10 u32 = session info, 0x11 = RAT as call mode) comes from the stock handler code; only logged.
- Registering VOICE indication 0x23 through `indicationRegisterVolte` happens only in the CLI. The HAL keeps its old registration, so its behaviour is unchanged.
- The rc switch relies on init being allowed to write `/sys/module/q6mvm/parameters/*`. Init writes sysfs in the stock rc files; verify under enforcing when the switch is ever turned on.
- The rebuilt `q6mvm.ko` is loaded next to audio6's other q6voice modules, which came from the same worktree source. MODVERSIONS is off. If the worktree had drifted since audio6, a struct mismatch would show up as an oops at the first call. The rom-v2 series build (all modules rebuilt together) has no such risk.
- `sendImsSms` is covered by a syntax check only. The Android SMS path with IMS registered is untested (it needs the ROM).

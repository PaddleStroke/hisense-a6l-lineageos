# audio6: microphone selection, gains, mono capture on MultiMedia2 (25 Sep 2026 night, agent `audio6`)

Offline only. Nobody touched the phone, and `m` was not run. Relay scripts: `audio6-01` … `audio6-13`.

## 1. What the 25 Sep audio5 capture really contains
* The laptop `v75/logs/au5-out/cap-.wav` is variant D (MM2, 16 kHz, 1 ch, headset mic). It is copied to
  `firmware/extracted/audio6-20260925/au5/cap-D-headset-16k.wav`.
* The first 0.5 s holds a start-up transient (peak 77 LSB, that is the reported −52.6 dBFS). **After that, rms is 0.8 LSB
  (−92 dBFS)**, the spectrum is flat, and there is no mains hum and no ambient noise.
* **So this is not "quiet speech". No analog signal reached the ADC at all.** It is only the quantisation or idle
  modulator floor. A biased electret mic at stock gain would show room noise well above this.
* **Raising the gain cannot fix this.** The gains already equal stock: ADC2 Volume 6 and DEC 0 dB.
* Stereo gives EINVAL (the path is mono, see stock `INT3_MI2S_TX Channels`=One). Mono works.
* Why it is silent is **not yet known**. The DAPM and register state during the successful variants were never captured
  (audio5 printed DAPM only for variant A, which failed to open). The candidates:
  1. the headset had no mic, or the Mic Jack was off (not logged);
  2. MIC BIAS External2 was not powered;
  3. the ADC2/TX2 analog front end or serial-TX mapping in the mainline pm8916-wcd-analog driver on the PM660L;
  4. the main mic was never tested.
* Checked and **ruled out offline**:
  * PDM TX pin: gpio20 is `pdm_tx` = func1, drive 8, the same as stock `cdc_pdm_2_gpios_active`.
  * AFE SD line: INT3 MI2S tx-lines 0x3, and mono uses SD0 as in CAF.
  * Mic-bias supply: L7B is pm660l_l7, as in stock `cdc-vdd-mic-bias`.
  * `micbias1/2-ext-cap` and `mbhc` properties are present in the base DT.

## 2. Stock mic configuration (source of truth)
* The stock HAL loads `vendor/etc/mixer_paths.xml` for card `sdm660-snd-card`. The `_mtp`/`_skus` files use
  DMIC3/DMIC4 and belong to other boards.
* That file (with Hisense overrides) sets:
  * `handset-mic` = `voice-rec-mic` = `unprocessed-mic` = **adc1**: ADC1 Volume 8, DEC1 MUX ADC1, ADC1_INP1 Switch 1.
    `handset-record-mic` uses ADC1 Volume 6.
  * `headset-mic` = **adc2** (ADC2 MUX INP2, DEC1 MUX ADC2) with **ADC2 Volume 6**.
  * `speaker-mic`/`factory-aux-mic` = **adc3**: ADC3 Volume 8, ADC2 MUX INP3, DEC1 MUX ADC2 (ADC3 shares serial TX2).
  * `camcorder-mic` = adc2(INP3) + adc1 in stereo, which is impossible on our mono path, so the ROM uses the main mic.
  * Top level: ADC1/2/3 Volume 4, DEC1–4 Volume 84 (0 dB). Mainline name: `Digital TX1/TX2 Digital Volume`.
* Stock DT routing: AMIC1←MIC BIAS External, AMIC2←MIC BIAS External2, AMIC3←MIC BIAS External, with micbias1/2
  ext-cap and hs-micbias external.
* The V74 base lacks **AMIC3's bias route**.

* Options: `RATE=16000` gives the voice-recognition rate, `SECS=n` sets the length, and `MODE=capsec` is an
  informative secondary-mic run. capsec is expected to be SILENT on the test DT because it has no AMIC3 bias.
* **Send the whole output, not grepped.**

Each capture prints:
* jack states (with a warning if Mic Jack is off for caphs, or a headset is plugged for capmain);
* the controls and the L7B regulator;
* **during the capture**: pcm status, DAPM widgets (MIC BIAS External1/2, MIC_BIAS1/2, ADC1/2/3, AMIC1-3, ADC2 MUX,
  PDM_TX, clocks), LPI pins 18–25, PM660L codec registers f140–f147 (MICB), f160–f16f (TX_EN) and f040–f05f
  (CDC_D clk/conn), read by seeking in regmap debugfs so only those registers are read, and the LPASS digital-codec
  registers (full dump in `/tmp/audio6-out/lpass-codec-regs-*.txt`);
* the tinycap output, klog errors, the level per 0.5 s block, and `A6L_AU6_CAP_<main|headset>_PASS|SILENT|FAIL`.

**How to read the result:**
| main | headset | meaning / next step |
|---|---|---|
| PASS | PASS | Mic paths are right. Check the level (speech peak −30…−10 dBFS expected). If low, raise ADC1 to 8 / TX1 to 90 (+6 dB) in the XML. |
| PASS | SILENT | Main path is fine. Headset: check Mic Jack, and that MIC BIAS External2 is On with f144 bit7 set; otherwise bias2/mbhc. |
| SILENT | SILENT, MIC BIAS On, ADC On | Analog front end: compare PMREG f14x/f16x with a stock dump. The next offline step is to read the PM660L TX init sequence in the stock `msm_anlg_cdc` (stock-symbolized.elf). |
| SILENT, MIC BIAS Off | — | DAPM route/bias problem (DT audio-routing); the dump names the widget. |

## 5. Risks / unknown
* Nothing here ran on the phone. The cause of the silent capture is unknown (§1); the bundle is built to locate it.
* The a6l_wavlevel verdict threshold (−80 dBFS) is based on one sample: 0.8 LSB rms silent, against typical room noise.
* The AMIC3 route in the ROM DT is untested. It only takes effect when the secondary-mic path is selected, and nothing
  selects it automatically. If the card fails to probe, drop `a6l-audio-mics-v75` from OVLS.
* The `MultiMedia1 Mixer LPI_MI2S_TX_3`=0 change means any client that opens pcmC0D0c gets EINVAL (no back end). Only
  the old HAL behaviour did that, and merge3's patch moves input to device 1.

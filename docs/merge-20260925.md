## 2. Decisions taken (and why)
- **Same Image, new modules.** Every 24–25 Sep kernel change is modular (q6voice stack, q6asm-dai, q6routing, LPI pinctrl,
  camss, CCI/v4l2-cci, sensors, haptics, LEDs, IPA). A rebuilt Image would be the only unproven part of the boot path.
- **Radio OFF by default** (`persist.vendor.a6l.radio=0`, RF rule). One command enables it (§6). The radio HAL still
  starts and reports RADIO_UNAVAILABLE; Wi-Fi/BT/GNSS/telephony need the radio.
- **Gated by a property, not autoloaded:** charger driver `qcom_smbx` (`persist.vendor.a6l.charger=1`, attended C2 first:
  1.95 A, no software JEITA) and IPA `ipa2_lite`+`rmnet` (`persist.vendor.a6l.ipa=1`, loaded before mss; MODE=load reset the
  phone on 24 Sep). Without the charger driver the PMIC charges with its bootloader/hardware defaults (as rom-v1).
- **Audio:** audio4 module set (kvoice q6voice stack as used in the 24 Sep call + audfix per-direction q6routing), CVD
  forced legacy (`q6voice.ko cvd_mode=0`, the mode that worked). Fallback without rebuild:
  `setprop persist.vendor.a6l.audio.q6routing upstream` + reboot loads `q6routing-upstream.ko` (the 24 Sep module).
  Speaker: voice+speaker DT with the TFA stub fallback (a failed TFA probe only mutes the speaker).
- **Voice DT in the base DT** (no runtime overlay): kvoice `a6l-voice-speaker-onbase-v75` (replaces audio3's speaker-onbase).
- **In-call glue (new):** the radio HAL sets `vendor.a6l.voice.active=1` while a call is dialing/alerting/active/held
  (not while an incoming call only rings); `a6l-q6voiced -r daemon` starts the CVD session and DSP voice routes;
  `a6l-audio-route` switches the codec to `voice-headphones` (headset, raw 84 = 0 dB, the level Pierre heard on 24 Sep)
  or `voice-handset` (earpiece) and the matching mic. No speakerphone (q6voice has no TERT route).
- **Haptics ilim:** the V75 dtso still says 400 mA; stock is 800 and the misc agent's fixed module defaults to 800, but
  the DT wins → the DT build sets `qcom,ilim-ma = 800`.
- **E-ink:** with the eink3 composer patch the e-ink DSI connector must stay connected (the composer ignores it by mode
  and leases it to a6l_epdd); `a6l-modules.sh display` keeps rom-v1's force-off only when no lease socket is configured.
- **microSD (new overlay):** stock `sdhci@c084000` → mainline `sdhc_2`: cd gpio54 **active-high** with pull-up (stock
  flags 0; same as the mainline sdm630 Nile boards), vmmc pm660l L5 2.95 V, vqmmc pm660l L2 1.8–2.95 V (the V74 base has no
  L2/L5 nodes; added with the stock windows). vold: `voldmanaged=sdcard1:auto`.
- **MTP NOT integrated:** the hals "gadget HAL fork" is the AOSP example stub (its setCurrentUsbFunctions never writes
  configfs or FunctionFS) and its Android.bp does not parse in this tree; the AOSP configfs rc needs `mtp.gs0` which
  mainline lacks. ADB stays on the proven configfs + soft_connect path. A real MonitorFfs-based gadget HAL is needed.
- **Thermal HAL dropped** (`android.hardware.thermal-service.example` is not an installable module in this tree; it
  only reported fake values).
- **SELinux** stays permissive (cmdline); the per-area policy dirs (radio, audio, q6voiced, gnss, eink, dualux vendor +
  system_ext) are compiled in so the daemons get their domains.

## 2. What the script does
Every mode logs to `/tmp/volte4-logs/volte4-<mode>-<time>.txt`. The raw qmicli output is saved as `list-*.raw`, `load.raw` and `activate-*.raw`. Digit runs of 13 or more (IMSI/ICCID-like) are masked to `NNNN*****NN`. Each qmicli call has its own timeout: 40 s for list, 180 s for load, 60 s for activate.
- **ro**: runs `qmicli -d qrtr://0 --pdc-list-configs=software`, then `volte-probe all` (PDC lines + IMSA). Prints `A6L_VOLTE4_CFG …` per config and `A6L_VOLTE4_STATE … active='…' orange_id=…`. Pass: `A6L_VOLTE4_RO_PASS active='ROW_Commercial' orange_loaded=no`. If qmicli lists 0 (for example the PDC indications never arrive), the script falls back to volte-probe's reading.
- **load**: runs the gates, then the pre-state. If Orange is already listed, prints `A6L_VOLTE4_LOAD_SKIP`. Otherwise it runs `qmicli --pdc-load-config=/tmp/volte4/mbn/France-Commercial-Orange.mbn` in 1 KiB chunks and expects `Finished loading`. After that Orange must be listed (Inactive). Pass: `A6L_VOLTE4_LOAD_PASS id=965d8d76…`. It records `A6L_VOLTE4_EFS` sha256 prefixes of the RAM copies and a **read-only** hash of the real modemst1/2, before and after.
- **activate**: runs the gates, then `qmicli --pdc-activate-config=software,<orange id>`, which does Set Selected + Activate. It then:
  1. Watches for the SSR for up to 45 s, using remoteproc state ≠ running or the klog lines `fatal error received`, `crash detected`, `recovering` or `is now up`.
  2. Waits for `running` for up to 180 s. If the state is `crashed` for 20 s it writes `recover` to `recovery`; if it is `offline` for 20 s it writes `start` to `state`.
  3. Checks that rmtfs, tqftpserv and diag-router are alive. It restarts diag-router with radio2's exact command. If rmtfs or tqftpserv died it stops and says to reboot.
  4. Waits for PDC to answer (`--pdc-noop`), then watches for `WATCH_AFTER=60` s for new `fatal error` lines.
  5. Checks that Orange is Active.

  Pass: `A6L_VOLTE4_ACTIVATE_PASS active='France-Commercial-Orange'`. If the modem does not restart by itself, the script says so, and `MANUAL_RESTART=1` does a remoteproc stop/start.
- **verify**: Orange must be Active (`A6L_VOLTE4_VERIFY_PASS`). The script then chains `KEEP_ONLINE=1 SKIP_RADIO=1 sh /tmp/volte2/volte2-test.sh`, passing `A6L_PIN` through, and prints `A6L_VOLTE4_VOLTE2_RESULT …`. `NO_VOLTE2=1` stops after the PDC check.
- **revert**: select + activate ROW_Commercial (`7af52eaad094b6617fd163ca7370863364601f22`, or `REVERT_ID=`) with the same restart handling. Pass: `A6L_VOLTE4_REVERT_PASS`. **The simplest revert is a reboot**, because the RAM EFS copy is discarded.

**Safety gates.** `load`, `activate` and `revert` stop with `A6L_VOLTE4_ABORT` and rc 20 **before any write** unless all of these hold:
- `A6L_RF_APPROVED=1`.
- The bundle `SHA256SUMS` checks out.
- The MBN sha256 and size equal the pinned values.
- The modem remoteproc (`4080000.remoteproc`) is `running`.
- **Exactly one** rmtfs process is running, and its cmdline contains `-o /tmp/rmtfs`.
- `/tmp/rmtfs/modem_fs1` and `modem_fs2` are present, and each has the **same size as its partition**.
- **No process** has modemst1, modemst2, fsg or fsc open. This is checked on every `/proc/*/fd`, by mmcblk name and by by-name path.
- **No other QMI client** is running: a6l-qmi, a6l-imsdcm, volte-probe, another qmicli, qcrild/rild or a radio HAL. With these gates the modem's PDC sees only us, and only the modem uses the RAM EFS.

The mock proved each gate aborts, and that no load or activate command was issued in any gate test.

## 3. Attended commands (V74 recovery, **fresh boot**, laptop `~/A6L-usb-20260915`; Pierre types the RF lines)
```
cd ~/A6L-usb-20260915 && (cd v75/volte4 && sha256sum -c SHA256SUMS | tail -1) && mkdir -p v75/logs
# 0. toybox links in /tmp/bin as usual (prep), then push

adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1 A6L_KEEP=1 A6L_WATCH=20 D=/tmp/radio2; sh /tmp/radio2/run.sh' 2>&1 | grep -E "A6L_(RADIO_DONE|MODEM_STABLE|MODEM_CRASH|HW_FAIL|KEEP|RMTFS_COPY)"
# 2. read-only                                                          -> A6L_VOLTE4_RO_PASS active='ROW_Commercial' orange_loaded=no
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export MODE=ro; sh /tmp/volte4/volte4-test.sh' 2>&1 | grep -v linker | tee v75/logs/volte4-ro-$(date +%H%M).txt
# 3. (Pierre) PDC load (EFS write -> RAM copy only)                     -> A6L_VOLTE4_LOAD_PASS id=965d8d76...

# 4. (Pierre) select + activate -> modem restarts (up to ~6 min)          -> A6L_VOLTE4_ACTIVATE_PASS active='France-Commercial-Orange'
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1 MODE=activate; sh /tmp/volte4/volte4-test.sh' 2>&1 | grep -v linker | tee v75/logs/volte4-act-$(date +%H%M).txt
# 5. (Pierre) verify + volte2 (PIN, online, IMS attempt, stays online)  -> A6L_VOLTE4_VERIFY_PASS + A6L_VOLTE4_VOLTE2_RESULT ... imsa=present registered=yes (hoped)
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1 A6L_PIN=<PIN> MODE=verify; sh /tmp/volte4/volte4-test.sh' 2>&1 | grep -v linker | tee v75/logs/volte4-verify-$(date +%H%M).txt
# 6. volte3 (docs/volte3-20260926.md §3): audio6 ovl + ADSP bundle + volte3 MODE=audio should precede step 1 if a call with sound is planned
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export MODE=status; sh /tmp/volte3/volte3-test.sh' 2>&1 | grep -v linker | tee v75/logs/volte3-status-$(date +%H%M).txt
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1; export NUM=<own> A6L_DIAL_TO=<own> SECS=30 MODE=call; sh /tmp/volte3/volte3-test.sh' 2>&1 | grep -v linker | tee v75/logs/volte3-call-$(date +%H%M).txt
# 7. revert (optional; a reboot does the same)                          -> A6L_VOLTE4_REVERT_PASS active='ROW_Commercial'
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; export A6L_RF_APPROVED=1 MODE=revert; sh /tmp/volte4/volte4-test.sh' 2>&1 | grep -v linker | tee v75/logs/volte4-revert-$(date +%H%M).txt
adb -s HLTE730T-PROBE pull /tmp/volte4-logs v75/logs/volte4-logs
```
Order matters. Run load and activate **before** the SIM PIN and before going online: step 1 leaves the modem in low power. The modem restart in step 4 resets the SIM session, so the PIN is given in step 5, and volte2 enters it. Do not start a6l-imsdcm, a6l-qmi or volte3 in the background during steps 3, 4 and 7, because the gate refuses to run.

| `A6L_VOLTE4_SSR seen=1 … recovery=enabled`, then `A6L_VOLTE4_MODEM state=running after Ns`, then `A6L_VOLTE4_DAEMON … pid=…` ×3, `A6L_VOLTE4_PDC_BACK`, `A6L_VOLTE4_WATCH 60s … new_fatal=0` | a clean modem restart into the Orange config |

## 5. Failure table
| symptom | likely cause | action |
|---|---|---|
| `A6L_VOLTE4_ABORT` + `GATE_FAIL …` | a precondition is missing (radio2 not run with KEEP, a stale a6l-imsdcm, rmtfs not in RAM mode, a wrong bundle) | fix what the line names. Nothing was written |
| `qmicli … couldn't access QRTR bus` / `couldn't open the QmiDevice` on the phone | qrtr module not loaded, or the musl loader cannot exec from /tmp | check `lsmod \| grep qrtr` (radio2 loads it) and `mount \| grep /tmp` (noexec?). Read-only, so it is safe to retry |
| ro: `qmicli_total=0` but volte-probe lists 4 | qmicli did not receive the List Configs indication in 2 s (it does not send PDC Register) | stop; the load/activate indications would probably be missing too. Report the raw log |
| load: `error: couldn't load config: …` / `frame reset requested` / timeout | PDC refused the file (signature, space, or an MBN mismatch) | nothing is active yet; reboot to be clean. Keep `load.raw` |
| load passes but the Orange id differs from `965d8d76…` | the modem assigned its own id | fine; the script uses the listed id |
| activate: `SSR seen=0` | activation is pending, the modem did not reset | check that `pending_id` = Orange; rerun `MODE=activate MANUAL_RESTART=1` (remoteproc stop/start, as radio2 does) |
| `A6L_VOLTE4_MODEM state=crashed/offline` after 180 s | the modem does not come back on this mainline stack | **reboot** (the RAM EFS is discarded; the original config returns) |
| `A6L_VOLTE4_FAIL_DAEMON rmtfs died` / tqftpserv died | the daemon did not survive SSR | reboot; next time add a stop/start around the activate |
| `new_fatal>0`, text `dog_hb … diag` | diag-router did not reconnect after SSR (the 23 Sep starvation symptom) | the script restarts diag-router if it died; if it is alive but stale, reboot and report |
| verify: active is still `ROW_Commercial` | the modem's auto-selection reverted it, or the activate did not stick | keep the log; try activate once more; otherwise report |
| `imsa=absent` with Orange active | the IMS task needs something else (the IMSDCM handshake, or a wait for the SIM/online state) | volte2 decision table (docs/volte2-20260925.md) |
| `imsa=present registered=no` | IMS PDN/registration failed (APN `ims`, Orange TAC eligibility) | volte2 table; stock check step −1 (docs/volte-20260925.md) |

## 6. Risks (honest)
- **Nothing ran on the modem.** The first contact of libqmi's QRTR backend with this modem is untested. volte-probe (raw QRTR) works, so the transport is fine; the qmicli framing is standard.
- **Modem restart on mainline**: MCFG Activate resets the modem. How that looks here is untested: an error-fatal SSR with remoteproc recovery, or a pending state. The script handles both and never needs anything but a reboot to recover.
- **Load writes the modem EFS.** Under rmtfs `-o /tmp/rmtfs` this lands in RAM. The gates make sure that is so, and a read-only hash of the real partitions is logged before and after. **If the gates were bypassed** (rmtfs without `-o`), the change would persist on eMMC. It would be reversible with PDC (revert) but not with a reboot. pmOS warns that PDC mistakes can leave a modem misconfigured.
- An official Orange MBN on an unlisted device or firmware combination: the MBN comes from this exact NON-HLOS, so no version mismatch is expected.
- The musl `ld-musl` loader exec'd directly from `/tmp` of the recovery: this works if `/tmp` is not noexec. The other bundles already run binaries from /tmp.

## 7. After IMS registers: what the ROM needs (short research)
**Keeping the MBN.**
- PDC Load and Activate write the MCFG state into the modem EFS (modemst1/2 via rmtfs).
- In the ROM, rmtfs serves the **real** partitions (no `-o`), so a single load + activate **persists across boots**. The modem boots straight into Orange with no reset.
- The stock design adds AP-side selection: qcrild's MbnModule copies `mcfg_sw.mbn` files into `/data/vendor/modem_config/mcfg_sw` and chooses by SIM IIN/PLMN (`persist.vendor.radio.sw_mbn_*`). Some modems can also auto-select by themselves: Qualcomm's "modem based carrier auto-selection", or Quectel `AutoSel`. The stock A6L kept `ROW_Commercial` active with only 4 MBNs loaded, so we cannot rely on modem auto-selection.
- **Recommendation: a small boot-time check in our radio HAL, or an init oneshot.**
  1. Read PDC Get Selected.
  2. If the SIM PLMN is 208-01/208-02 and the active config is not Orange, Load it (if it is not listed) and Activate it. This costs one modem restart, once.
  3. Otherwise do nothing, so later boots cost nothing.
  4. Add SFR/Bouygues MBNs the same way (from `aside/`) if Pierre ever changes carrier.
  5. Do the "load at each boot" only if the EFS approach misbehaves.
- The ROM must not ship qmicli plus glib (size and licence mix). Instead, add PDC Load/Select/Activate/List to our own QMI library in `device/hisense/a6l/radio/qmi` (a6l-qmi already speaks QRTR and has fake-modem tests). **Pierre's go is needed before any persistent EFS write.**

**Android side (LineageOS 24 radio HAL, modem-centric IMS = plan B, already in docs/volte3-20260926.md §4).**
- Without an ImsService, AOSP dials through `IRadioVoice.dial`, and the modem picks IMS by itself (Orange MBN `voice_domain_pref=3`).
- The HAL must:
  - report calls of type VOICE_IP from `getCurrentCalls`, and handle SRVCC transparently (done in volte3);
  - report **voice registration IN_SERVICE on LTE** when IMS voice is available. Otherwise the framework blocks dialling once there is no CS/CSFB;
  - implement `getImsRegistrationState` and `sendImsSms` (done in volte2/volte3);
  - send `emergencyDial` as QMI EMERGENCY;
  - fill `Call.audioQuality` (AMR-WB/EVS) to get the HD icon.
- **IRadioIms (AIDL)** exists for **AP-side** IMS stacks: updateImsRegistrationInfo, startImsTraffic, setSrvccCallInfo, triggerEpsFallback. It is optional, and not needed while the modem runs IMS.
- The IMS AIDL (`ImsService`/MmTelFeature) is needed only for the native VoLTE toggle and icon, Wi-Fi calling, RTT and `isImsRegistered()`. That would be a later option C: an ImsService that proxies the modem's IMSA state and VOICE_IP calls.

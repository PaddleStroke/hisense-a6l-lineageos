### Reading failures
| symptom | meaning / next step |
|---|---|
| `…TEMP-DISABLED … reason=WRONG_KEY` | password (or WPA3-only AP with an SAE issue): retry with `export A6L_WIFI_KEYMGMT=SAE;` then `WPA-PSK` |
| `CTRL-EVENT-NETWORK-NOT-FOUND` repeatedly, `A6L_WIFI_SCAN_RESULTS 0` | SSID typo, or regdb not applied (`A6L_WIFI_REG` not FR: 5 GHz/ch 12-13 passive in world domain) |
| `ASSOC-REJECT status_code=30/31/77` or `AUTH-REJECT` | PMF/SAE negotiation: `export A6L_WIFI_PMF=0; export A6L_WIFI_KEYMGMT=WPA-PSK;` (WPA2 only) |
| stuck ASSOCIATING, ath10k `wmi` errors in the klog tail | firmware side: collect, add `export A6L_WIFI_DEBUG=1;` (supplicant -d to /tmp, never -K; the SSID/password are never printed) |
| DHCP fail after COMPLETED | no data path (4-way done but no EAPOL/data frames): look at `A6L_WIFI_STA … rx/tx` |
| ping ok, DNS/HTTP fail | Livebox DNS; the script also tries 1.1.1.1 as DNS and HTTP to 1.1.1.1 directly |
| `A6L_BT_PUBLIC_ADDR … status≠0` | vendor BD-address write refused: rerun with `export A6L_BT_ADDR=…` or check the klog tail (qca) |
| `A6L_BT_DISCOVERY type 0x07 status=…` | LE not supported in that state: the tool falls back to BR/EDR only (still finds a discoverable phone) |
Knobs: `A6L_WIFI_COUNTRY` (FR), `A6L_WIFI_TIMEOUT` (40), `A6L_WIFI_HOLD` (stay connected N s, e.g. 60, to watch RSSI), `A6L_WLAN_MAC`, `A6L_BT_SECS` (15), `A6L_BT_ADDR`.

## 3. Secrets handling (Pierre's rule: never echoed, never in laptop logs)
* Read on the phone with `IFS= read -r` (stdin) or from env vars that the script unsets at once; the config is written with a
  shell here-document (no argv), mode 600 in `/tmp/a6l-wifi` (mode 700, RAM), and `rm -rf` in an EXIT trap (also on Ctrl-C).
  The SSID is written as hex. Printed: only lengths, BSSID, frequency, key_mgmt, cipher, signal.
* Everything printed from the supplicant log goes through a mask (`SSID='…'`, `ssid="…"`, `SSID:` lines, `psk=`/passphrase
  lines, hexdumps removed). `wpa_cli status` output drops `ssid=`. The supplicant never runs with `-K` (key material).
* Verified in the mock run: the SSID and password strings occur 0 times in the captured output.

## 4. ROM integration (ledger lines added)
* The ROM keeps the AOSP `wpa_supplicant`/Wi-Fi HAL from `hals` (unchanged); this bundle is **test-only** (recovery).
* **New for the ROM: `device/hisense/a6l/wifi/wifi-regdb.mk`** (PRODUCT_COPY_FILES of `external/wireless-regdb/regulatory.db{,.p7s}`
  to `/vendor/firmware`, where `rom/init/init.qcom.rc` points `firmware_class.path`). Without it cfg80211 stays in world domain
  `00` in the ROM too. For the `flash` agent: `$(call inherit-product, device/hisense/a6l/wifi/wifi-regdb.mk)` in the ROM product.
* `a6l-bt-scan` confirms (or not) the hals finding that hci0 comes up **unconfigured** and that `SET_PUBLIC_ADDRESS` with
  WLAN MAC + 1 is accepted: that is exactly what `a6l_macs bt` does in the ROM before the Bluetooth HAL starts.

## 5. Risks and unknowns
* Association itself is untested: ath10k-snoc + WCN3990 FW with mac80211 SME, SAE and PMF have never run on this phone. The
  failure table covers the likely cases; the WPA2-only knob removes SAE/PMF from the equation.
* adb stdin forwarding to the V74 recovery adbd is unverified (fails safe; fallback line given).
* The BT mgmt-socket path has only parser tests; the opcode/event layouts follow `include/net/bluetooth/mgmt.h` (same as
  `a6l_macs`). The public address is written to the controller's RAM only.
* RF: Wi-Fi association + DHCP (hostname `a6l-test` shows up in the Livebox device list), BT inquiry + LE scan. No pairing.
* The test adds a default route (metric 1234) on wlan0 and removes it at the end; the IPA/rmnet data path is not touched.

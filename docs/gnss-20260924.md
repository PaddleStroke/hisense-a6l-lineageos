## 2. Design

```
 LocationManager / GnssLocationProvider (system_server, JNI, AIDL cpp)
          │ binder: android.hardware.gnss.IGnss/default (V7)
 android.hardware.gnss-service.a6l   (vendor, user gps, class hal)
   hal/Gnss.cpp      IGnss + IGnssConfiguration (blocklist) + IGnssDebug (last fix); every other extension returns
                     EX_UNSUPPORTED_OPERATION (the JNI's checkAidlStatus then treats it as "not supported")
   lib/GnssEngine    worker thread: connect / lookup / configure / START / STOP / injections; re-arms after a modem restart
   lib/LocClient     reader thread: QRTR packets -> responses (by txn) / indications / name-service events
   lib/qrtr_transport AF_QIPCRTR SOCK_DGRAM (in-kernel qrtr + name service: the same stack rmtfs/tqftpserv/diag-router use)
          │ QRTR (SMD/GLINK) ─ modem: service 16 "Location service (~PDS v2)"
```

The engine starts once, when the framework calls `setCallback()` at boot. It waits for the LOC service instead of polling,
because a `NEW_LOOKUP(16)` on the QRTR name service stays open. While the radio is off (`persist.vendor.a6l.radio=0`)
the HAL is idle: the socket is open and the LOC service is simply absent. If AF_QIPCRTR itself is missing (qrtr.ko not
loaded), it retries every 5 s and logs one line per 12 attempts. When the modem restarts it sees
`DEL_SERVER` and later `NEW_SERVER`, then re-sends REG_EVENTS, SET_OPERATION_MODE, SET_NMEA_TYPES and START if a session was active.

### QMI LOC messages used (msg id / TLVs)
| message | id | TLVs sent / parsed |
|---|---|---|
| INFORM_CLIENT_REVISION | 0x0020 | 0x01 u32 = 2 (the result is ignored) |
| REG_EVENTS | 0x0021 | 0x01 u64 = position 0x1, SV 0x2, NMEA 0x4, inject-time req 0x10, inject-position req 0x40, engine state 0x80, fix session 0x100 |
| SET_OPERATION_MODE | 0x004A | 0x01 u32 = 4 STANDALONE by default (`persist.vendor.a6l.gnss.mode` = standalone, default or msb). The ROM has no SUPL/data path, so STANDALONE avoids waiting on server-connection requests nobody answers |
| SET_NMEA_TYPES | 0x003E | 0x01 u32 = GGA, RMC, GSV, GSA, VTG, GLGSV, GNGSA (0x19F) |
| START / STOP | 0x0022 / 0x0023 | 0x01 u8 session = 1; 0x10 recurrence = 1 (periodic); 0x11 accuracy = 3 (high); 0x12 intermediate = 1 (on); 0x13 min interval in ms |
| INJECT_UTC_TIME | 0x0038 | 0x01 u64 UTC ms; 0x02 u32 uncertainty ms (framework `injectTime`, CLI `--inject-time`) |
| INJECT_POSITION | 0x0039 | 0x10 lat f64; 0x11 lon f64; 0x12 horUnc f32; 0x13 confidence u8 = 68 (framework `injectLocation`; **least certain layout**) |
| DELETE_ASSIST_DATA | 0x0044 | 0x01 u8 deleteAll = 1 (`deleteAidingData(ALL)`, CLI `--cold`) |
| SET_ENGINE_LOCK | 0x003A | 0x01 u32 = 1 NONE. Only sent with `--unlock` or `persist.vendor.a6l.gnss.unlock_engine=true`, because it writes modem NV (with rmtfs read-only, the default, the change stays in RAM) |
| POSITION_REPORT ind | 0x0024 | status 0x01, session 0x02, lat/lon 0x10/0x11, horUnc 0x12, speed 0x18/0x19, alt ellipsoid/MSL 0x1A/0x1B, vertUnc 0x1C, heading 0x20/0x21, tech 0x23, DOP 0x24, UTC ms 0x25, leap 0x26, GPS time 0x27, time unc 0x28, SVs used 0x2C, altitude assumed 0x2D |
| GNSS_SV_INFO ind | 0x0025 | 0x01 altitude assumed; 0x10 list: u8 n + n × 28 bytes (valid u32, system u32, id u16, health u8, status u32, info u8, elevation, azimuth, SNR f32) |
| NMEA ind | 0x0026 | 0x01 string (≤ 200 characters), or 0x10 expanded string when present. Split on CR/LF |
| ENGINE_STATE / FIX_SESSION_STATE / INJECT_TIME_REQ / INJECT_POSITION_REQ ind | 0x2B / 0x2C / 0x28 / 0x2A | forwarded as `gnssStatusCb(ENGINE_ON/OFF)`, a log line, `gnssRequestTimeCb`, `gnssRequestLocationCb` |

Behaviour details:
- Only SUCCESS reports that carry lat/lon become `gnssLocationCb`. IN_PROGRESS reports are logged or printed as
  INTERMEDIATE. FAILURE, TIMEOUT and ENGINE_LOCKED are logged.
- If the modem sends no NMEA within 2.5 s of a fix, GGA and RMC are synthesized from the fix. The CLI prints them as
  `NMEA(synth)`.
- SV ids are mapped to Android numbering: SBAS 33-64 → 120-151, GLONASS 65-96 → 1-32, BDS 201-263 → 1-63, Galileo
  301-336 → 1-36. USED_IN_FIX comes from the used-SV list in the last position report, and satellites on the blocklist
  have that flag cleared.
- Capabilities are SCHEDULING and SATELLITE_BLOCKLIST. There are no raw measurements, navigation messages, batching,
  geofencing, AGNSS/SUPL, PSDS/XTRA or antenna info.

## 4. Attended test A: recovery RAM session with the modem up (needs Pierre's RF go, because the modem is started)
GNSS itself only receives, but starting the modem is covered by the radio rule. Use the proven v74/radio2 order (qrtr,
rmtfs on RAM copies, tqftpserv, diag-router, `echo start`), then wait for "remote processor is now up" and the QMI
services. Then, from the laptop (`~/A6L-usb-20260915`):
```
adb -s HLTE730T-PROBE push <repo>/firmware/extracted/gnss-20260924/a6l_gnss_test /tmp/
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; chmod 755 /tmp/a6l_gnss_test; /tmp/a6l_gnss_test --list'
#   expect: "A6L_GNSS QRTR server service=16 version=2 ... <- LOC" (plus the other modem services)
adb -s HLTE730T-PROBE shell 'export PATH=/tmp/bin:$PATH; /tmp/a6l_gnss_test --seconds 900 --inject-time --record /tmp/gnss-rec.log' | tee gnss-run1.txt
adb -s HLTE730T-PROBE pull /tmp/gnss-rec.log .
```
Put the phone at a window or outdoors, rear up. What Pierre should look for:
1. `SERVICE up`, then no `error` after REG_EVENTS, SET_OPERATION_MODE and START (use `-v` to see every request).
2. `ENGINE on` and `SESSION started` within about 1 s.
3. `SV total=… with_cn0=…` lines. Satellites with C/N0 above 25 should appear within 1-2 minutes if the antenna path works.
4. `FIX lat=… lon=… acc=…m`. A cold standalone start with no assistance data takes anywhere from about 1 to 15 minutes.
   The last line should read `A6L_GNSS_RESULT result=FIX` (exit 0).
- If there is no SV with C/N0 at all after 5 minutes: suspect the GNSS antenna/LNA power path. The stock modem enables it
  itself; there is no AP-side regulator in the stock DT for GNSS.
- `position report status ENGINE_LOCKED`: rerun with `--unlock` (writes modem NV, RAM only with rmtfs `-r`).
- Any `error N` on START: rerun with `--mode default` and send the `-v` log.
- The `--record` log replays offline with `a6l_gnss_test --replay gnss-rec.log`, so the real modem's indications become
  test fixtures (`tools/build-gnss-a6l.sh` style).

## 6. Risks and unknowns
- TLV layouts are taken from the public IDL. The riskiest ones are INJECT_POSITION, the 28-byte SV record and the
  optional START TLVs 0x11 to 0x13. Every parser checks bounds, so a mismatch shows up as "malformed" or an `error N`
  in the log rather than a crash. The first real `--record` log settles this.
- Newer modem firmware may report satellites only through the extended SV/measurement indications and not 0x0025. In that
  case positions and NMEA still work and only the satellite list stays empty.
- Engine lock and NV-based GPS configuration on this carrier firmware are unknown.
- TTFF is standalone only: no XTRA and no SUPL, because there is no data path yet. Time injection helps, and the framework
  does it once NTP time is known.
- QRTR as an unprivileged user (`gps`): ephemeral autobind and sending to the name service need no capability on 7.2,
  but this is untested on the phone. The CLI runs as root.
- rom-v1 is permissive and the sepolicy is not compiled. `hal_gnss_default` needs `qipcrtr_socket` access when enforcing.

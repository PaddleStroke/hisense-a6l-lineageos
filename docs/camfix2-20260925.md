## 1. What the t25 log proves

**The receive side is up.**
- `A6L_CSID0 csi0 rate 310000000`
- `A6L_CSIPHY0 … settle_cnt 20 mask 0x8f`
- IMX576 frame counter goes 255 -> 6 in 200 ms, then 157 frames in about 5 s (≈30 fps).

**No error lines at all between stream-on and stream-off.** The log has none of the following:
- `VFE sof timeout`, `reg update timeout`, `halt timeout`
- ISPIF overflow
- SMMU fault
- `Missing ready buf`

**The VFE saw RDI0 SOF (inference).** The previous run (without ISPIF) printed `VFE sof timeout` at stream-off. This run did not.
- `vfe_disable_output()` waits for the next **RDI0 SOF** (500 ms) and then for a **reg-update ack**. Both completed, and it also got the halt ack.
- So the VFE IRQ works, and frame starts arrive through CSIPHY → CSID0 → ISPIF → VFE0 RDI0.

**What is missing is the write-master "ping-pong done" IRQ, i.e. the frame reaching memory.** Upstream handles none of the silent causes:
- VFE 4.8 unmasks `IMAGE_MASTER_n_BUS_OVERFLOW` (IRQ_STATUS_1 bits 9..15), but `vfe_isr()` ignores those bits.
- sdm660 has **no interconnect vote** (`sdm660_resources` has no `icc_res`), although the DT has `interconnects = <&mnoc 5 &bimc 5>` "vfe-mem".
- An SMMU/IOVA problem would also be silent.

So the data stops **between the VFE RDI input and DDR**. This is not a sensor, lane or CSID-format problem. Lane mask 0x8f = clock lane 7 + data 0-3, which matches the stock LaneAssign 0x4320 (see camfix doc). The stock cam-smmu "vfe" cb uses SIDs 0xc00-0xc03, and mainline `iommus` uses the same SIDs.

**The oops.** `vfe_pm_domain_off+0x38 → device_link_del(NULL)`. On sdm660, `vfe->genpd` is *not* NULL: `has_pd` + `attach_by_id` works with the DT `power-domains = <VFE0_GDSC>, <VFE1_GDSC>`, and camss_top is their parent in mmcc-sdm660. The real cause is `ispif_reset()`:
- It calls `camss_pm_domain_on/off(VFE0)` and `camss_pm_domain_on/off(VFE1)` while VFE0 is already powered by `vfe_get()`.
- `device_link_add()` returns the same link with kref+1. The nested off then calls `device_link_del()` and sets `vfe->genpd_link = NULL`.
- At STREAMOFF, `vfe_put()` → `vfe_pm_domain_off()` → `device_link_del(NULL)` → oops. The mutex is held, which explains the next insmod getting stuck in D state.
- This path only exists because camfix put ISPIF back in the graph.
- The GDSC was not the cause of "no frames": the link kept one reference, so the VFE stayed powered.

## 2. Changes (`device/hisense/a6l/kernel/camera/patches/camfix2_patch.py`, applied after `camfix_patch.py`)
Cumulative diff against the 7.2.3 source: `patches/camss-sdm660-camfix2-cumulative.patch` (477 lines).

1. **Oops fix:** the per-VFE power-domain link is refcounted.
   - A new field `a6l_pd_users` is added in `camss-vfe.h`.
   - A nested `on` only counts. `off` deletes the link on the last user only.
   - A NULL link now gives a warning instead of an oops.
2. **ICC vote for sdm660:** `icc_res_660 = { "vfe-mem", avg 1 GB/s, peak 2 GB/s }`. It is set on runtime resume, as for the other SoCs.
3. **Diagnostics** (module param `a6l_dbg`, default 1; set it at runtime in `/sys/module/qcom_camss/parameters/`):
   - `A6L_CSIPHY<n>_IRQ` (first 8 PHY IRQs) and `A6L_CSIPHY<n>_STOP`: the 12 COMMON_STATUS registers (lane/SOT/ECC error bits).
   - `A6L_CSID<n> irq#k status 0x…` (first 16), plus `A6L_CSID<n>_START` / `_STOP` dumps of registers 0x000–0x0ff (non-zero rows).
     - Optional `a6l_csid_irqmask=<mask>` writes the CSID IRQ_MASK at stream-on, for packet/CRC/ECC IRQs.
   - `A6L_ISPIF irq#k vfe0 s0 s1 s2 vfe1 …` (first 16) and `A6L_ISPIF_STOP` with a dump of registers 0x000–0x4ff.
   - `A6L_VFE<n> irq#k s0 s1 pp` (first 12; `a6l_dbg=2` adds every 64th).
     - `A6L_VFE<n> ERR s1 … (ovf wm …) violation …` for bus overflow, violation or camif error.
     - `A6L_VFE<n>_STOP irqs N bits s0bX:count s1bY:count`: per-bit IRQ counters for the whole stream.
     - VFE register dump 0x000–0x15f (IRQ masks, WM0–3 cfg, **ping/pong addresses**), 0x300–0x35f (ping-pong status) and 0x400–0x4bf (bus BDG/RDI cfg).
     - Dumps are taken at stream-off, before the VFE is stopped, while the sensor is still streaming.
   - `A6L_VFE<n> <clk> rate … (min …)` for every VFE clock set. `a6l_vfe_min=<Hz>` sets a floor on the VFE core clock (default 0 = upstream).
4. **`run-camera.sh` (camfix2):**
   - bars/live refuses to run if dmesg already contains an oops ("reboot first").
   - It prints `KERNEL_OOPS_FAIL`, `VFE_ERR seen` and a `DIAG A6L_VFE0_STOP …` summary.
   - It saves the full capture dmesg to `/tmp/cam-<sensor>-<mode>.dmesg` and prints up to 160 relevant lines.
   - Camcap runs under `timeout 60` when available.
   - New env knobs `DBG=`, `VFE_MIN=`, `CSID_IRQMASK=`.
   - Probe prints `CAMSS_CAMFIX2_PASS`, which proves the new qcom-camss is the one loaded.

Build: `device/hisense/a6l/camera/tools/build-camfix2.sh` (build dir `/home/a6l/camfix2`, which also holds `src-snapshot/`).

Expected results:
- Probe: as before, plus `CAMSS_CAMFIX2_PASS`.
- Bars: **no oops at stream-off** (no `KERNEL_OOPS_FAIL`). That is the pass criterion for the fix.
- The `DIAG` line should be printed.
- If the ICC vote was the missing piece: `frame 0..3` and `CAPTURE_imx576_bars_PASS`.

How to read the DIAG / dump. VFE 4.8 bits:
- s0: b5 = RDI0 reg-update, b8+n = WM n ping-pong done, b31 = reset ack.
- s1: b29 = RDI0 SOF, b9+n = WM n bus overflow, b7 = violation, b8 = halt ack.

| Observation | Meaning / next step |
|---|---|
| `s1b29` ≈ 30/s, `s0b8..` (WM done) = 0, **`A6L_VFE0 ERR … ovf`** | WM cannot drain to DDR. The ICC vote did not help enough: check the `vfe_axi`/`throttle_axi` clocks and the SMMU. Retry with `VFE_MIN=300000000`. |
| `s1b29` counts, no WM done, no ERR | WM not armed. Check `A6L_VFE0_REG 0a0` (WM0 cfg, ping/pong: they must look like IOVAs, e.g. 0xff…, not 0) and the 0x46c RDI cfg. Send the `.dmesg`. |
| `s1b29` = 0 | SOF does not reach the VFE; the "SOF arrived" inference was wrong. Look at `A6L_ISPIF irq#` (overflow bits) and `A6L_CSID0_STOP`. Retry with `CSID_IRQMASK=0x7fffffff`: this may flood IRQs for ~1 s, and the dump shows the result. |
| `A6L_CSIPHY0_*` status non-zero | PHY lane errors: settle count. Retry after a reboot with `insmod qcom-camss.ko a6l_phy_fast=0`. |

Then run `s5k3t1` and `hi846` the same way (`MODE=bars SENSOR=…`, one per run), then `MODE=off`.

## 5. Risks / unknowns
- The ICC path `<&mnoc 5 &bimc 5>` comes from the upstream DT. If `devm_of_icc_get` fails, camss **probe fails** (no /dev/video) and `ISPIF_IN_GRAPH_FAIL` shows it. Fallback: the camera2 qcom-camss.ko with the NULL-deref risk. Tell the camfix agent, who can build an icc-less variant in 2 min.
- The register dumps read only inside the DT-mapped ranges while clocks are on. They are debug-only, and `DBG=0` disables them all.
- The IRQ-context `dev_info` calls are bounded (16/12/8 lines).
- The frame loss is not fixed for certain. This round makes the next run show exactly where data stops.
- Raising `VFE_MIN` above 300 MHz without MMCX corner voting may be unstable. Use only if needed.

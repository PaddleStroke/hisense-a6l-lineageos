# Radio HAL (calls, SMS, mobile data, SIM, network) for the A6L: agent `ril`, 24 Sep 2026

**Status in one line:** a native AIDL radio HAL (V4) over QMI/QRTR is **written, unit-tested offline and
built in the Lineage tree (`m` rc=0, 24 Sep 10:11)**. The attended test tool `a6l-qmi` is built as a static aarch64 binary. **Nothing ran on the phone.**
Mobile data is blocked on the kernel: SDM660 has **IPA v2.6L**, and mainline has no v2 support
(plan: `docs/ipa-sdm660-plan-20260924.md`). Calls will connect **without audio** (no q6voice/CVD on 7.2).
SMS and SIM/network have no kernel blockers.

## 1. Choice of stack (evaluated today)

| option | verdict |
|---|---|
| **aospm/qrild** (C++, AIDL radio **V1**, libqril + qmic + libqrtr) | Development halted by its author. `main` is a PoC ("hacky… full of memory leaks"). `rewrite` (default branch) only removed libqril, which moved to its own repo; the HAL was never ported to it. Data: it never asked WDS for DNS (Get Current Settings without the DNS bit), hard-coded `1.1.1.1`, printed the LE u32 IPv4 via `inet_ntoa` and configured the netdev itself. Useful as reference (rmnet netlink capture, UIM captures), not as a base |
| **libqmi** (+ libqrtr-glib, glib, meson) | Complete and correct message definitions (used here as the **spec**: `data/qmi-service-*.json`, test vectors). As a runtime dependency on Android it needs glib + gio cross-built into the vendor partition: heavy, slow to integrate into Soong, and the async GLib model does not fit the binder HAL well |
| ModemManager / oFono / Ubuntu Touch / Droidian | Linux-desktop stacks (D-Bus). Droidian/UT use Halium with the *vendor* RIL (qcrild), which needs the downstream kernel. Not usable here |
| **Chosen: own C++ QMI client + Google's libminradio** | `liba6lqmi`: a small codec plus an AF_QIPCRTR transport with in-kernel name-service lookup and typed requests for DMS/UIM/NAS/WMS/VOICE/WDS/WDA (TLV layouts from the libqmi JSON). No glib and no codegen. The HAL builds on **libminradio** (`hardware/interfaces/radio/aidl/minradio`, new in this tree: base classes for config/data/modem/network/sim V4 with sane defaults), copied as a static library without its ASan/fuzzer sanitizers. Messaging and voice bases are **generated** from the frozen AIDL (every method answers REQUEST_NOT_SUPPORTED unless implemented) |

Required versions (tree `hardware/interfaces/compatibility_matrices`): 202504 needs radio.* **3-4**, and
202604/202704 need **3-5**. The HAL is **V4** (inside both ranges). IMS (`radio.ims` 2-4) is optional in the
matrix and is not declared.

## 2. What is implemented

`device/hisense/a6l/radio/` (repo), same tree in WSL `/home/a6l/ril-work/radio`:

| path | content |
|---|---|
| `qmi/` (`liba6lqmi`, host+vendor) | `message` (codec, bounds-checked reader, GSM7/UCS2 helpers, IPv4/IPv6 formatting), `client` (QRTR socket, NEW_LOOKUP / NEW_SERVER / DEL_SERVER / BYE, txn matching, timeouts, indication dispatch on its own thread, service up/down callbacks), `services` (DMS ids/revision/opmode, UIM card status / read transparent+record / file attributes / PIN verify-unblock-change-protect / events, NAS serving system (resp+ind TLV shift) / signal info / operator name / cell location / mode pref / register / scan, WMS raw send / routes / event report / ack / read / delete / SMSC, VOICE dial/answer/end/all-call-info/manage/DTMF, WDS bind-mux / ip-family / start / stop / current settings / packet status, WDA data format), `datacall` (per-family WDS clients on one mux id, DNS/GW/MTU, rmnet link), `rmnet` (rtnetlink RTM_NEWLINK type rmnet), `sms` (PDU helpers for the CLI) |
| `hal/` | `ModemCore` (connects forever, waits for DMS/UIM/NAS/WMS/VOICE, registers indications, caches state, SMS ack FIFO, SSR = service gone → RADIO UNAVAILABLE and re-init), `RadioSimModemConfig.cpp`, `RadioNetworkData.cpp`, `RadioMessagingVoice.cpp`, `service.cpp`, `gen/` (generated voice/messaging bases + `gen_bases.py`) |
| `minradio/` | libminradio from the tree (Apache-2.0), unchanged, built as `liba6lminradio` |
| `tools/a6l_qmi_cli.cc` | `a6l-qmi` test tool (static NDK build for the recovery RAM session, and a vendor module) |
| `tools/ril-test.sh`, `tools/build-ril.sh` | attended test steps; offline build (host tests + NDK + `m`) |
| `tests/` | offline tests: fake QRTR name service + fake modem, real captured vectors (`vectors.h`) |
| `init/…rc`, `init/…xml` | service `vendor.radio-a6l` (user radio, NET_ADMIN/NET_RAW), VINTF fragment (7 HALs, V4, slot1) |
| `sepolicy/` | `hal_radio_default`: qipcrtr_socket, netlink_route (nlmsg_write), udp ioctls for IFF_UP/MTU, net_admin; props `ro.vendor.a6l.ril.*`, `persist.vendor.a6l.ril.*` |
| `radio.mk`, `BoardConfig-radio.mk` | for the flash agent (§6) |

Behaviour, by interface:
- **SIM:** real card status (USIM/ISIM apps, PIN1/UPIN states, ICCID from EF 2FE2 through the card session with a
  DMS fallback), IMSI (EF 6F07 under 7FFF, then 7F20), **iccIoForApp passthrough** (READ BINARY/RECORD, UPDATE,
  and GET RESPONSE converted from QMI file attributes to the TS 51.011 15-byte layout that `IccFileHandler`
  expects), PIN/PUK/change PIN, facility lock "SC", simStatusChanged on UIM indications.
- **Network:** voice/data registration from NAS Serving System (CS and PS attach, roaming, PLMN with 2/3-digit MNC,
  GSM7-packed operator names decoded), cell identity (LTE via cell-location info), signal (GSM/WCDMA/LTE),
  operator name (NITZ/PLMN name, then description, then numeric), NITZ indications, allowed network types →
  NAS mode preference, automatic/manual selection. Network scan is not supported.
- **Modem:** IMEI/SVN, baseband version, setRadioPower → DMS ONLINE / LOW_POWER, radio state UNAVAILABLE while the
  modem is down.
- **Messaging:** send (Android's SMSC+TPDU → WMS Raw Send format 6, "expect more" link timer), receive through
  **transfer-only routes** (fallback: store-and-notify on NV, read and delete), newSms / newSmsStatusReport with
  ACK_EXP, ack → WMS Send Ack (memory-full cause mapped), SMSC query, cell broadcast activation (config accepted
  and not programmed).
- **Voice:** dial / emergency dial (call type emergency, retried without it), current calls (state mapping,
  number, presentation, MT/MPTY), hangup, answer / reject, hold/swap/conference/ECT/separate (Manage Calls),
  DTMF, callStateChanged + callRing, emergency numbers 112/911. **No audio path.** Call forwarding, waiting,
  CLIR, USSD: not supported yet.
- **Data:** setupDataCall is asynchronous. It sends WDA data format once, then for each family (v4 and v6 legs,
  each with its own QMI client) bind mux → set family → start network (APN/user/pass/auth) → **Get Current
  Settings with the DNS bit**. It builds the addresses/gateways/**DNS**/PCSCF/MTU, creates
  `rmnet_data<N>` on `rmnet_ipa0` (flags 0x01) and returns them to Android, which configures the interface through
  netd. Disconnect indications → dataCallListChanged. **Without the IPA netdev, it fails fast with
  OEM_DCFAILCAUSE_1 and a 10 min retry hint.** setInitialAttachApn is accepted but not programmed into modem
  profile 1.

## 3. Offline verification (what was actually run)
- Host unit tests `tests/qmi_tests.cc`: **105 checks pass** under g++ with ASan+UBSan and under clang, also in WSL
  (`build-ril.sh` step 1), and pass 5 runs in a row (threading). Covered:
  - Real modem captures: DMS Get IDs and NAS Get Serving System (libqmi vectors, "Iliad" GSM7 name,
    LAC/CID), UIM Get Card Status (SDM845 over QRTR: 2 cards, USIM ready, AID, PIN retries), UIM Get File
    Attributes EF 6F62, converted to the 2G GET RESPONSE.
  - rmnet RTM_NEWLINK bytes identical to an iproute2 capture (except the ACK flag we add).
  - File path TLV encoding, IMSI/ICCID decoding, SMS-SUBMIT encoding and SMS-DELIVER decoding (classic vectors).
  - Client over the fake modem: service lookup, request/response, QMI error, timeout, indication dispatch,
    late service arrival, DEL_SERVER → NoService.
  - Data manager in modem-only mode: dual-stack, the **request carries the DNS bit**, IPv4 DNS `10.11.12.13`
    and IPv6 DNS `2001:4860:4860::8888` come out, address `10.0.0.5/30`, MTU, 2× Stop Network on teardown,
    and fail-fast without a netdev.
- NDK r27c static aarch64 `a6l-qmi`: builds with `-Wall -Wextra -Werror`.
- Lineage tree `m android.hardware.radio-service.a6l a6l-qmi a6l-qmi-tests`: **rc=0** (after 4 compile-fix rounds: a host sysroot without `linux/qrtr.h`, namespace aliases, missing AIDL includes). The Soong host test `a6l-qmi-tests` also passes 105/105. The build ran as root, like the earlier flash builds, because `out/soong` already holds root-owned files (an a6l-user build fails with "permission denied").
- **Not verifiable offline:** anything with the real modem (QRTR node/instance numbers, which TLVs this modem
  firmware accepts, transfer-only SMS routes, voice indications), the framework's behaviour with this HAL (no
  telephony in the QEMU image), sepolicy (not compiled, the image is permissive), and data (no IPA).

## 5. What is untested / open (honest list)
- The HAL has never talked to the real modem. Most likely first-contact issues: instance/version selection when
  a service is announced twice, NAS Register Indications TLVs rejected (there is a retry with basics), WMS
  transfer-only routes refused (the store fallback exists), UIM session choice for ISIM/other AIDs.
- The framework's side: whether GSI telephony (TeleService) likes the V4 minradio-based responses; carrier
  config / APN DB presence in the lineage GSI; SIM file reads through iccIo (2G GET RESPONSE conversion checked
  offline only).
- No call audio (needs a q6voice/CVD port: postmarketOS q6voiced; closest reference is the msm8998 CVD client).
- No USSD, call forwarding/waiting, CLIR, network scan, cell broadcast programming, initial-attach APN
  programming, IMS/VoLTE (VoLTE-only carriers: no calls on LTE; the modem has to fall back to 2G/3G).
- Data needs the IPA v2.6L kernel port (2–4 weeks, uncertain) — `docs/ipa-sdm660-plan-20260924.md`.
- sepolicy was written against system/sepolicy names and has not been compiled into a policy (checked by hand against the tree: `qipcrtr_socket` class, `netlink_route_socket nlmsg_*`, `SIOC*` ioctl defines, `vendor_internal_prop` and `hal_radio_default` are all present; `hal_radio_default` is already `net_domain`).

## 6. Integration for the flash agent
1. `lineage_gsi_a6l.mk`: `$(call inherit-product, device/hisense/a6l/radio/radio.mk)`; `BoardConfig.mk`:
   `-include device/hisense/a6l/radio/BoardConfig-radio.mk` (vendor sepolicy dir).
2. Packages: `android.hardware.radio-service.a6l` (vendor/bin/hw, rc + VINTF fragment come with the module),
   `a6l-qmi`. Permissions: `android.hardware.telephony.{gsm,radio.access,subscription,calling,messaging,data}.xml`. Properties: `ro.vendor.a6l.ril.*`
   (data parent, rmnet flags 1, endpoint 4/1), `ro.telephony.default_network=9`.
3. Depends on the hals agent's modem services (`a6l-radio.rc`, gate `persist.vendor.a6l.radio.enable=1`) and the
   kernel modules `qrtr qrtr-smd qcom_q6v5_mss …`. For data later: `ipa-v2.ko` + `rmnet.ko`.
4. The HAL always starts. Without the modem it publishes the services and reports RADIO_UNAVAILABLE: this is safe
   on a ROM with the modem off.

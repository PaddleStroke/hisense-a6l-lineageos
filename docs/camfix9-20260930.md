VERSION reads `0x20100000`, the other registers read sane values (`inrd 10001000`, `inwr 00100010`, `outrd 00000010`, `outwr 00000020`, `rrqos 3`, `amem 2222`).

  - VBIF `pnderr(190)` and `srcerr(194)` stay 0 through the bus error: the VBIF never saw an AXI error response.
  - `halt(204)` = `000c0000` at START (xin2/3 acked) and `000d0000` at STOP (xin0 acked after the VFE bus halt). So xin0 is the VFE0 client, and it is not halted during the stream.
- **Stock camera driver** (msm camera_v2 `msm_isp47.c` / `msm_isp48.c`, LA.UM sdm660; copy in WSL `/home/a6l/references/msm-camera-v2-sdm660/`):
  - `init_hardware_reg` writes `vbif-regs <0x124 0xac 0xd0>` = `<3 0x40 0x1010>` blind, without a readback.
  - `VFE47_VBIF_CLK_OFFSET 0x4` (VBIF_CLKON) bit 0 is set only in `msm_vfe47_axi_halt` and cleared at the halt IRQ. It is not held during streaming.
  - There is no VBIF clock beyond `camss_vfe_vbif_ahb_clk` / `camss_vfe_vbif_axi_clk` (plus NORETAIN mem/periph flags on vbif_axi).

- **camfix8 ordering bug.** `vfe_gen1_enable` calls `set_qos` (VBIF_STICK) **before** `a6l_prepare_output` (`a6l_v8_on`). So the pll* stick probes ran before the PLL was enabled, which is why the `pll4_st` column shows 0. posthold and post406 are still valid, because their clock state persists from the previous stream.

## 2. Hypotheses, ranked
1. **The VBIF is clocked and writable; the LOST readback is a probe artefact** (RAZ/WI bits) (~55 %).
   The VBIF is then not the cause. The write path stalls on the VFE side (WM/UB/bus bridge), and stock hides the RDI 0xC94 bit.
   camfix9 bit 0 decides this with fields that exist on every VBIF: the xin0 byte of `0xd0`, `0x124` and the xin0 nibble of `0x160`, plus all-ones masks.
2. **HLOS writes to the camera VBIF are blocked** (xPU/TZ access control, or an alias) (~20 %). The result would be `VBIF_WR READONLY` in every variant.
   The stock QoS values would then never have been applied from Linux either, which matters for the ROM.
3. **The VBIF register or core domain is clock-gated without a force** (~10 %). The result would be READONLY in base and WRITABLE with `clkon`/`fctl`.
   If the stream also improves, the ROM fix is to set VBIF_CLKON / CLK_FORCE in camss.
4. **The shared VBIF needs the VFE1 domain up** (~5 %). The VFE1 GDSC is off (`vfe1 00282001`) and xin1 never acks. The test is the `vfe1` variant.
5. Other (NoC/xPU on the buffer PA, WM programming) (~10 %). This carries on from camfix8 §2.3.

Ruled out: VBIF clocks missing from the DT or not enabled, a wrong VBIF base, MMPLL4 off (camfix8), SMMU fault (FSR 0x400 = FORMAT), ICC votes, UB/burst/line-rate variants.

## 5. Risks
- All bit-0 test writes are restored immediately, before the WMs are enabled. The `d0`/`ac` all-ones masks exist for about 2 µs on an idle VBIF.
- Bits 2 and 4 force VBIF clocks on during the stream only, which costs power. They are restored at stream-off.
- Bit 8 powers and resets VFE1, which is otherwise off. A reset timeout returns an error (logged) and does not oops. VFE1 is released at stream-off.
- Bit 16 leaves the stock VBIF values set until reboot (`post` runs last for that reason).
- hi846 (2 SOF) is unrelated and stays open.

## 6. Stock RDI comparison (camfix9b)
The source is msm camera_v2 `msm_isp47.c`, `msm_isp48.c`, `msm_isp_axi_util.c` and `msm_isp_util.c` (LA.UM sdm660), in WSL `/home/a6l/references/msm-camera-v2-sdm660/`. On sdm660 the VFE is vfe48: it uses the vfe47 ops, except `enable_wm` (0xCEC), the UB size and the two bus-error hooks.

The comparison covers one RDI0 raw stream, stock against mainline camss `vfe-4-8` + camfix, as run in the sweeps (`a6l_wm=6`, fixed ping/pong).

### Differences found
| # | stock (vfe48) | ours (before camfix9b) | camfix9b knob |
|---|---|---|---|
| 1 | **An RDI reg-update every frame.** In `msm_vfe47_process_reg_update`, case `VFE_RAW_x`, the comment reads "Reg Update is pseudo SOF for RDI, so request every frame". It calls `reg_update(RAW_x)` at every RDI REG_UPDATE irq, so a REG_UPDATE is always pending and the RUP irq fires once per frame. | Mainline requests the reg-update at stream start and on buffer or frame-drop changes only. | 2 | **Bus error.** `msm_vfe48_get_bus_err_mask` reads 0xC94 and removes the bits of RDI WMs (`bus_err_ign_mask`, set in `msm_isp_axi_reserve_wm` for `stream_src >= RDI_INTF_0`). | 4 | **Ping/pong.** At every buf done, `msm_isp_process_axi_irq_stream` calls `msm_isp_cfg_ping_pong_address` for the finished slot, which rewrites the address and max = (addr+size) & ~0x1f, even when the buffer is the same. | Fixed mode programs both slots once at start and never rewrites them. | `a6l_stk` bit4 rewrites the finished slot at WM done. |
| — | Same in both: frame-based `ADDR_CFG` 0x2, `BUFFER_CFG` = the ADDR_CFG value (camfix `a6l_wm` bit1), `IRQ_SUBSAMPLE` 0xffffffff, framedrop pattern 1/period 1, XBAR 0xC00 for RDI0, `RDI_CFG` (rdi·3)<<28 \| cid<<4 \| 1<<2 (bits 0–1 = camif_input MIPI = 3, which mainline also sets), WM enable via 0xCEC, `BUS_CFG` 0x101, the irq clear sequence (0x64/0x68 + 0x58), per-WM CGC override, and the VBIF values. | | |

No stock step is missing from the RDI path except items 1–4. Stock has no per-frame halt, reset or reload, no "frame based vs line based" switch for RDI beyond `frame_base` from userspace, and no RDI irq subsample. The RDI SOF status bits (s1 29–31) are ignored by stock: for RDI, the reg-update irq is the SOF.

The strongest candidate is item 1. Our failure pattern fits an RDI path that is never re-armed after its first frame: a few lines per SOF, one bus error at SOF 1–6, and rare dones. Stock re-arms it with a REG_UPDATE on every frame. Confidence: medium (~35 %). The combination with item 2 (the bus error ignored exactly like stock) comes next.

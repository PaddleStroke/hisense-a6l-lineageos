# V54 — genuine Health HAL in the offline VM

V53 completed SystemServer bootstrap services and stopped in BatteryService because no default IHealth instance was available. V54 builds the unmodified local `android.hardware.health-service.example`, stages its vendor ELF dependency closure and original AIDL V5 VINTF fragment, starts the real service, checks its Binder registration and saves its actual dump before attempting SystemServer again.

This is a diskless, networkless QEMU test. No phone, battery, charger or physical power-supply nodes are exposed. The upstream BatteryMonitor explicitly supports systems with no battery. No `ro.boot.fake_battery` override or fabricated Health result is introduced. Registration alone does not prove Android BatteryService accepts the service; the subsequent SystemServer log must establish that separately.

The existing APEX and SystemSuspend daemon lifetimes are extended to 300 seconds, matching the supervisor ceiling, so that they cannot expire before the 180-second Zygote test ends. Native supervisor and kernel are unchanged. The test remains a staged root/permissive VM environment, not production Android init or SELinux validation.

Build: `tools/build-framework-health-v54.sh`, with fresh log `/home/a6l/logs/build-framework-health-v54-r1.log`.

Test: `tools/Test-FrameworkV48.py --rooted --runtime-kernel --apex-service --native-bootstrap --applications --health --attempt N`.

The A6L's eventual implementation remains separate: verified fuel-gauge telemetry is only part of battery support. PM660/SMB1351 charge policy, thermal limits, charger mode, physical unplug/replug, suspend and shutdown need their own validation. See `power-sensors-preparation-20260917.md` and later physical results in the status index. The generic example service is not declared production-ready for A6L.

Primary reference checked: [AOSP Health AIDL implementation guidance](https://android.googlesource.com/platform/hardware/interfaces/+/refs/heads/android16-release/health/aidl/README.md). It explains the default service and when device customization is required. Local build/source is authoritative for our pinned version.

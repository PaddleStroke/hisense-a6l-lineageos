# Audio 3: root cause of the "inverted DPCM", TFA made optional, ROM audio HAL config (24 Sep 2026, agent `audio3`)

This was all done offline. Nobody touched the phone and nobody ran `m`. The builds are against the V67 phone kernel
(`7.2.3-a6l-probe+`, `out-a6l-phone-v67`), which V74 still runs (V74 changed only the DT).

## 1. Root cause: the MultiMedia front ends are SWAPPED, not inverted

**The 23 Sep diag (r180).** It set two routes, "LPI_MI2S_RX_0 Audio Mixer MultiMedia1" and "MultiMedia2 Mixer LPI_MI2S_TX_3".
With those on, `pcmC0D0p` and `pcmC0D1c` failed with EINVAL, while `pcmC0D0c` and `pcmC0D1p` opened.

**Mechanism.** It is a chain of four facts, all checked in the 7.2.3 sources and the V74 DTB:
1. `q6asm-dai.c` has **no `of_xlate_dai_name`**. `snd_soc_get_dlc()` (soc-core.c:3450) therefore falls back to the
   generic rule: `<&q6asmdai N>` means **the N-th DAI of the component**. The DAIs are registered in DT child order
   (`of_q6asm_parse_dai_data`, `for_each_child_of_node`).
2. fdtoverlay **prepends** new child nodes. `a6l-audio-internal.dtso` writes `dai@0 {}; dai@1 {};` under `&q6asmdai`.
   The merged V71/V74 DTB therefore contains `dai@1, dai@0`. This was verified by decompiling `recovery-v74-candidate-20260923/base.dtb` and
   `merged-captured-abl.dtb`. The debugfs `dais` list in r180 also shows `MultiMedia2` before `MultiMedia1`.
3. As a result, link "MultiMedia1" (pcm device 0) got the **MultiMedia2** DAI (widgets MM_DL2/MM_UL2), and link
   "MultiMedia2" (device 1) got **MultiMedia1** (MM_DL1/MM_UL1).
4. In 7.2, `dpcm_fe_dai_open()` returns **-EINVAL at open** when the front end has no back end. It prints
   "no backend DAIs enabled" only once per boot, via `dev_err_once`. Dynamic debug printed nothing new because every
   other message is `dev_dbg` from before that point.

   With MM_DL1 and MM_UL2 routed, only device 1 playback (MM1) and device 0 capture (MM2) had a back end. That is exactly
   the r180 pattern. The HW_REFINE numbers agree: they are per stream direction and do not depend on the DAI.

**Ruled out** (sources read):
* soc-pcm/soc-dapm direction logic: `dpcm_path_get`, `snd_soc_dapm_dai_get_connected_widgets`, `dpcm_end_walk_at_be`,
  `dpcm_add_paths`, `dpcm_get_be`. These are unmodified mainline.
* qcom `common.c` link flags: an FE has no codec, so it gets `dynamic=1`; a BE has `no_pcm=1`. The code has no
  playback_only/capture_only flags.
* q6routing widget directions.
* q6afe-dai. It has an xlate by port id, so the order of its children does not matter.

The earlier "must be reversed" rule for the *links* (21 Sep) was right. The same prepend effect on the *q6asm children* was missed.

**Side effect of the swap.** Even an open that "worked" (device 1 playback) called `q6routing_stream_open()` with the link
id (1) while the ASM session was 1+1. Close then used a different key than open, so the fix is needed even for playback on device 1.

### Fix (two layers; they are compatible)
* **Module patch `device/hisense/a6l/kernel/a6l-q6asm-dai-xlate-v75.patch`.** It adds `q6asm_dai_of_xlate_dai_name()`,
  which maps `<&q6asmdai N>` to the DAI whose id (= `reg`) is N. The result no longer depends on DT order. On an in-order DT it
  returns exactly what the stock rule returned.
  * It is the **only fix possible on the V74 base.dtb**: fdtoverlay cannot reorder existing nodes.
  * It is built as `q6asm-dai.ko` in an own `M=` directory (see artifacts).
  * For the ROM, the `flash` agent applies it to the kernel tree. `patch --dry-run` on the tree is part of the build script.
* **DT `a6l-audio-internal-v75.dtso`, for a base WITHOUT sound nodes.** Same content as a1, but the q6asm children are written
  reversed (`dai@1` first), so the merged DTB is in order (index == reg). It is then correct with the stock module and with the
  patched one.
* **Do not** "fix" the V74 base by swapping the phandle args (`<&q6asmdai 1>` for MultiMedia1). That breaks as soon as the
  patched module is used.

### Offline verification
* `tools/check-audio-dt-links.py <merged.dtb> [--rule index|reg|both] [--expect-tfa|--expect-no-tfa]`. It decompiles the DTB
  and prints the link order and the q6asm child order. For each FE it shows the DAI it gets under the stock rule (index) and
  under the patched rule (reg). It fails when a link named MultiMedia<k> does not get DAI MultiMedia<k>, or when a q6routing
  BE comes before the first FE.

| DTB | rule | result |
|---|---|---|
| V74 as flashed (`merged-captured-abl.dtb`) | index (stock module) | **FAIL**: MultiMedia1→MultiMedia2, MultiMedia2→MultiMedia1. Reproduces r180. |
| V74 as flashed | reg (patched module) | PASS |
| V74 + `a6l-audio-speaker-onbase-v75.dtbo` | reg | PASS, links MM1, MM2, Speaker, Int Playback, Int Capture, TFA node present |
| no-sound base (V74 with the sound nodes removed by `fdtput -r`) + old `a6l-audio-internal.dtso` | index | FAIL (same as V71/V74) |
| no-sound base + `a6l-audio-internal-v75.dtbo` | both | PASS |
| no-sound base + `a6l-audio-speaker-v75.dtbo` | both | PASS, TFA present |

* A QEMU audio test is **not feasible**. The card needs the real ADSP (APR/q6afe/q6asm over GLINK) and the LPASS/PM660L codecs.
  QEMU has none of these, and the ASoC card does not bind without them. The proof is the attended `MODE=map` below, which
  makes no sound.

## 2. Speaker (TFA9894): shippable without endangering the headset

**The problem.** The sm8250 machine driver binds the card only when every dai-link codec is registered. A TFA probe failure
therefore removed the headset and the mics along with the speaker.

**Why not a separate card or an aux device.** The q6afe/q6asm/q6routing components can belong to only one card. A second
card for TERT_MI2S would need its own DSP components, so it is impossible. An aux device blocks the card in the same way a codec does.

**What was done: `tfa98xx-a6l/apply-a6l-optional-v75.sh`.** Run it after `apply-a6l-patches.sh`; tested locally on a fresh
upstream checkout, and it is idempotent. It changes three things:
* The real probe becomes `tfa98xx_i2c_probe_hw`. A wrapper registers a **silent stub codec** instead when the real probe
  fails for any hardware reason. Examples are an I2C NACK, an unknown revision, or a failed regmap/GPIO. The stub is
  `tfa98xx-aif-stub`: playback only, no controls. The wrapper logs `A6L_TFA_STUB <err>`. The card binds, and the speaker is mute.
  -EPROBE_DEFER and -ENOMEM keep their normal meaning.
* A failed IRQ request is no longer fatal. Interrupts are skipped, as for the TFA989x parts.
* `remove()` copes with the stub, which has no driver data.

**Build-time requirements** (the flash agent must satisfy them; they are not run-time risks):
* `snd-soc-tfa98xx.ko` is shipped and loaded, together with `tfa98xx.cnt` in `/vendor/firmware` (or `/lib/firmware`).
* The LPI pinctrl is built with `a6l-lpi-ter-mi2s-v74.patch`. The amp node's `pinctrl-0` uses the `ter_mi2s_*` functions. With
  an unpatched LPI driver, `pinctrl_bind_pins` returns -EINVAL before probe, and the whole card waits.
* Recommendation: put both patches in the kernel tree, not as separate out-of-tree modules.

**If in doubt, ship without the speaker.** The fallback DT for the first ROM is `a6l-audio-internal-v75` (no TFA). With the V74
base, simply do not apply a speaker overlay. The ROM routing daemon notices when the TERT control is missing and falls back to
the headphones path.

**DT variants:**
* `a6l-audio-speaker-onbase-v75.dtso`: for the V74 base. It needs the patched q6asm-dai.
* `a6l-audio-speaker-v75.dtso`: for a no-sound base, with the q6asm children reversed.

Both give the link order MM1, MM2, Speaker Playback, Internal MI2S Playback, Internal MI2S Capture.

## 3. ROM audio HAL (for the `flash` agent)

**HAL survey:**
* **AOSP AIDL example HAL** (`com.android.hardware.audio`, already in the product). Its "primary" module (ModulePrimary,
  StreamPrimary over `StreamAlsa`) opens **ALSA card 0 / device 0** for both directions. It **never sets mixer controls**; it
  has only an optional master volume. It has **no mixer_paths support**.
* **Linaro `device/linaro/dragonboard/audio/audio_hw.c` (db845c).** Current main was checked. It is a legacy
  `audio_hw_device` (HIDL-era) HAL. It includes `audio_route.h` but no longer calls it: routing is static, and the card is
  found by probing cards 0–7. It is not AIDL, and it is not in the Lineage tree.
* **CAF/Lineage `audio.primary.sdm660`.** It needs the downstream msm audio kernel (not mainline), so it is not usable.
* A read-only relay survey of the Lineage tree (`audio3-03-halsurvey.sh`) was queued to confirm this against the actual tree.
  The relay was stalled all night; see the status line at the end.

**Chosen design.**
* **The AOSP AIDL example HAL is kept.** After the fix, card 0 / device 0 is MultiMedia1, which handles both directions.
* **A small vendor daemon, `a6l-audio-route`, owns the mixer.**
  * It uses libaudioroute (the CAF mixer_paths parser) with `/vendor/etc/mixer_paths_a6l.xml`.
  * It polls the card's ASoC jack kcontrols every 300 ms. With "Headphone Jack" on, it selects `headphones`; otherwise it
    selects `speaker`, or `headphones` when there is no TERT route. With "Mic Jack" on, it selects `headset-mic`; otherwise `main-mic`.
  * The XML top level keeps **MultiMedia1 connected to LPI_MI2S_RX_0 and LPI_MI2S_TX_3 at all times**. The HAL's open
    therefore never hits the DPCM "no backend" EINVAL. With the HPH/EAR switches at ZERO, nothing is audible.
* **Framework overlay `config_useDevInputEventForAudioJack=true`.** The jack is an input device (SW_HEADPHONE_INSERT), so
  AudioPolicy also switches to the Wired Headset device.
* **Limitations:**
  * No speaker and headset at the same time (for example, a ringtone on both).
  * No earpiece (broken on this unit anyway).
  * No voice-call audio.
  * Volume is software (AudioFlinger) on top of a fixed codec level: raw 78 = −6 dB, stock is 0 dB.

**Files** (all under `device/hisense/a6l/audio/`):

| file | installs as | purpose |
|---|---|---|
| `audio_policy_configuration.xml` | `/vendor/etc/audio_policy_configuration.xml` | Module "primary": Speaker, Wired Headset, Wired Headphones, Built-In Mic, Wired Headset Mic (48 k stereo out; 8/16/48 k mono/stereo in). r_submix and bluetooth modules are kept from realinit3 (the APEX declares them). **Replaces** `audio/realinit/audio_policy_configuration.xml`. |
| `mixer_paths_a6l.xml` | `/vendor/etc/mixer_paths_a6l.xml` (prebuilt_etc `mixer_paths_a6l.xml`) | Paths `headphones`, `speaker`, `handset`, `main-mic`, `headset-mic`. The names are the real ones from the 23 Sep dump. |
| `route/a6l_audio_route.c`, `route/a6l-audio-route.rc`, `Android.bp` | `/vendor/bin/a6l-audio-route` + init service `vendor.a6l-audio-route` (class hal, user audioserver, group audio) | Routing daemon (cc_binary, vendor; libaudioroute, libtinyalsa, liblog; `-Wall -Werror`). |
| `sepolicy/a6l_audio_route.te`, `sepolicy/file_contexts` | vendor sepolicy | Domain for the daemon: audio_device, proc_asound, vendor_configs_file. |
| `overlay/frameworks/base/core/res/res/values/config.xml` | framework RRO/overlay | `config_useDevInputEventForAudioJack=true` |
| `audio.mk` | – | PRODUCT_PACKAGES `a6l-audio-route mixer_paths_a6l.xml`, PRODUCT_COPY_FILES for the policy, DEVICE_PACKAGE_OVERLAYS |

**Integration list for `flash`:**
1. In `lineage_gsi_a6l.mk`, `$(call inherit-product, device/hisense/a6l/audio/audio.mk)`, and **delete** the
   `audio/realinit/audio_policy_configuration.xml` line (same destination).
2. In `BoardConfig.mk`, `BOARD_VENDOR_SEPOLICY_DIRS += device/hisense/a6l/audio/sepolicy`.
3. Kernel:
   * apply `a6l-q6asm-dai-xlate-v75.patch` (required);
   * apply `a6l-lpi-ter-mi2s-v74.patch` (for the speaker);
   * build the TFA driver with `apply-a6l-patches.sh` + `apply-a6l-optional-v75.sh` (as a module next to the sound modules).
   * Ship `tfa98xx.cnt`.
4. DT for the ROM boot image:
   * V74 base with the patched q6asm-dai: as is (headset only), or + `a6l-audio-speaker-onbase-v75.dtbo`;
   * a no-sound base: `a6l-audio-internal-v75.dtbo` or `a6l-audio-speaker-v75.dtbo`.
   * Check it with `tools/check-audio-dt-links.py merged.dtb --rule reg`.
5. Module load order is not critical: the card defers until every component is registered. All audio modules
   (and `snd-soc-tfa98xx`, if the speaker DT is used) must be in the ROM's module list.

## 4. Attended test v75/audio3 (V74 recovery, same flow as audio2)

The bundle is on the laptop at `~/A6L-usb-20260915/v75/audio3` and in the repo at `firmware/extracted/audio3-20260924/v75/audio3`.

**What the bundle does.**
* It keeps the V71/V74 header: image check `hisense,a6l-controls = v71`, SHA256SUMS, `load()`.
* Its modules are the audio2 set with **`q6asm-dai.ko` replaced by the patched build**.
* `extra/` holds the patched LPI and the optional TFA module. `firmware/` holds `tfa98xx.cnt`.
* `bin/` holds tinyalsa, pcmprobe and a static `a6l-audio-route`.

**Safety rules:**
* Volumes are RAW (dB = raw − 84). LEVEL 1/2/3 = 54/60/66, with a **hard cap of 66 (−18 dB)**. Every write is read back; a
  bad read-back mutes everything and aborts. The safety messages go to stderr, so they stay visible even when a step's
  output is hidden.
* The first headset run is done with the headset **not worn**.
* The speaker tone is −40 dBFS.
* Earpiece: skipped.

**Needs a FRESH recovery boot** (or one in which no earlier audio bundle loaded the old `q6asm-dai`). The script checks
`/proc/kallsyms` for `q6asm_dai_of_xlate_dai_name`. If the old module is loaded, it stops with `A6L_HW_FAIL … reboot to recovery`.

```
# laptop ~/A6L-usb-20260915 (ADSP bundle first, as in the audio2 session: v68 adsp modules + echo start)
adb -s HLTE730T-PROBE push v75/audio3 /tmp/audio3
# phone shell lines (ph.sh), each starting with: export PATH=/tmp/bin:$PATH;
D=/tmp/audio3 MODE=map sh /tmp/audio3/run.sh          # NO SOUND
D=/tmp/audio3 MODE=headset sh /tmp/audio3/run.sh      # headset plugged, NOT worn; LEVEL=1 (-30 dB) default
D=/tmp/audio3 MODE=mic sh /tmp/audio3/run.sh          # 5 s headset mic, 5 s main mic
adb -s HLTE730T-PROBE pull /tmp/audio3-out v75/logs/audio3-out ; python3 v75/audio3/wav-level.py v75/logs/audio3-out/cap-*.wav
D=/tmp/audio3 MODE=route sh /tmp/audio3/run.sh        # ROM routing daemon once (no sound); PLAY=1 adds a headset tone
D=/tmp/audio3 MODE=speaker sh /tmp/audio3/run.sh      # ONLY on a V75 image with a speaker DT; else prints A6L_SKIP
D=/tmp/audio3 MODE=off sh /tmp/audio3/run.sh
```

**What to watch:**
* **map**
  * Expect `A6L_Q6ASM_PATCHED yes`.
  * With routing OFF, all four nodes return errno=22.
  * With only the MultiMedia1 routes on, expect `pcmC0D0p open OK`, `pcmC0D0c open OK`, `D1p/D1c errno=22`, then **`A6L_MAP_PASS`**.
  * `A6L_MAP_FAIL` with D1 opening instead means the fix is not active.
* **headset**
  * Expect `A6L_MIXER headset.txt ok=7 fail=0` and `A6L_PLAY_RC … 0` three times.
  * The HPHL/HPHR PA lines should show On.
  * Ask Pierre: left / right / both.
* **mic**
  * Expect `A6L_CAPTURE_RC … 0` and a non-zero byte count.
  * On the laptop, the RMS level should rise when he speaks.
* **route**
  * Expect `A6L_AUDIO_ROUTE out=headphones in=headset-mic` with the headset plugged. Without it, expect `out=headphones`
    (V74 has no TERT control, so this is the fallback) and `in=main-mic`.
  * Expect `A6L_ROUTE_RC 0`, and D0p/D0c `open OK` afterwards.
* **speaker** (V75 speaker DT only)
  * `A6L_TFA_STUB` in dmesg means the amp did not answer, and the step skips; the headset must still work in that case.
  * Otherwise: a quiet 1 kHz tone. The klog tail shows the tfa/q6afe lines.

**Offline checks done on the script.**
* `sh -n` / `bash -n` pass.
* A dry run on x86 with a fake tinymix/pcmprobe and fake /proc gave:
  * map → `A6L_MAP_PASS`;
  * unpatched kallsyms → abort;
  * a forced volume read-back of 124 → `A6L_HW_FAIL … muting and aborting` (exit 10);
  * route with LEVEL=2 → the XML is rewritten to raw 60.

## 6. Risks and unknowns
* Nothing has run on hardware. The root cause is proven by the source reading plus the DTB (and the r180 pattern matches
  exactly), but `MODE=map` is the real confirmation.
* The analog gains (HPH) are driver defaults. The −30 dB digital level has never been heard; start at LEVEL 1.
* Capture now uses MultiMedia1 (the HAL uses one device for both directions). This is expected to work (q6asm capture on
  MM1 is standard), but it is untested.
* TFA9894: the stock container is used unchanged, and no calibration may be run. The TERT_MI2S bit clock/format comes from
  sm8250.c. None of this has been tested.
* The routing daemon polls the jack kcontrols. The names "Headphone Jack" and "Mic Jack" are the ASoC pin-jack kcontrols of
  `qcom_snd_wcd_jack_setup`; "Headphone Jack: On" was seen on 23 Sep. "Mic Jack" is assumed from the same code.
* The AIDL example HAL's ALSA card/device choice (card 0 / device 0) comes from AOSP knowledge. It is not yet confirmed on
  the Lineage tree because the relay survey did not run. If the tree differs, only the policy and daemon need adjusting.

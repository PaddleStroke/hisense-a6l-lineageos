## 1. Call audio

### 1.1 Sources and what was ported
* **Base:** the sc7280-mainline PR #32 series (`refs/pull/32/head`, 7.1). This is Stephan Gerhold's msm8916 q6voice plus
  Richard Acayan's sdm670 work:
  * q6voice-common / q6mvm / q6cvp / q6cvs / q6voice / q6voice-dai;
  * the VoiceMMode1 DAI;
  * the rx/tx port controls;
  * the CVD 2.3 init sequence;
  * the topology controls;
  * the default NONE TX topology.
* It was chosen over msm8916-mainline 7.2-rc1 and ShapeShifter499 joan PR #9 because:
  * it is the newest;
  * it already has the VoiceMMode1 path, which is what SDM660 stock uses;
  * it already has the CVD 2.3 variant.
* The joan PR #9 branch is mostly msm8998 bring-up debugging, with no separate CVD client worth taking.
* **Patches used** (kept in `device/hisense/a6l/kernel/kvoice/q6voice-series/`): 0001–0009, 0013–0019 and 0021–0023.
* **Patches skipped:**
  * 0010/0011: TDM data delay, not needed;
  * 0012: q6core ACDB topology registration. It needs `qcom,acdb-name` + `Global_cal.acdb`, and q6voice does not call it,
    so `q6core.ko` stays unmodified.
* **A6L patch `device/hisense/a6l/kernel/kvoice/a6l-q6voice-sdm660-v75.patch`:**
  * **Routes.** Adds `VoiceMMode1 Capture Mixer` → `LPI_MI2S_TX_3`, and the widget `LPI_MI2S_RX_0 Voice Mixer` (controls
    `CS-Voice`, `VoiceMMode1`) → `LPI_MI2S_RX_0`. These are the mainline names of the stock INT3_MI2S_TX / INT0_MI2S_RX
    ports. TERT_MI2S_RX (speaker) is already in the upstream table.
  * **CVD version auto-detect.** q6mvm sends `VSS_IVERSION_CMD_GET` (0x00011378) once and parses `VSS_IVERSION_RSP_GET`.
    A version ≥ 2.3 selects the V3 sequence; otherwise, and also on error or timeout, it uses the legacy
    `CREATE_FULL_CONTROL_SESSION_V2` sequence.
    * The DT can force the choice with `qcom,cvd-v2.3` / `qcom,cvd-v2.2`.
    * Module parameter `q6voice.cvd_mode=-1|0|1`, writable at run time, which lets the attended test try both.
    * Everything is logged as `A6L_Q6VOICE …` (version string, the sequence chosen, the AFE port ids and the topologies).
  * **Bug fix.** `session_create_v3()` tested for `NULL`, but the create function returns an `ERR_PTR`. An error there would
    have crashed.
* **Full patch against 7.2.3:** `device/hisense/a6l/kernel/kvoice/a6l-q6voice-full-7.2.3.patch` (15 files, 2044 lines).
  It is the upstream series plus the A6L patch plus audio3's `a6l-q6asm-dai-xlate-v75.patch`. `git apply --check` on
  `a6l-baseline-7.2` succeeds.
* **Config for the flash agent:** `CONFIG_SND_SOC_QDSP6_Q6VOICE=m` (selects `..._Q6VOICE_DAI`).

### 1.2 Stock → mainline translation
* **Stock mixer_paths.xml `voicemmode1-call`** (and `headphones`):
  * `INT0_MI2S_RX_Voice Mixer VoiceMMode1 = 1` maps to **`LPI_MI2S_RX_0 Voice Mixer VoiceMMode1`**.
  * `VoiceMMode1_Tx Mixer INT3_MI2S_TX_MMode1 = 1` maps to **`VoiceMMode1 Capture Mixer LPI_MI2S_TX_3`**.
* **`voicemmode1-call speaker`** uses `TERT_MI2S_RX_Voice Mixer`, which maps to `TERT_MI2S_RX Voice Mixer VoiceMMode1`. It
  needs a speaker DT.
* The analog side is unchanged: the audio3 paths `headphones` / `headset-mic` / `main-mic`. The earpiece is broken on this
  unit.
* **Stock DT:**
  * `qcom,msm-pcm-voice` (`qcom,destroy-cvd`), `qcom,msm-voip-dsp`, `qcom,msm-pcm-hostless`;
  * int-mi2s0: rx-lines 3;
  * int-mi2s3: tx-lines 3.
  * These map to mainline APR services MVM 0x9 / CVS 0xa / CVP 0xb on the ADSP (same APR domain and PD as
    q6afe/q6asm/q6adm), plus the `qcom,q6voice-dais` child of q6mvm.
* **Session name:** VoiceMMode1 uses the MVM passive session "11C05000", which is the stock VSID of VoiceMMode1.

### 1.3 DT and dai-link order (respects docs/audio3-20260924.md)
fdtoverlay and the kernel overlay code both **prepend** new children. Every variant is therefore written so that the merged
order is FEs first: MultiMedia1 (pcmC0D0, the HAL), MultiMedia2, **VoiceMMode1 (pcmC0D2)**, then the q6routing BEs.
`q6voice-dai` uses `SND_SOC_COMP_ORDER_LATE`, so its routes to the q6afe widgets always resolve. Its DAIs come from a static
array (index == id), so there is no child-order problem like the q6asm one.

| file (`device/hisense/a6l/kernel/kvoice/dt/`) | base | links (merged) | needs |
|---|---|---|---|
| `a6l-voice-onbase-v75.dtso` | V74 base (sound links present) | MM1, MM2, VoiceMMode1, Int PB, Int Cap | patched q6asm-dai (audio3) |
| `a6l-voice-speaker-onbase-v75.dtso` | V74 base | MM1, MM2, VoiceMMode1, Speaker, Int PB, Int Cap | same as audio3 speaker-onbase + patched q6asm-dai |
| `a6l-audio-voice-internal-v75.dtso` | no-sound base | MM1, MM2, VoiceMMode1, Int PB, Int Cap | nothing special |
| `a6l-audio-voice-speaker-v75.dtso` | no-sound base | MM1, MM2, VoiceMMode1, Speaker, Int PB, Int Cap | audio3 speaker build requirements |

**Offline check.** Each file was compiled with `dtc -@` and merged by fdtoverlay onto `recovery-v74-candidate/merged-captured-abl.dtb`
(the no-sound base is made with `fdtput -r`, as audio3 did). Results:
* `tools/check-voice-dt-links.py`: **PASS** for all four, with `voice_pcm_device=2`.
* `tools/check-audio-dt-links.py --rule reg`: **PASS** for all four.
* `--rule both`: **PASS** for the no-sound-base variants.

The merged dtbs are in `firmware/extracted/kvoice-20260924/dt/`.

**Integration rule.** The voice file **replaces** the audio3 file of the same base; it is not added on top.

### 1.4 How it works at run time
* Voice audio stays inside the DSP: modem ⇄ CVD (ADSP) ⇄ AFE LPI MI2S ports ⇄ codec.
* The kernel starts the MVM/CVP session only while **both** VoiceMMode1 PCMs (playback and capture) are open and prepared.
  The order is: MVM passive session plus dual control, then CVP create (V2, or V3 + channel info + media format + topology
  commit), then CVP enable, attach, and MVM START.
* The modem side of the call is driven by the modem itself (dual-control policy).
* **`a6l-q6voiced`** (`device/hisense/a6l/kvoice/q6voiced/`: C, Android.bp, rc, sepolicy):
  * It holds the two PCMs using raw ALSA ioctls (S16_LE, mono, 8 kHz, 2×1024 frames, `stop_threshold` ≥ boundary, so
    there is never an xrun).
  * Modes:
    * `hold <s>`: attended tests.
    * `daemon [prop]`: ROM. It follows `vendor.a6l.voice.active` = 1/0, which the **RIL/call manager must set** when a call
      becomes ACTIVE and clear when it ends.
    * `routes 0|1`.
  * `-r` also toggles the two DSP route controls.
  * The analog path is still owned by `a6l-audio-route` / mixer_paths.
* The pmOS q6voiced (dbus + ModemManager/oFono + alsa-lib) cannot be used on Android. Its logic is small, so it was rewritten.

### 1.6 Attended test v75/kvoice (V74 recovery; **FRESH boot**; same flow as audio3)
**Why a runtime overlay.** The V74 DT has no CVD services and no VoiceMMode1 link. `extra/a6l_voice_ovl.ko` applies
`a6l-voice-onbase-v75.dtbo` to the live DT with `of_overlay_fdt_apply` (`CONFIG_OF_OVERLAY=y` in v67; V74 has
`__symbols__`). It **must be loaded before the ADSP is started**: APR creates its service devices when the ADSP glink edge
comes up. It must also be loaded before the card driver.

```

#   2. run the v68 ADSP bundle exactly as in the audio2/audio3 sessions (modules + echo start)
D=/tmp/kvoice MODE=load sh /tmp/kvoice/run.sh         # 3. NO SOUND. expect A6L_KV card=0 voice_dev=2 mm1_dev=0, four "ok '<control>'", A6L_KV_LOAD_PASS
D=/tmp/kvoice MODE=session sh /tmp/kvoice/run.sh      # 4. NO RF, NO SOUND (analog muted): expect A6L_Q6VOICED OPEN card 0 dev 2 / CLOSED,
                                                      #    klog "A6L_Q6VOICE cvd version query ret=0 ver='2.x'", "using ... init sequence",
                                                      #    "path 6 tx_port 0x... rx_port 0x...", then A6L_KV_SESSION_PASS
#   if 4 fails in CVP create/enable: CVD=0 or CVD=1 D=/tmp/kvoice MODE=session sh /tmp/kvoice/run.sh (forces legacy / 2.3)

adb -s HLTE730T-PROBE pull /tmp/kvoice-out v75/logs/kvoice-out
```

**Step 5, `MODE=call`: RF, only with Pierre's explicit go.** Needs:

Then run `D=/tmp/kvoice MODE=call LEVEL=1 SECS=60 sh /tmp/kvoice/run.sh`:

**What to watch:**
* **Step 3.**

  * **No sound is expected in step 4:** there is no call.

### 1.7 Risks / unknowns (voice)
* **Nothing has run on hardware.**
* **CVD version of the SDM660 ADSP is unknown.** Auto-detection plus the override cover both paths. If
  `VSS_IVERSION_CMD_GET` is not supported (old CVD), the fallback is legacy, which is what msm8916 uses.
* **Calibration:** none. There is no ACDB, TX topology NONE and RX DEFAULT (no echo cancellation/noise suppression). Call
  quality will be basic; this is acceptable for a first call. Stock uses ECNS topologies with ACDB.
* **DPCM with a voice FE on LPI ports.** The BE hw_params come from `sm8250_be_hw_params_fixup` (48 kHz stereo). CVP gets
  the AFE port ids and resamples. This works on sdm845 and sc7280, but is untested on SDM660 LPI.
* **Concurrency.** The ringtone and voice both use LPI_MI2S_RX_0 while a call is active. The ROM HAL keeps MM1 routed, and
  mixing happens in the AFE. This is untested.
* **ROM integration:** nothing in Android starts or stops the voice session yet. The RIL has to set
  `vendor.a6l.voice.active` and select `in_call` routing (AudioManager MODE_IN_CALL). The AIDL example HAL ignores telephony
  modes.
* **Effort:** kernel part done. Hardware bring-up is expected to take one attended session with 1–3 iterations. The Android
  glue depends on the RIL.

## 2. Mobile data (IPA)

### 2.1 SDM660 IPA hardware version
* **Stock DT:** `qcom,ipa@14780000 { qcom,ipa-hw-ver = <0x06>; reg-names = "ipa-base","bam-base"; ... }` and
  `qcom,rmnet-ipa { qcom,ipa-loaduC; }`.
* **Enum:** in the msm-4.4 `enum ipa_hw_type` (uapi msm_ipa.h, verified), `IPA_HW_v2_6L = 6`, and v3.0 = 10, v3.1 = 11,
  v3.5 = 12, v3.5.1 = 13. So **SDM660 = IPA v2.6L**, with BAM transport (no GSI).
* **Stock kernel symbols agree:** `_ipa_init_sram_v2_6L`, `__ipa_commit_hdr_v2_6L`, `_ipa_cfg_ep_holb_v2_6L`,
  `ipa_bam_reg_dump`. There are also 179 `ipa2_` symbols; the ipa3 code is compiled in too, but it is dispatched by hw-ver.
* **Correction:** docs/hals-20260924.md says "IPA v3.1". That is wrong: v3.1 is MSM8998.

### 2.2 Mainline support
* **Mainline:** `drivers/net/ipa` in 7.2 supports IPA v3.1 and later only (GSI; data files v3.1 … v5.5). **v2.x is not
  supported**, and GSI firmware (`ipa_fws.mdt`) does not apply to v2.
* **Earlier attempt:** Sireesh Kodali and Vladimir Lypak posted an RFC in 2021, "net: ipa: Add support for IPA v2.x"
  (tested on 5.13). Their report: "SDM625 (v2.6L) got an IP but could not pass packets; compression/decompression is
  missing". It was not merged.
* **Community port:** msm8953-mainline keeps a squashed standalone driver, **`drivers/net/ipa-legacy`**, in branch
  `alikates/6.5/ipa` (A. Tafalla, Jun 2023; 46 files, 13k lines). It supports v2.0/2.5/2.6L over the kernel BAM dmaengine.
  It also needs two bam_dma extensions, descriptor metadata and immediate commands, which Sireesh wrote.

### 2.3 What was done
* **ipa-legacy port.** `ipa-legacy` from alikates/6.5/ipa was ported to 7.2.3 by
  `device/hisense/a6l/kernel/kvoice/ipa/a6l-ipa-legacy-fix.py`. It is idempotent; the resulting diff is
  `a6l-ipa-legacy-7.2-sdm660.diff` (76 changed lines). Changes:
  * `init_dummy_netdev` → `alloc_netdev_dummy` (and freed on exit);
  * `platform_driver.remove` now returns void;
  * the `DMA_PREP_IMM_CMD` flag, via a shared header;
  * the compatible **`qcom,sdm660-ipa`**, which reuses the v2.6L data. The downstream v2 ep_mapping and SRAM tables are
    per hardware version, so SDM660 has the same pipes as MSM8953: pipes 2..9, cmd_tx = 3, ap_lan_rx = 2,
    ap_modem_tx/rx = 4/5, modem 6..9;
  * the module is renamed `ipa_legacy.ko` / driver `ipa-legacy`, because mainline `ipa.ko` also exists;
  * a **1:1 IOMMU window over the SMEM item**, as in mainline ipa_mem.c, because on SDM660 the IPA sits behind anoc2_smmu
    (SID 0x19c0).
* **`a6l_ipa_bam.ko`.** This is a fork of the 7.2 bam_dma with Sireesh's metadata patch, the IMM flag (desc flag bit 8 =
  downstream `SPS_IOVEC_FLAG_IMME`), and a **private compatible `a6l,ipa-bam-v1.7.0`**. The phone kernel has
  `CONFIG_QCOM_BAM_DMA=y` without these features. The fork removes the need for a new kernel Image for testing. For the
  ROM, apply the two patches to the in-tree bam_dma instead, and use the normal `qcom,bam-v1.7.0` compatible.
* **DT `device/hisense/a6l/kernel/kvoice/ipa/dt/a6l-ipa-v75.dtso`:**
  * `ipa@147c0000`: ipa-reg 0x147c0000/0x5000 and ipa-shared 0x147c5000/0x2000 (the msm8953 layout, base + 0x40000/0x45000);
  * IRQ SPI 333, clock `RPM_SMD_IPA_CLK` (68), `iommus = <&anoc2_smmu 0x19c0>`, BAM dmas 2..9, `modem-remoteproc`;
  * BAM `dma-controller@14784000`, SPI 432;
  * no interconnects: the driver skips the votes. Candidate paths are given in the file.
  * It merges onto the V74 DTB, and the phandles resolve.
* **`a6l_ipa_ovl.ko`:** runtime overlay. `/soc@0` is a populated bus, so the platform devices appear immediately.
* **rmnet:** `CONFIG_RMNET=m` is already in v67, and `rmnet.ko` is in the bundle. ipa-legacy creates `rmnet_ipa0`
  (QMAP); `rmnet_data0` (mux_id 1) is then added on top.
* **Firmware:**
  * **No AP-side IPA firmware is needed for v2.6L.** `ipa_fws` is the GSI firmware of IPA v3+. The stock kernel contains
    the string `ipa/ipa_fws.elf` only in its ipa3 code, and no `ipa_fws.*` exists in the extracted stock firmware.
  * The IPA uC on v2 (`qcom,ipa-loaduC`) is brought up by the modem side.

### 2.4 Attended test v75/kipa (V74 recovery, FRESH boot, modem NOT started yet)
```
adb -s HLTE730T-PROBE push v75/kipa /tmp/kipa
D=/tmp/kipa MODE=load sh /tmp/kipa/run.sh     # NO RF. expect "IPA driver initialized", a6l-ipa-bam + ipa-legacy bound,
                                              # "A6L_IPA SMEM mapped 1:1", no "Unhandled context fault" -> A6L_KIPA_LOAD_PASS
#  then Pierre runs radio2 by hand (RF, as on 23 Sep):  ... export A6L_RF_APPROVED=1; export D=/tmp/radio2; sh /tmp/radio2/run.sh
D=/tmp/kipa MODE=status sh /tmp/kipa/run.sh   # expect rmnet_ipa0 present; watch for IPA QMI/"modem" lines and that the modem
                                              # still reaches A6L_MODEM_STABLE_PASS 300s (IPA must not crash the modem)
```
**Stop criteria:**
* SMMU context-fault storms, an oops, or the modem crashing within 300 s after IPA. In that case, reboot and report the
  dmesg tail.
* If context faults show SID 0x19c0 or a neighbour, the SMMU mapping is the suspect. The alternative is to drop `iommus`
  and boot with `arm-smmu.disable_bypass=0`, which needs a boot-image cmdline, not possible in V74.

**Data (a later ROM or LineageOS-from-RAM test, not recovery), with the ril agent's QMI client:**
1. WDA set data format: QMAP, link-layer raw-IP, on the IPA endpoint.
2. WDS start network (APN).
3. `ip link set rmnet_ipa0 up; ip link add link rmnet_ipa0 name rmnet_data0 type rmnet mux_id 1`.
4. Set the address, gateway and DNS from WDS get-current-settings.
5. `ping -I rmnet_data0`.

Recovery has no `ip` binary with rmnet support. The reference: aospm/qrild did data but not DNS.

### 2.5 Risks / effort (IPA): honest view
* **Nothing has run on hardware, and upstream never got v2.6L to pass packets.** Sireesh's RFC could get an IP but no
  traffic on SDM625. Whether alikates' 2023 squash fixed that is not documented. "Compression/decompression" (modem
  header/ZIP handling, `IPA_MEM_ZIP` in the memory map) may be required by the modem firmware.
* **SDM660-specific unknowns:**
